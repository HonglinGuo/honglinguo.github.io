记住聊过的，查到没学过的

LLM 有两个先天短板：每次调用都是独立的，聊过就忘；知识停在训练截止那天，没学过的不知道。第八章给 HelloAgents 加了两样东西来补：记忆系统负责“记住聊过的”，RAG 负责“查到没学过的”。两者都被做成工具（memory_tool 和 rag_tool），延续上一篇“万物皆为工具”。这一篇的重点是几个能算、能动手的东西：四种记忆各用什么公式打分，遗忘和整合怎么操作，文档怎么被切成块，查询怎么被扩展。

本系列是开源教程《Hello-Agents：从零开始构建智能体》（Datawhale 社区编写的开源教程，CC BY-NC-SA 4.0 协议；本笔记依据 2026 年 10 月 14 日的仓库版本）的学习笔记。原书十六章，按“概念 → 手写范式 → 平台与框架 → 自研框架 → 记忆、上下文、协议、训练、评估 → 综合案例”展开，代码量很大。这里重排成十三篇，用自己的话重讲：代码只保留能看清机制的骨架，做成可以逐行走读、可以填空回忆的互动；每篇末尾配原书面试题清单里的相关题目做口述演练。每节标出对应的原书章节，演示数值标“示意”。笔记同样按 CC BY-NC-SA 4.0 共享。

两个短板，两个工具

原书 8.1.2–8.1.3 节

短板一：无状态导致遗忘。每次 API 调用都是独立计算，模型不会自己记住上次聊了什么。第七章的 SimpleAgent 虽然在 _history 里暂存了当前对话，但那只是进程内的一个临时列表：重启或换个实例就没了，也不能检索、遗忘、整合。后果是上下文丢失、无法个性化、无法从经验中学习、前后矛盾。

短板二：知识是静态的。训练有截止时间，专业领域可能不够深，回答没有出处、也难以核对。RAG 的思路是生成之前先从外部知识库检索相关内容，作为上下文一起交给模型。

原书把两者设计成两个独立工具：memory_tool 存取对话中产生的交互信息，rag_tool 从用户提供的知识库里检索，并可以把重要的检索结果自动写进记忆。记忆系统分四层（基础设施：MemoryManager、MemoryItem、MemoryConfig、BaseMemory；记忆类型；存储后端：Qdrant 向量、Neo4j 图、SQLite 文档；嵌入服务：百炼 DashScope、本地 Transformer、TF-IDF 兜底），RAG 系统也分四层（文档处理、嵌入、向量存储、智能问答）。

原书习题 4 问：什么时候该查 RAG、什么时候该查 Memory？先练练判断。

易混辨析：Memory vs RAG

两者底层都可以用向量检索，区别在数据从哪来、属于谁。Memory 存的是智能体在交互中自己产生、关于这个用户和这段经历的信息，会被不断写入、整合、遗忘；RAG 查的是外部提供的、相对稳定的知识文档，通常批量导入、按命名空间隔离。一句话：Memory 回答“我们之间发生过什么”，RAG 回答“资料里是怎么说的”。

四种记忆，四种寿命

原书 8.1.1、8.2.1、8.2.5 节

原书从认知心理学的经典模型出发：人类记忆分感觉记忆（0.5–3 秒，容量巨大）、工作记忆（15–30 秒，约 7±2 项）、长期记忆（程序性记忆，以及陈述性记忆里的语义记忆“巴黎是法国首都”和情景记忆“昨天的会议”）；记忆的形成经过编码、存储、检索、整合、遗忘五个阶段。

映射到智能体，就是四种记忆：工作记忆存当前会话的临时上下文，纯内存、容量默认 50 条、TTL 自动过期（默认 60 分钟），用 TF-IDF 加关键词匹配做词法检索；情景记忆存具体事件和经历，带会话 ID 和时间，SQLite 存结构化数据、Qdrant 存向量，先按时间、重要性等结构化过滤再做语义检索；语义记忆存抽象知识、概念、用户偏好、长期规则，写入时自动抽取实体和关系存进 Neo4j 知识图谱，同时向量存进 Qdrant，检索时向量和图两路并行再融合；感知记忆存图像、音频等多模态数据，按模态分开建向量集合（文本、CLIP 图像、CLAP 音频）避免维度不匹配。

评分公式：相关、新近、重要

原书 8.2.5 节

每种记忆检索时都要给候选打分排序，公式长得像但侧重不同，可以一起记。共同的结构是（相关性的加权组合）×（0.8 + 重要性 × 0.4）：重要性在 0 到 1 之间，乘子落在 [0.8, 1.2]，原书解释说这样能让重要性起调节作用，又不至于压过相似度。

不同之处在括号里：工作记忆是（TF-IDF 相似度 × 0.7 + 关键词得分 × 0.3）再乘时间衰减；情景记忆是向量相似度 × 0.8 + 时间近因性 × 0.2；语义记忆是向量相似度 × 0.7 + 图相似度 × 0.3；感知记忆和情景一样是 0.8 / 0.2。时间近因性用指数衰减 exp(−0.1 × 小时数 / 24)，最低保留 0.1。原书习题 1 让你解释：情景记忆强调“什么时候发生的”，所以带近因性；语义记忆强调“概念之间怎么关联”，所以带图检索。

两条记忆比一比：调相似度、近因、重要性，看谁排在前面。

记忆类型

记忆的操作：存、查、忘、整合

原书 8.2.3–8.2.4 节

MemoryTool 是统一入口，“统一入口，分发处理”：一个 execute(action, **kwargs)，按 action 分发到 add、search、summary、stats、update、remove、forget、consolidate、clear_all。底下是 MemoryManager，按配置启用哪些记忆类型（默认工作、情景、语义，感知需显式开启），负责协调；具体存储和检索由各记忆类型自己实现。这是关注点分离：Tool 管接口和参数，Manager 管逻辑。

add 时自动补会话 ID 和时间戳，可指定 memory_type 和 importance（0 到 1）。search 支持单个或多个类型、min_importance（默认 0.1）过滤低质量记忆。forget 有三种策略：基于重要性（删掉低于阈值的）、基于时间（删掉超过天数的）、基于容量（超限时删最不重要的）。consolidate 模拟记忆固化：默认把重要性超过 0.7 的工作记忆提升为情景记忆，也可以把重要性超过 0.8 的情景记忆提升为语义记忆。

RAG：从朴素到模块化

原书 8.3.1–8.3.4 节

RAG 拆开是三个词：检索（从知识库查相关内容）、增强（把检索结果融入提示词）、生成（产出有依据的答案）。流程分两段：数据准备（提取、分块、向量化、入库）和应用（提问、检索、注入提示、生成）。

原书把发展分三个阶段：朴素 RAG（2020–2021）“检索—读取”，靠 TF-IDF、BM25 关键词匹配，检索结果原样拼进提示；高级 RAG（2022–2023）转向稠密嵌入的语义检索，并加入查询重写、分块优化、重排序；模块化 RAG（2023 至今）各环节可插拔组合，混合检索、多查询扩展、假设文档嵌入，生成侧加思维链、自我反思。

HelloAgents 的 RAG 是“五层七步”：用户层（RAGTool）、应用层（问答、搜索、管理）、处理层（解析、分块、向量化）、存储层（向量库、文档存储）、基础层（嵌入模型、LLM、数据库）。处理链路是任意格式 → MarkItDown 转换 → Markdown → 结构感知分块 → 向量化 → 存储检索。关键设计是先用微软开源的 MarkItDown 把 PDF、Word、Excel、PPT、图片（OCR）、音频（转录）统统转成 Markdown（PDF 另有增强处理，失败退回纯文本读取），后面就只需一套分块逻辑。嵌入用百炼 API，不可用退到本地 all-MiniLM-L6-v2，再不行用 TF-IDF 兜底；不同知识库用 rag_namespace 隔离。

动手分块

原书 8.3.4 节（2）

分块分两步。第一步按标题切段：逐行扫描，遇到 # 开头的标题行就把缓冲区里的段落落盘，并维护一个标题栈（遇到同级或更高级标题时弹栈），每个段落都记下它的标题路径，比如“第三章 > 3.2 分词”。第二步按 Token 数装箱：段落依次放进当前块，放不下就封箱；封箱时从尾部往回保留不超过 overlap 的段落，作为下一块的开头（重叠保证跨块的信息连续）。

Token 数用一个中英文混合的近似：CJK 汉字个数，加上按空白切分得到的片段数（英文大致一词一个；中文因为几乎没有空格，基本就是字数）。这比调用真正的分词器便宜得多，又比按字符数准确。标题路径会作为元数据随块入库，检索结果能告诉你答案出自哪一节。

改 chunk_tokens 和 overlap，看块怎么变（实现按原书逻辑移植，段落以空行分隔为简化）。黄色是与上一块重叠的段落。

高级检索：MQE 与 HyDE

原书 8.3.5 节

用户的说法和文档的写法常常对不上。多查询扩展（MQE）解决用词多样性：让 LLM 把一个问题改写成几种语义等价的说法（“如何学习 Python”→“Python 入门教程”“Python 学习方法”），分别检索再合并，提升召回率，对模糊查询和术语查询特别有效。假设文档嵌入（HyDE）解决语义鸿沟：问题是疑问句，文档是陈述句，两者在向量空间里分布不同；HyDE 让 LLM 先写一段“可能的答案”，用这段答案去检索，即使假答案内容不全对，它带的术语和表述风格也更接近真实文档。

两者整合在 search_vectors_expanded 里：扩展（原查询 + MQE 改写 + HyDE 段落，去重）→ 检索（每个扩展查询都检索，候选池按 candidate_pool_multiplier，默认 4 倍放大）→ 合并（去重、按分数排序取 top-k）。原书的建议：一般查询开 MQE；专业领域 MQE 和 HyDE 都开；性能敏感时只做基础检索或只开 MQE。注意每开一项都要多调一次 LLM。

易混辨析：MQE vs HyDE

两者都用 LLM 生成新的检索查询，区别在生成的是什么。MQE 生成的是更多的问题（换说法），对付“同一件事不同叫法”；HyDE 生成的是一段假答案（换文体），对付“问句和陈述句长得不像”。MQE 增加召回的广度，HyDE 拉近查询与文档的距离；HyDE 的假答案如果方向错了，也可能把检索带偏。

面试演练

题目取自原书 Extra01 与第 8 章习题

如何为 Agent 设计短期记忆和长期记忆？可以借助哪些工具或技术？Extra01 · Agent 第 4 题

  • 短期：当前会话的消息窗口或工作记忆，容量上限 + TTL，超长时摘要或截断；纯内存即可。
  • 长期：情景（事件，带时间与会话，适合回溯）+ 语义（抽象知识与偏好，可配知识图谱）；向量库（Qdrant 等）、图数据库（Neo4j）、关系库（SQLite）组合。
  • 生命周期：写入时打重要性；检索按相关 × 近因 × 重要性排序；定期整合（短期中重要的升为长期）和遗忘（低重要、过期、超容量）。
  • 工程要点：用户级隔离、隐私数据的彻底删除（向量与图里的副本都要删）、写入时机放在固定钩子而非全靠模型自觉。

解释 RAG 的工作原理。与微调相比它解决了什么问题？完整流水线有哪些步骤？Extra01 · RAG 第 1、2 题

  • 原理：生成前从外部知识库检索相关片段，注入提示词，让模型基于资料作答。
  • 相对微调：知识可随时更新、不改权重；可给出处、可核对；对长尾和私有知识更省成本；微调更适合改变风格、格式和能力而非灌知识。
  • 流水线：文档解析（如 MarkItDown 转 Markdown）→ 清洗与分块（结构感知、重叠）→ 嵌入 → 入库（命名空间隔离）→ 查询处理（改写、MQE、HyDE）→ 检索（向量 / 混合）→ 重排 → 拼上下文 → 生成并引用来源。

怎么选切块大小和重叠长度？背后的权衡是什么？Extra01 · RAG 第 3 题

  • 块太大：一个向量混了多个主题，相似度被稀释；塞进上下文浪费 Token。
  • 块太小：语义不完整，答案被切到两块里，需要更多块才能拼全。
  • 重叠：缓解边界切断，但增加存储和重复召回。
  • 做法：先按文档结构（标题、段落）切，再按 Token 装箱；按嵌入模型的最佳输入长度和问题粒度调参；用检索评测集（召回率、MRR）对比几组参数。

除了基础向量检索，还有哪些技术能提升 RAG 的检索质量？“Lost in the Middle”是什么？Extra01 · RAG 第 5、6 题

  • 查询侧：查询改写、MQE、HyDE、子问题分解。
  • 检索侧：混合检索（BM25 + 向量）、元数据过滤、知识图谱多跳、父子块（小块检索大块返回）。
  • 排序侧：交叉编码器重排、去重与多样性。
  • Lost in the Middle：模型对长上下文开头和结尾的信息利用得好，中间的容易被忽略；缓解办法是减少无关片段、把最相关的放在开头或结尾、压缩摘要后再注入（第 9 篇上下文工程）。

动手练（原书习题 3）

  1. 设计一个“智能遗忘”策略，综合重要性、访问频率、时间衰减。
    思路

    为每条记忆维护 access_count 和 last_access；保留分 = w1 × 重要性 + w2 × log(1 + 访问次数) + w3 × exp(−λ × 距上次访问天数)；定期删掉保留分最低的若干条，或在容量超限时触发。被检索到时更新访问统计，相当于“复习”。

  2. 要“忘记”用户的隐私数据，从数据库删除就够了吗？
    思路

    不够。向量库里的向量和载荷、图数据库里由这条记忆抽出的实体与关系、文档库的原文、嵌入缓存、日志与备份里都可能有副本。需要按 memory_id 级联删除所有存储，并对派生出的知识（图谱节点）做引用计数，没有其他来源支撑的一并删除。

回扣开头的三个问题

先自己答，再点开
1. Memory 与 RAG 各补哪个短板？何时查哪个？

Memory 补“无状态导致遗忘”：保存交互中产生的、关于用户和经历的信息，支持检索、整合、遗忘；RAG 补“知识静态有限”：从外部文档知识库检索资料作为上下文。问“我们之间发生过什么、用户喜欢什么”查记忆；问“资料里怎么规定、某个事实是什么”查知识库；两者都可能相关时并行检索再合并。

2. 四种记忆存什么、存哪、怎么打分？遗忘与整合？

工作记忆：当前会话临时上下文，纯内存，容量 50、TTL 60 分钟，(TF-IDF × 0.7 + 关键词 × 0.3) × 时间衰减 × 重要性乘子。情景记忆：事件经历，SQLite + Qdrant，(向量 × 0.8 + 近因 × 0.2) × (0.8 + 重要性 × 0.4)。语义记忆：概念偏好规则，Qdrant + Neo4j，(向量 × 0.7 + 图 × 0.3) × 重要性乘子。感知记忆：多模态，分模态集合，同情景记忆公式。遗忘三策略：按重要性、按时间、按容量；整合默认把重要性 > 0.7 的工作记忆升为情景记忆。

3. PDF 到被检索的步骤？MQE 与 HyDE？

MarkItDown 把 PDF 等转成 Markdown → 按标题切段并记录标题路径 → 按近似 Token 数装箱、带重叠 → 预处理后用嵌入模型向量化 → 存入 Qdrant（命名空间隔离）→ 查询时扩展、检索、合并去重、取 top-k → 注入提示生成。MQE 生成多种问法解决用词差异、提高召回；HyDE 生成假设答案用来检索，解决问句与文档的语义鸿沟。
