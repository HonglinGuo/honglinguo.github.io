一步值，一步策略，交替到最优

从这一章起开始讲算法。三个算法——值迭代、策略迭代、截断策略迭代——长得几乎一样：每轮都是“更新一次值、更新一次策略”。区别只在于“更新值”时迭代多少次：一次、无穷次、还是有限次。把它们放在一张图上比较，就会发现前两者只是第三者的两个极端。它们都需要模型，属于动态规划；但第 5 章的无模型算法正是从这里改出来的。

本系列是教材《强化学习的数学原理（Mathematical Foundations of Reinforcement Learning）》（赵世钰（Shiyu Zhao）著，西湖大学；Springer Nature 与清华大学出版社 2025 年出版，作者在 GitHub 免费公开全书 PDF 与课件，本笔记依据仓库中 2025 年 7 月更新的英文 PDF（已含勘误））的学习笔记。原书仓库没有附带开源许可证，版权归作者与出版社所有；这里不转载原文和插图，而是按“先说清楚它解决什么问题、再动手算、最后记下来”的顺序用自己的话重讲，网格世界、算法与图都在浏览器里重新实现和手绘。公式、定义、例子与参数以原书为准，标注了对应的节号和页码；页面里的模拟结果标注“示意”，复现出原书图中数值的地方标注“原书数据”。

本篇要回答的 3 个问题

  1. 值迭代每一轮做哪两步？它的中间值 vk 是某个策略的状态值吗？
  2. 策略迭代为什么每一轮都不会变差？为什么离目标近的状态先找到最优动作？
  3. 截断策略迭代怎样把前两者统一起来？策略评估要迭代几次才划算？

值迭代

原书 4.1 节 · 第 58–62 页

值迭代就是第 3 章收缩映射定理给出的那个算法：vk+1 = maxπ(rπ + γPπvk)。拆开看，每轮两步。策略更新：πk+1 = argmaxπ(rπ + γPπvk)。值更新：vk+1 = rπk+1 + γPπk+1vk。

逐元素实现时，对每个状态先算 qk(s, a) = Σr p(r|s, a) r + γΣs′ p(s′|s, a) vk(s′)，策略选 argmax（并列时任选一个，不影响收敛），值取 max。一句话流程：vk(s) → qk(s, a) → 贪心策略 πk+1(s) → vk+1(s) = maxa qk(s, a)。

一个容易混淆的点：vk 不是状态值。它只是算法的中间量，一般既不满足 πk+1 的贝尔曼方程，也不满足 πk 的；相应地 qk 也不是动作值。它只在极限处收敛到 v*。

先跟着原书例子（2×2 网格，s2 禁区，s4 目标，γ = 0.9）逐步算 q 表；再在 5×5 网格上一轮一轮地跑。

算法 4.1　值迭代需要模型 p(r|s, a)、p(s′|s, a)

  1. 任取初值 v0。当 ‖vk − vk−1‖ 大于阈值时，对每个状态 s：
    1. 对每个动作 a：q_k(s,a) = Σ_r p(r|s,a) r + γ Σ_s′ p(s′|s,a) v_k(s′)
    2. 策略更新：π_{k+1}(a|s) = 1 当 a = argmax_a q_k(s,a)
    3. 值更新：v_{k+1}(s) = max_a q_k(s,a)

策略迭代

原书 4.2 节 · 第 62–70 页

策略迭代不直接解 BOE，但思想更重要，后面大部分算法都是它的变形。从任意 π0 出发，每轮两步。策略评估（PE）：解贝尔曼方程 vπk = rπk + γPπkvπk，得到当前策略真正的状态值。策略改进（PI）：πk+1 = argmaxπ(rπ + γPπvπk)，逐元素就是对 qπk(s, a) 取贪心。注意它是“迭代里套迭代”：策略评估本身用第 2 章的 v(j+1) = rπk + γPπkv(j)，理论上要 j → ∞。

为什么不会变差？引理 4.1：若 πk+1 是对 vπk 的贪心策略，则 vπk+1 ≥ vπk。证明：两者都满足各自的贝尔曼方程，而贪心性给出 rπk+1 + γPπk+1vπk ≥ vπk；相减得 vπk − vπk+1 ≤ γPπk+1(vπk − vπk+1)，反复代入趋于 0。于是 vπ0 ≤ vπ1 ≤ … ≤ v*，单调有界必收敛。定理 4.1 进一步证明极限就是 v*：把它和从同样起点出发的值迭代序列比较，可以归纳证明 vk ≤ vπk ≤ v*——策略迭代每轮都不比值迭代慢。

原书图 4.4（5×5，rforbidden = −10，从随机策略出发）观察到两个现象：离目标近的状态先找到最优动作——只有近处先找到通往目标的路，远处才能“借道”；以及值的空间分布也是近大远小。

先手算原书图 4.3 的两状态例子；再在 5×5 网格上从随机策略开始逐轮迭代，绿框标出已经取到最优动作的格子。

算法 4.2　策略迭代需要模型

  1. 任取初始策略 π0。当 vπk 未收敛时：
    1. 策略评估：任取初值，反复 v^(j+1)(s) = Σ_a π_k(a|s)[Σ_r p(r|s,a) r + γ Σ_s′ p(s′|s,a) v^(j)(s′)] 直到收敛，得 vπk
    2. 策略改进：对每个 s、a 算 q_πk(s,a)，令 π_{k+1}(a|s) = 1 当 a = argmax_a q_πk(s,a)

截断策略迭代

原书 4.3 节 · 第 70–74 页

把两个算法并排写：策略迭代 π0 → vπ0 → π1 → vπ1 → …；值迭代 v0 → π1′ → v1 → π2′ → …。让它们从同一个点出发（v0 = vπ0），前三步完全相同，第四步才分叉：值迭代算 v1 = rπ1 + γPπ1v0，只代入一次；策略迭代要解 vπ1 = rπ1 + γPπ1vπ1，相当于代入无穷次。

v(0) = v0 → v(1) = 值迭代的 v1 → … → v(j) = 截断策略迭代的 v̄1 → … → v(∞) = 策略迭代的 vπ1

只代入有限的 jtruncate 次，就是截断策略迭代。值迭代是 jtruncate = 1 的极端，策略迭代是 jtruncate = ∞ 的极端。截断后的 vk 不再是真正的状态值，还能找到最优策略吗？能。命题 4.1：若策略评估的初值取上一轮的值 vπk−1，内层迭代单调不减 v(j+1) ≥ v(j)——多迭代几次只会更接近，不会走错方向。直观上，它的收敛速度介于两者之间（原书图 4.5）。

实践建议（原书 Q&A）：内层迭代几次，但不要太多。几次就能明显加速，再多收益递减——毕竟马上就要改策略，把一个“临时”策略评估得极准是浪费。

拖动 jtruncate，比较三个算法收敛到 v* 的过程，以及总计算量（内层代入的总次数）。

算法 4.3　截断策略迭代需要模型

  1. 任取 π0。当 vk 未收敛时：
    1. 策略评估：以 vk−1 为初值，只代入 jtruncate 次 v^(j+1) = r_πk + γ P_πk v^(j)，令 vk = v(j_truncate)
    2. 策略改进：对 vk 算 q，取贪心得 πk+1

三者的关系与广义策略迭代

原书 4.4–4.5 节 · 第 74–75 页

三个算法的共同结构：每轮一步更新值、一步更新策略，两者相互作用直到收敛。这种“值与策略交替更新”的思想叫广义策略迭代（GPI）。它不是一个具体算法，而是一种框架——本书后面几乎所有算法都在它的范围内：蒙特卡罗用采样回报做“不精确的评估”，Sarsa 甚至只评估一步就改策略。

本章算法都需要系统模型，所以通常叫动态规划算法，而不是强化学习算法。还有一个名字要分清：强化学习分有模型（model-based）和无模型（model-free）两类。这里的“有模型”不是指“需要事先给定模型”，而是指用数据估计出模型，再在学习中使用这个模型；无模型方法学习过程中完全不估计模型。从第 5 章开始全是无模型算法，它们都由本章算法“去掉模型”改造而来。

用几道题检验三个算法的区别。

判断

易混辨析：值迭代 vs 策略迭代

值迭代：直接解 BOE，v → π → v 交替，每次值只代入一步，vk 不是任何策略的状态值。策略迭代：π → vπ → π 交替，每次把当前策略评估到底，vπk 是真正的状态值，且单调不减。

同一个起点下：策略迭代每轮都不比值迭代慢（定理 4.1 的证明就是这个比较）。二者都是截断策略迭代的极端。

易混辨析：有模型 vs 无模型；动态规划

动态规划：已知模型、直接计算（本章）。有模型强化学习：用数据估计模型，并在学习中使用它。无模型强化学习：学习中不估计模型，直接从经验估值或学策略（第 5–10 章）。

本篇小结

本章公式卡

值迭代：πk+1 = argmaxπ(rπ + γPπvk)，vk+1 = rπk+1 + γPπk+1vk；逐元素 vk+1(s) = maxa qk(s, a)
策略迭代：vπk = rπk + γPπkvπk；πk+1 = argmaxπ(rπ + γPπvπk)
策略改进引理：vπk+1 ≥ vπk；收敛：vk（值迭代）≤ vπk ≤ v*
截断策略迭代：内层 v(j+1) = rπk + γPπkv(j) 只做 jtruncate 次；j = 1 为值迭代，j = ∞ 为策略迭代
命题 4.1：初值取 vπk−1 时 v(j+1) ≥ v(j)

回扣三问

  1. 值迭代每轮做哪两步？vk 是状态值吗？
    先自己答，再点开

    策略更新（对 qk 取贪心）和值更新（vk+1(s) = maxa qk(s, a)）。vk 不是任何策略的状态值，只是收敛到 v* 的中间量。

  2. 策略迭代为什么不变差？为什么近处先收敛？
    先自己答，再点开

    贪心改进满足 rπk+1 + γPπk+1vπk ≥ vπk，展开得 vπk+1 ≥ vπk。远处的状态要“借道”近处的状态才能拿到目标奖励，所以近处先找到通往目标的动作。

  3. 截断策略迭代怎么统一前两者？迭代几次划算？
    先自己答，再点开

    策略评估只代入 jtruncate 次：j = 1 是值迭代，j = ∞ 是策略迭代。几次就能明显加速，太多收益递减，因为策略马上就要变。
