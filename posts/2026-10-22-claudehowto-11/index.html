不用守着它：放后台、定时跑、换个设备接着看

原教程“高级功能”的另一半，讲的是让 Claude Code 脱离“你盯着一个终端”的工作方式：长任务放到后台、用事件流代替轮询等待、定时重复执行、从手机或浏览器接管本机会话、用 worktree 同时开几条线。最后收一些天天用得上的终端习惯：输出风格、状态栏、快捷键和 ! 直接跑命令。这些功能版本更新最频繁，带版本号的细节以原文为准。

本系列是开源教程《Claude How To》（luongnv89 与社区贡献者编写，MIT 协议；本笔记依据 2026 年 10 月 20 日的仓库版本（commit 188f468），原文标注对应 Claude Code v2.1.302）的学习笔记。原教程按十个模块（01-slash-commands 到 10-cli）组织，配了大量可复制的模板。这里重排成十二篇：先用一篇讲清七种扩展机制的分工，再逐个拆开，每个功能按“它解决什么问题、最小可用配置放在哪个路径、什么时候不该用”来写，并配上“读配置猜行为”、模拟器和场景判定题。功能与字段取自原文（主要依据英文原版，中文版是它的缩写译本），每节标出对应的原文目录；为演示设的场景和数值标“示意”。Claude Code 更新很快，原文里带版本号的细节以原文和官方文档为准。

后台任务与 Monitor

原文「Background Tasks」「Monitor Tool (Event-Driven Streams)」

后台任务让长时间的操作（整套测试、构建、迁移、部署脚本）不阻塞对话：跑起来以后按 Ctrl+B 放到后台，或者直接说“在后台跑测试”；你继续和 Claude 做别的，任务结束时 Claude 收到通知。/tasks 列出正在跑的 shell 和子代理，可以看输出或停掉。时间限制只在无人值守的会话里有（-p、SDK、CI、云端会话：默认 30 分钟、最多 2 小时），终端、桌面、VS Code 里的后台命令不限时。CLAUDE_CODE_DISABLE_BACKGROUND_TASKS=true 整体关闭。

Monitor 工具（v2.1.98）解决“等”的问题：它挂在一个后台命令的 stdout 上，每一行输出就是一个事件，会唤醒会话。和用 /loop 或 sleep 轮询相比，原文强调两点：轮询每一轮都要一次完整的 API 往返，不管有没有变化；Monitor 没事件时不花 token，有事件时立刻反应。两种典型写法：流过滤（tail -f app.log | grep --line-buffered "ERROR"）和定期检查只在变化时输出（循环里查 API，有新评论才打印）。原文说的头号坑：管道里用 grep 一定要加 --line-buffered，否则 grep 攒满 4KB 才输出，低流量时事件会延迟几分钟。每个 Monitor 都有截止时间（最多 30 分钟，-p 里 10 分钟），到期后 Claude 会被通知去重新挂上。

调一调等待时长和轮询间隔，比较两种方式要多少次 API 往返（示意）。

示意计算：轮询次数 = 等待时长 ÷ 间隔；Monitor 的唤醒次数 = 事件数。真实成本还取决于每次往返的上下文大小。

动态工作流：把扇出写成脚本

原文「Dynamic Workflows」

动态工作流（v2.1.154）让 Claude 用一个脚本编排几十到几百个后台子代理：扇出、流水线、并行阶段都写在脚本里，而不是靠模型临场发挥，所以是确定性的。单个代理只有一个上下文窗口，工作流把任务拆给很多代理再汇总结果。原文给的适用场景：全面覆盖（跨很多文件或维度的审计、审查）、提高置信度（多个独立视角，再交叉验证发现）、超出单个上下文的规模（大迁移、大范围排查）。一次性的、你已经想清楚的任务，原文说单个代理或直接改仍然是正确选择。

用法：直接让 Claude“用工作流审一遍 src/ 下每个文件”，它会写编排脚本并在后台运行；/workflows 看运行中和已完成的工作流。规模有一个建议值（默认 medium，目标少于 10 个代理；Pro 计划默认 small），在 /config 的 Dynamic workflow size 里改，或设 workflowSizeGuideline；它是建议而不是硬上限，硬上限是 CLAUDE_CODE_MAX_CONCURRENT_SUBAGENTS。/effort 里的 Ultracode 开关打开后，Claude 默认就用工作流来做事。

四种“多代理”方式容易混，先理一下。

易混辨析：子代理、动态工作流、Agent Teams、/batch

子代理：Claude 临场决定委派一个或几个，结果交回。动态工作流：Claude 先写一个编排脚本，按脚本确定性地扇出几十上百个后台子代理并汇总，适合大范围、可并行的工作。

Agent Teams（实验）：多个独立的 Claude Code 实例，靠共享任务列表和邮箱互相沟通。/batch：随附 Skill，用 git worktree 编排大规模的并行修改。

定时任务

原文「Scheduled Tasks」

本地定时有两种：/loop 按间隔重复执行一个提示词（/loop 5m 检查部署是否完成，也能写自然语言“每 30 分钟检查一次构建状态”，或标准 5 段 cron）；一次性提醒（“下午 3 点提醒我推 release 分支”“45 分钟后跑集成测试”）。它们的共同特点是随会话存在：Claude Code 在运行才会触发，会话结束就清掉，错过的不补跑，重启不保留；每个会话最多 50 个，循环任务 3 天后自动过期，触发时间有少量抖动。底层是 CronCreate / CronList / CronDelete 三个工具。

/schedule 创建的是云端定时任务（在 claude.com 上叫 Routines），跑在 Anthropic 的基础设施上，重启不丢、本机不用开着。原文提醒一个坑：只要设置了 ANTHROPIC_API_KEY、ANTHROPIC_AUTH_TOKEN 或 apiKeyHelper 之一，/schedule 就会静默不可用，同样受影响的还有 Remote Control、claude.ai 的 MCP 连接器和通知偏好。需要长期稳定的自动化，原文建议还是用 CI/CD、GitHub Actions 或桌面应用的定时任务。

在哪里跑：远程、网页、桌面与外部输入

原文「Remote Control」「Web Sessions」「Desktop App」「Channels」「Chrome Integration」

Remote Control：会话仍然跑在你的机器上，你从手机、平板或任意浏览器接着操作，本机的 MCP、文件和命令行工具都能用。启动用 claude remote-control --name "Auth Refactor"（服务器模式，可同时服务多个会话）或会话里 /remote-control（别名 /rc），然后用终端打印的 URL、按空格显示的二维码，或在 claude.ai/code 和手机应用里按名字找。只走出站 HTTPS，不开入站端口。终端要一直开着。

网页会话：会话跑在 Anthropic 的云上，不依赖你的本机环境。命令行里 claude --cloud "实现新接口" 创建（--remote 是已弃用的别名），claude --teleport 或 /teleport 把网页会话拉回本地终端。桌面应用：可视化 diff 审阅、内嵌浏览器预览、PR 监控、多会话自动 worktree 隔离、定时任务，/desktop 把当前 CLI 会话交给它。Channels（研究预览）：通过 MCP 把 Telegram、Discord、iMessage、webhook 的消息推进正在运行的会话，claude --channels plugin:名字@市场。Chrome 集成：claude --chrome 或 /chrome，让 Claude 操作你登录状态下的浏览器做调试和验证，遇到登录页和验证码会停下等你。

worktree 并行

原文「Git Worktrees」

claude --worktree（-w）在一个隔离的 git worktree 里启动，可以在不 stash、不切分支的情况下并行做几件事。worktree 建在 <仓库>/.claude/worktrees/<名字>；会话结束时如果没有改动会自动清理。-w 还接受 GitHub PR 或 GitLab MR 的 URL，加 --tmux 会顺带开一个 tmux 会话。

三个设置：worktree.baseRef 决定从哪里分出来（默认 "fresh" 从 origin/默认分支，忽略你本地没推的提交；"head" 从本地 HEAD）；worktree.sparsePaths 在 monorepo 里只稀疏检出需要的包；worktree.bgIsolation 控制后台会话是否自己建 worktree（默认建，"none" 直接改当前工作区，代价是前后台并发修改可能冲突）。相关的工具 EnterWorktree、ExitWorktree 和 Hook 事件 WorktreeCreate、WorktreeRemove。

终端习惯：风格、状态栏、快捷键

原文「Output Styles」「Status Line」「Interactive Features」

输出风格改的是 Claude 怎么回答（角色、语气、格式），不是它知道什么。内置五种：Default、Proactive（遇到常规决定直接做，不停下来问，但不改变权限模式）、Explanatory（步骤之间加“Insights”解释实现选择）、Learning（除了解释还留 TODO(human) 让你自己写一小段）、Concise（先给结果，省掉铺垫）。用 /output-style 名字 或 /config 切换，在 /clear 或新会话后生效；自定义风格放 ~/.claude/output-styles/ 或 .claude/output-styles/，改沟通方式但仍要它写代码时加 keep-coding-instructions: true。风格只作用于主对话，子代理不受影响。

状态栏是一个命令，Claude Code 把一段 JSON（模型、上下文用量百分比、花费、分支、worktree 等字段）从 stdin 喂给它，它打印什么底部就显示什么，用 /statusline 配置。几个天天用的交互：! 开头直接跑 shell 命令（v2.1.186 起输出会自动发给 Claude 并得到回应，"respondToBashCommands": false 改回只进上下文）；多行输入用 \ 加回车、Shift+Enter 或 Ctrl+J；Ctrl+R 搜索历史（默认跨所有项目，Ctrl+S 收窄到当前项目）；/keybindings 编辑 ~/.claude/keybindings.json。

常用快捷键速查（据原文表，可在下面自测）。

易混辨析：输出风格、CLAUDE.md、--append-system-prompt

输出风格修改系统提示词，决定每一轮的角色、语气、格式；CLAUDE.md 作为系统提示词之后的一条用户消息加入，告诉 Claude 项目约定；--append-system-prompt 只对这一次调用追加系统提示词，不删除任何东西。

回扣开头的三个问题

先自己答，再点开
1. /loop 轮询与 Monitor 的区别？Monitor 最常见的坑？

轮询每一轮都要一次完整 API 往返，不管有没有变化；Monitor 挂在后台命令的 stdout 上，每行输出是一个事件，没事件时不花 token，有事件立刻唤醒。最常见的坑是管道里的 grep 没加 --line-buffered，输出攒满 4KB 才吐，事件延迟几分钟。Monitor 有截止时间（最多 30 分钟，-p 里 10 分钟）。

2. /loop、提醒、/schedule 各跑在哪？会话关了还跑吗？

/loop 和一次性提醒是会话内的本地定时：Claude Code 运行时才触发，会话结束清除，错过不补，重启不保留，每会话最多 50 个，循环 3 天过期。/schedule 是云端定时（Routines），跑在 Anthropic 基础设施上，重启不丢、本机可以不开；设置了 API key 类环境变量时 /schedule 不可用。

3. Remote Control 与网页会话的根本区别？

Remote Control 的会话跑在你的机器上，只是换个设备操作，本机的 MCP、文件、命令行工具都可用，终端要开着；网页会话跑在 Anthropic 云上，不依赖本机环境，用 claude --cloud 创建，claude --teleport 拉回本地。
