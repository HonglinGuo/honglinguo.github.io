反思：做完了，再让一个“挑刺的”看一遍

原书第 4 章

即使流程设计得再好，第一版输出也常常不够准确、不够完整。反思（Reflection）让智能体评估自己的输出，再用评估结果改进它。原书把它拆成四步：执行（产出初稿）→ 评估 / 评审（用另一次 LLM 调用或规则集检查事实、连贯性、风格、完整性、指令遵循）→ 反思 / 优化（据此改稿、调参数，甚至改整体计划）→ 迭代，直到满意或触发停止条件。和链、路由最大的不同是：它引入了反馈循环。

原书推荐的实现是把角色分开：生产者只管产出，评审者只管挑问题，评审者通常带一个具体身份，比如“高级软件工程师”“严谨的事实核查员”。单个智能体也能自我反思，但分成两个角色（或两次用不同系统提示的调用）能避免评审自己作品时的“认知偏差”，更客观。原书的 LangChain 示例让模型写一个阶乘函数，评审者要么列出问题清单，要么回复 CODE_IS_PERFECT，以此或最大迭代次数作为停止条件；ADK 示例则让评审者输出 {status, reasoning} 结构化结论。

原书也说清了代价：每轮都是新的 LLM 调用，成本和延迟上升，不适合时间敏感的场景；对话历史每轮都在变长，内存密集，更容易撞上上下文窗口或 API 限制。它还指出反思和两个模式天然配合：目标设定与监控提供评判基准，记忆让反思从一次性事件变成可累积的过程（都在第 4 篇）。

问题
初稿常常不准确、不完整，基础工作流没有让智能体发现并修正自身错误的环节。
做法
执行 → 评审 → 优化 → 迭代；推荐分成生产者和评审者两个角色。
何时用
质量、准确性、细节比速度和成本更重要：长文、代码、详细计划。需要高客观性时用独立评审者。
代价
延迟和成本上升；历史膨胀，可能超出上下文窗口或触发 API 限制。
实现
单轮反思用 LCEL 就能做；完整迭代要有状态的工作流（LangGraph、ADK 的 SequentialAgent / LoopAgent）。
相关
目标监控提供基准，记忆让反思可累积；推理技术里的“自我纠正”是同一思路。

规划：方法是要“发现”的，还是已经知道的

原书第 6 章

规划（Planning）是智能体构思一系列行动、从初始状态走向目标状态的能力。你说“组织一次团队外出”，只定义了目标和约束（预算、人数、日期），没给方法；规划智能体要自己把路线想出来。计划不是预设的，而是按请求动态生成的。原书强调它的核心价值是适应性：首选场地订不到时，好的智能体不会直接失败，而是记下新约束、重新评估、给出替代方案。

但原书紧接着泼了冷水：动态规划是特定工具，不是通用解。当解法已经被充分理解、可以重复时，把智能体限制在预先确定的固定工作流里更有效，能减少不确定和不可预测的行为。是否用规划，取决于一个问题：“方法”需要被发现，还是已经已知？

按这个标准判断几个场景。

模式卡 · 规划

Planning

问题
复杂目标无法一步完成；没有结构化方法时，智能体难以把高层目标拆成可执行步骤并处理依赖。
做法
先生成连贯的计划（子目标 / 步骤），再按序执行、编排工具；遇到障碍时调整计划。
何时用
请求无法由单个动作或工具完成：研究报告、新员工入职、竞品分析等多步且相互依赖的流程。
不该用
方法已知、可重复的流程，用固定工作流更可靠可预测。
实现
在提示或任务定义中显式要求“先出计划再执行”（原书用 CrewAI 演示）；Deep Research 是典型产品形态。

Deep Research：规划模式的产品形态

原书第 6 章、第 17 章

原书在规划和推理两章都拿 Deep Research 做例子。Google Gemini Deep Research 先把用户的问题分解成多点研究计划，交给用户审阅修改；批准后进入迭代的“搜索—分析”循环，根据已收集的信息动态调整查询、识别知识缺口、核对差异；整个过程异步运行，可能分析数百个来源，用户可以离开、完成时收到通知；最后不是把结果罗列出来，而是综合成有章节结构的多页报告，并给出完整的来源列表。

原书在第 17 章把它概括为一个转变：普通搜索立刻给链接，综合工作留给用户；Deep Research 则是用户给出复杂问题和一段“时间预算”（通常几分钟），换回一份详细报告。OpenAI 的 Deep Research API 有三点被原书强调：带内联引用的结构化输出；公开所有中间步骤（推理、搜索查询、运行的代码），便于调试；支持 MCP，能把私有知识库接进来。模型有高质量的 o3-deep-research 和低延迟的 o4-mini-deep-research 两档。

    推理技术全家福：核心都是推理时多花算力

    原书第 17 章

    第 17 章把这些技术归到一个共同原则下：在推理过程中分配更多计算，给模型更多时间或步骤，换取更准确、更连贯、更鲁棒的结果。按原书的顺序：

    思维链 CoT：让模型写出中间推理步骤，可以用少样本示例，也可以只说“逐步思考”。思维树 ToT：在 CoT 基础上分叉出多条推理路径，支持回溯和比较。自我纠正：对草稿和中间思考做内部评审、迭代改进，就是第 4 章反思的推理版。程序辅助语言模型（原书写作 PALMs）：让模型生成并执行代码，把精确计算和逻辑操作交给确定性环境。RLVR（可验证奖励强化学习）：在数学、代码这类有确定答案的问题上训练，让“推理模型”学会可变长度的长思考，能自我纠正和回溯，难题上多花算力。

    ReAct：推理和行动交错，思考 → 行动（调工具）→ 观察 → 再思考。辩论链 CoD：原书称其为微软提出的框架，多个模型像委员会一样提出、互相批评、反驳，减少个体偏见。辩论图 GoD：把论点做成节点、“支持 / 反驳”做成边，结论来自图中最稳固、有证据支撑的论点集群。MASS：自动搜索多智能体系统的提示词和拓扑（本篇最后一节）。

    易混辨析：反思 vs 自我纠正

    原书第 17 章说自我纠正“如第 4 章的专门示例所示”，两者是同一种思路：反思作为工作流模式，常常拆成生产者和评审者两个角色、跨多次调用；自我纠正作为推理技术，强调在一次推理过程里对草稿和中间思考做内部审查。推理模型通过 RLVR 学会的回溯，可以看作把自我纠正内化进了模型。

    ReAct：智能体思考过程的骨架

    原书第 17 章

    原书在第 17 章末尾用 ReAct 总结“智能体的思考过程”：思考（分解问题、制定计划、分析现状，这段内部独白让推理透明、可引导）→ 行动（从预定义的离散动作集中选一个，比如搜索、读网页、给出最终答案）→ 观察（拿到环境反馈）。循环直到智能体执行“完成”动作。ReAct 常用少样本示例，给模型看类似人类的解题轨迹。

    原书还提到一个细节：思考的频率可以按任务调整。事实核查这类知识密集任务，每个动作前后都思考；在模拟环境里导航这类动作很多的决策任务，思考可以更节制，让智能体自己决定何时需要思考。

    推理扩展定律：小模型 + 更多思考预算

    原书第 17 章

    训练扩展定律讲的是数据和算力越多、模型越好；原书介绍的推理扩展定律讲的是另一件事：推理时投入更多计算，往往能让相对小的模型得到更好的结果。这不一定是换更强的 GPU，而是用更复杂的推理策略，典型例子是让模型生成多个候选答案（多样化束搜索、自一致性），再用选择机制挑出最好的那个。

    原书由此得出的结论是：“更大就一定更好”并不成立，部署智能体时要在模型大小、响应延迟、运营成本三者之间权衡，把算力花在最能提升质量的地方。

    MASS：让系统自己搜出提示词和拓扑

    原书第 17 章（可选高级主题）

    多智能体系统的效果很依赖两样东西：每个智能体的提示词质量，和它们之间的交互拓扑。两者组合起来是个巨大的搜索空间。MASS（Multi-Agent System Search）用三阶段交错优化来走这个空间，可选的积木包括聚合、反思、辩论、总结、工具使用。

    原书总结的三条设计原则：先用高质量提示词把单个智能体调好再组合；用有影响力的拓扑组合，而不是在无约束的空间里乱搜；最后做工作流级联合优化，把智能体之间的相互依赖考虑进去。

    逐个看三个阶段，每个阶段都带着原书举的例子。

    回扣开头的三个问题

    先自己答，再点开
    1. 反思为什么推荐拆成生产者和评审者？它的代价是什么？

    避免评审自己作品时的认知偏差，评审者可以带特定身份和标准，更客观。代价是每轮新增 LLM 调用，成本和延迟上升；历史不断膨胀，内存密集，可能超出上下文窗口或触发 API 限制。

    2. 判断该不该用规划模式，原书给的关键问题是什么？

    “方法”需要被发现，还是已经已知？方法已知、可重复时，用固定工作流更可靠、更可预测。

    3. ReAct 比 CoT 多了什么？推理扩展定律说的是什么？

    ReAct 在推理中交错行动和观察（思考 → 行动 → 观察），能根据实时反馈调整。推理扩展定律：推理时投入更多计算（如多候选 + 选择），相对小的模型也能得到更好的结果，需要在模型大小、延迟、成本之间权衡。
