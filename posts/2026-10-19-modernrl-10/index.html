训练决定上限，推理计算决定发挥

普通语言模型一个 token 接一个 token 往下写，一步算错就一路错下去，不会停下来检查。推理模型用 RL 学会组织长思考，并把“想多久”做成了可调的预算。原教程这两章回答三个问题：多出来的推理计算该怎么花（多采样、多修订、多搜索）？什么时候加计算不再划算？以及——候选里出现了正确答案，系统能不能把它挑出来？后者引出了过程奖励模型。

从语言模型到推理模型

原文 docs/chapter19_reasoning/emergence-and-o1.md、r1-zero-pure-rl-reasoning.md

原文的开场例子：解 x² − 5x + 6 = 0 时把判别式算成 −1，后面每一步都在复数域里“认真”延续这个错误。根源是自回归生成——前面的 token 一旦确定，后面只能在条件概率下继续，缺少软件开发里那种“编译—测试—定位—修改”的循环。推理模型用大规模 RL 训练模型组织更长的内部推理（检查、回退、换方法），并让推理时的思考长度可以随任务变化。

OpenAI 的 o1（2024.9）把这件事做成了产品，随后加入 reasoning_effort 档位，表达质量、延迟和费用之间的取舍；o3 / o4-mini（2025.4）把搜索、Python、文件读取等工具放进推理循环——猜递推关系 → 用 Python 验算前 20 项 → 发现第 17 项不对 → 修改猜想。原文特别提醒读榜时保留评测方式：o1 发布说明里 AIME 2024 上 GPT-4o 单次约 12%、64 次共识约 56%，o1 单次约 74%、64 次共识约 83%——采样次数本身就会改变分数。

开放模型这边，R1-Zero 说明了在有规则奖励时，只用正确性奖励和格式奖励做 GRPO，也能间接强化出自我检查（第 9 篇）：检查能提高正确率，正确率带来奖励，所以检查行为被保留下来。原文的解读是“涌现与激活”并存——推理的原材料来自预训练，RL 把它们组织成稳定的策略；它需要三个前提：基座能生成候选、题目有自动验证器、同一组采样里有对有错。

测试时计算：并行采样、顺序修订、树搜索

原文 docs/chapter19_reasoning/test-time-scaling.md（16.3 节）

Snell 等人（2024）用一组对照实验回答了“推理预算怎么花”：固定 Llama-3-8B-Instruct，比较“多采样 + 验证器挑选”与“换一个更大的模型”。原文总结了三条：恰当分配推理计算能让小模型超过分配不当的大模型；基座单次正确率 p 接近 0 时，多加预算收益很快消失；没有通用最优分配——题目难度不同、验证器可靠程度不同，最佳花法都不同。训练计算决定能力上限，推理计算决定接近上限的程度。

三种花法。并行采样（Best-of-N）：独立生成 N 个，至少一个正确的概率（覆盖率）是 1 − (1 − p)N；第 N + 1 个候选的边际收益是 p(1 − p)N，每多一个就乘一次 (1 − p)，几何级数衰减，而每个候选的成本是固定的——当它低于单个候选的成本时就该停。顺序修订：让模型检查、改错，延迟随轮数串行增加，没法靠加 GPU 缩短。树搜索：结合广度与深度，常用过程奖励给中间步骤打分来剪枝。

最关键的一句：覆盖率只保证正确答案出现在候选里，能不能挑出来取决于验证器。没有可靠验证器时，用多数投票（self-consistency）：把最终答案规范化后数票。它隐含的假设是不同推理路径独立犯错、错得各不相同；一旦模型在同一个地方系统性地犯同一个错，多数票选出的就是错误答案。

思考预算：一条长链，还是多条短答

原文 hybrid-thinking.md（16.4）、adaptive-thinking.md（16.5）、cot-visibility-alignment.md（16.6）

同一个模型可以有两种模式：深度思考与直接回答（DeepSeek V3.1、Qwen3 的双模式，再加上 thinking budget 控制思考长度）。原文引用 Ma 等人（2025）的对比：同样 4000 token，一条 4000 token 的长链，还是 8 条 500 token 的短回答再投票？在低预算区间，多条短答常常更划算——但结论不能外推：需要连续推导依赖的任务（证明、写复杂算法、多步规划）后面的步骤依赖前面的结论，没法拆成 8 个独立的短证明投票；短答要胜出，还要求单次成功率不太低、并且有可靠的验证或投票。

长思考训练的副作用是推理链变长：反复检查、重复表述、绕圈子。部署时硬截断很危险（截断点可能落在结论之前），所以要在训练阶段做 long2short：监督式压缩（用更短的正确推理做 SFT），或在 RL 奖励里同时放进“答对”和“少算”。原文 16.5 节进一步讨论自适应思考：由模型根据任务判断要想多久；并提醒“长不等于好”——无效推理、延迟与成本的波动、推理链注入攻击都要考虑。

关于推理链给不给用户看，原文分清了三个层次（内部推理、轨迹、面向用户的解释）：隐藏原始推理链能防蒸馏、留出安全处理空间；展示能支持开源生态与步骤检查。原文的立场是：过程对齐比可见性更重要——推理文本要和最终答案一致，PRM、CoT 监控、可解释性工具都是过程对齐的研究方向。

过程奖励：不只看答对，还看推对

原文 docs/chapter20_prm_search/outcome-vs-process.md、discriminative-prm.md、generative-prm.md、formal-prm.md、inference-time-search.md

结果奖励（ORM）只问“整件事完成了吗”：便宜、稳定，答案可以代回、代码可以跑测试。过程奖励（PRM）问“走到这一步，还在正确方向上吗”。原文的例子是一份“证明 √2 是无理数”的九步证明：第 6 步把 4k² = 2q² 错写成 4k = q²，但最后结论碰巧是对的。只核对结论的 ORM 给整条回答 1 分——第 6 步的代数错误不但没被惩罚，反而和正确步骤一起被强化。这就是稀疏奖励的归因困难。

形式上，ORM(q, o) 给整条回答一个分；PRM(q, o, i) 给第 i 步一个分（+1 / 0 / −1 或“这一步正确”的概率），训练数据是“前缀 + 这一步是否正确”，标注量按步骤数放大——OpenAI 为此建了 PRM800K。原文给了三个判断“值不值得上 PRM”的条件：步骤能否稳定切分（证明的一次变换、代码的一次修改、Agent 的一次工具调用可以；写诗不行）、错误会不会向后传播、结果验证是否足够。R1-Zero 只用 ORM 也学出了自我检查，说明结果奖励在某些条件下够用。

PRM 有三种形态：判别式（分类器给每步打分）、生成式（像 ThinkPRM 那样先写自然语言评价再下结论，复用模型已有的推理能力，评价本身也能“多想一会儿”）、形式化验证器（Lean 4 等定理证明器给出确定的对 / 错，AlphaProof、DeepSeek-Prover 走这条路，但只适用于能形式化的领域）。用法上，PRM 可以给 Best-of-N 重排序、在 beam search / MCTS 里剪枝，也可以把步骤分数放进 RL 训练——这正是第 5 篇说的“网络引导搜索”在 LLM 上的翻版。

    易混辨析：ORM、PRM、验证器与奖励模型

    ORM vs PRM：一条回答一个分 vs 每一步一个分。ORM 便宜稳定但归因困难；PRM 能定位错误但标注贵。

    规则验证器 vs PRM：验证器通常只能检查最终结果（答案、测试），是 ORM 的一种；Lean 这类形式化验证器能逐步检查，是确定性的 PRM。

    覆盖率 vs 准确率：覆盖率是“候选里有没有正确答案”，准确率还取决于“挑不挑得出来”。

    训练计算 vs 推理计算：前者改参数、提高上限，后者不动参数、让这一次更接近上限；知识型失败只能靠前者。

    1. 哪类失败能靠推理时多算补救？Best-of-N 收益为什么递减？

    采样型失败（会方法但这次算错、选错路线）可以靠多采样、修订、搜索补救；知识型失败（根本不会）只能靠训练。第 N + 1 个候选只有在前 N 个都错时才有用，收益 p(1 − p)^N 每次乘 (1 − p) 几何衰减，而成本固定；p ≈ 0 时一开始就几乎没收益。

    2. 覆盖率高为什么不等于答对率高？多数投票何时失灵？

    覆盖率只说明正确答案出现在候选里，还要有验证器把它挑出来；验证器会误判，N 越大被它“骗”的机会也越多。多数投票假设各路径独立犯错且错得分散；当模型在同一处系统性地犯同一个错（错误答案集中）时，错误答案会赢得多数票。

    3. ORM 与 PRM 的区别？mean、min、product 各表达什么？

    ORM 一条回答一个分，只看结果；PRM 给每一步打分，能指出错误第一次出现在哪里，但标注贵、要能切分步骤。mean 容忍个别差步骤（可能稀释关键错误）；min 只要有一步差整条就不行（最保守）；product 在步骤独立时等于“全部正确”的概率，对低分步最敏感。原文的数学实验里 min 效果最好，但开放写作不能照搬。
