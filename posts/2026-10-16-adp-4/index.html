让智能体越用越好

前三篇的智能体做完一件事就“清零”。这一篇的四个模式让它跨越时间：记忆让它记住过去，学习与适应让它根据经验改变行为，目标设定与监控让它知道自己是否走在正确的路上，探索与发现让它主动去找还不知道的东西。

本系列是开源书《Agentic Design Patterns 智能体设计模式》（Antonio Gulli 著，xindoo 等中文翻译）的学习笔记。21 个模式按主题重新分成 7 篇。每个模式先讲它要解决的问题，再用一张统一格式的模式卡收住，最后配一个小实验；原书的 LangChain / ADK / CrewAI 代码不复述，建议对照原书阅读。

记忆管理：工作台和档案柜

原书第 8 章

原书把智能体记忆分为两类。短期记忆（上下文记忆）像工作记忆，主要就是上下文窗口：最近的消息、回复、工具结果、反思。它容量有限，要靠总结旧对话、突出关键细节来管理；而且长上下文模型只是把短期记忆扩大了，会话一结束照样丢失，每次处理还很贵。长期记忆（持久记忆）存在智能体环境之外的数据库、知识图谱或向量库里，需要时检索出来、并入短期上下文。

原书用 Google ADK 讲具体落地，三个组件：Session 跟踪单个聊天线程（按时间排列的事件 events + 临时数据 state），由 SessionService 管生命周期，实现有内存版（测试用、重启即丢）、数据库版、Vertex AI 版；State 是 Session 的“草稿本”，一个键值字典，用前缀区分范围：user: 跟用户走、跨会话，app: 全体用户共享，temp: 只在当前轮有效、不持久化；MemoryService 管可搜索的长期知识，add_session_to_memory 写入、search_memory 检索，生产环境常用基于 RAG 的 VertexAiRagMemoryService。

原书特别提醒：不要拿到 session 后直接改 session.state 字典。这样做绕过了事件机制：不会记入事件历史、可能不被持久化、有并发问题、时间戳也不更新。正确做法是用 output_key（保存智能体的最终文本回复）或在 append_event 时带上 EventActions.state_delta。托管方案里还有 Vertex Memory Bank：用 Gemini 异步分析对话、提取关键事实和偏好、按用户 ID 组织并自动整合矛盾。

这些数据该放在哪里？

模式卡 · 记忆管理

Memory Management

问题
没有记忆，智能体无法维持对话上下文、跟踪多步任务、从经验中学习或个性化。
做法
短期记忆在上下文窗口内；长期记忆在外部存储，按需语义检索后并入上下文。
何时用
不只是回答单个问题：要维持上下文、跟踪任务进度、记住用户偏好、从成败中学习。
实现
ADK：Session / State / MemoryService；LangChain：ChatMessageHistory、ConversationBufferMemory；LangGraph：检查点器（短期）+ Store（长期，命名空间 + 键）。

长期记忆的三种类型：事实、经历、规则

原书第 8 章 LangGraph 部分

原书借用人类记忆的分法，把长期记忆分成三类。语义记忆：记住事实，例如用户偏好、领域知识，可以存成一个持续更新的用户“配置文件”（JSON），也可以存成一组独立的事实文档。情景记忆：记住经历，对智能体而言常常是“上次是怎么把这类任务做成的”，实践中多用少样本示例实现。程序记忆：记住规则，即智能体的核心指令和行为方式，通常在系统提示里；智能体修改自己的提示来改进很常见，有效的做法是反思：审视当前指令和最近的交互，然后改写自己的指令。

分一分。

易混辨析：记忆管理 vs RAG

两者都用向量库和语义检索，原书第 8 章也把 RAG 列为记忆的一个应用。区别在写入方：RAG 的知识库通常是预先准备好、定期更新的外部文档；记忆是智能体在交互中自己写入的（会话历史、提取的偏好、改写的指令）。所以记忆要处理“什么时候写、写什么、矛盾时怎么合并”，Memory Bank 的“整合新数据、解决矛盾”就是在干这件事。

记忆的提取、冲突消解在另一个系列里讲得更细：深入理解 AI Agent · 03 记忆与知识库。

学习与适应：从改参数到改自己的代码

原书第 9 章

原书先列了六种学习方式：强化学习（试错、奖惩）、监督学习（标注样本）、无监督学习（找隐藏模式）、基于 LLM 的少样本 / 零样本（几个例子就适应新任务）、在线学习（持续吸收数据流）、基于记忆的学习（回忆过往经验调整行动）。所谓“适应”，就是学习带来的行为或知识的可见变化。

两个对齐算法是本章重点。PPO 每次只对策略做小而谨慎的更新：收集一批经验，计算一个“裁剪”过的替代目标，在当前策略周围划出信任区域，像安全刹车一样阻止步子太大、毁掉已学到的东西。传统 LLM 对齐用 PPO 要两步：先用人类偏好训练奖励模型，再用 PPO 让 LLM 追求高分；这既复杂又不稳定，LLM 还可能学会“钻奖励模型的空子”。DPO 完全跳过奖励模型，直接用偏好数据更新策略：提高生成被偏好回答的概率，降低不受欢迎回答的概率。

原书还讲了两类“自我改进”系统。SICA（自我改进编码智能体）既是修改者又是被修改者：从历史版本档案里按成功率、时间、计算成本的加权分挑出最好的版本，让它分析档案、修改自己的代码库，再跑基准、记入档案，如此循环；它自己发明了“智能编辑器”“AST 符号定位器”等工具；旁边有一个异步监督者（另一个 LLM）盯着它，发现循环或停滞时可以介入停止；整个系统跑在 Docker 里隔离。原书也坦言其局限：很难让 LLM 每轮都独立提出新颖、可行的修改。AlphaEvolve 则用 Gemini Flash（广撒提案）+ Pro（深入改进）+ 自动评估 + 进化算法发现和优化算法；OpenEvolve 是一个开源的同类框架，可以进化整个代码文件。

拖动比率 r，看 PPO 的裁剪目标什么时候“踩刹车”。

PPO 的裁剪目标

原书只做了文字描述。这里用 PPO 论文的标准形式：L = min(r·A, clip(r, 1−ε, 1+ε)·A)。虚线是不裁剪的 r·A，实线是实际优化的目标，蓝色带是信任区域。

模式卡 · 学习与适应

Learning and Adaptation

问题
预编程逻辑应付不了没预料到的新情况；不能从经验中学习就无法优化策略、个性化交互。
做法
集成学习机制：从强化学习、偏好优化，到 SICA 式自我修改、AlphaEvolve 式进化搜索。
何时用
动态、不确定、持续演化的环境；需要个性化、持续改进、自主应对新情况。
要点
自我改进系统要配子智能体（分解任务、控上下文）和监督者（防循环停滞）；上下文窗口的组织方式很关键。

目标设定与监控：知道终点，也知道自己走到哪了

原书第 11 章

这个模式给智能体两样东西：明确的目标，和跟踪进度、判断是否达成的手段。原书要求目标符合 SMART：具体、可衡量、可实现、相关、有时限；监控则观察智能体的行动、环境状态和工具输出，形成反馈循环，让智能体能纠偏、改计划或升级。在 ADK 里，目标通常写在智能体指令里，监控靠状态管理和工具交互。

原书的示例是一个写代码的智能体：你给它问题描述和一份质量清单（“方案必须简单”“功能必须正确”“处理意外边界情况”），它起草 → 对照清单自查 → 判断 True / False → 不达标就改，直到 True 或用完尝试次数。紧接着原书就列了这个示例的问题：LLM 可能没真正理解目标却判定自己成功；可能幻觉；同一个 LLM 既写又判，更难发现自己走错了方向；监控太简单，有永远跑下去的风险；最终代码仍然要你自己运行和测试。更稳健的做法是把关注点分给不同角色：同伴程序员、代码审查员、文档编写员、测试编写员、提示词优化器。

模式卡 · 目标设定与监控

Goal Setting and Monitoring

问题
没有目标就只能被动反应；没有监控就无法判断行动是否带来了成功。
做法
定义清晰、可衡量的目标和成功标准；持续监控进度与环境；偏离时纠正、重规划或升级。
何时用
智能体要在少人干预下自主完成多步任务、适应动态条件。
风险
自判成功、幻觉、自写自判难纠偏、无限循环；解法是分离评审角色、设上限、真跑测试。

易混辨析：目标监控 vs 反思 vs 规划

规划回答“怎么走”，目标监控回答“走到哪了、到没到”，反思回答“哪里做得不好、怎么改”。原书第 4 章说三者常常协同：目标给反思提供评判基准，监控发现偏差后，反思充当纠正引擎，必要时触发重新规划。

探索与发现：去找“未知的未知”

原书第 21 章

前面的模式大多在已定义的解空间里优化。探索与发现则要智能体主动进入陌生领域、尝试新方法、产生新知识，目标是发现“未知的未知”。用例包括科研自动化、游戏策略（如 AlphaGo）、市场趋势发现、安全漏洞发现、创意生成。

原书的主案例是 Google Co-Scientist（AI 协同科学家）：基于 Gemini 的多智能体系统，主管智能体在异步框架里协调六个专门智能体，按“生成、辩论、进化”的循环模拟科学方法，并采用“测试时计算扩展”。原书强调它的定位是增强而非取代（“科学家在环”），局限包括只能读开放获取文献、缺少很少发表的负面实验结果、继承 LLM 的幻觉。安全上，研究目标和生成的假设都要过安全审查，用 1,200 个对抗性研究目标做了初步评估。

代码示例是开源的 Agent Laboratory：文献综述 → 实验 → 报告撰写 → 通过 AgentRxiv 共享知识，角色模仿学术层级（教授、博士后等），并用三个评审智能体从不同角度打分，模拟人类审稿。

模式卡 · 探索与发现

Exploration and Discovery

问题
静态、预编程的知识应付不了开放式问题，智能体无法超越“优化已知”。
做法
常用多智能体框架模拟科学方法：生成假设 → 批判评审 → 排名 → 进化最有前景的想法。
何时用
解空间没有完全定义的开放、复杂、快速演化领域：科研、市场分析、创意。
定位
增强人类而非完全自动化；人始终在环。

回扣开头的三个问题

先自己答，再点开
1. 上下文窗口很长了，为什么还需要长期记忆？ADK 用哪三个组件？

长上下文只是扩大了短期记忆：会话结束即丢失，每次处理成本高。ADK 用 Session（线程 + 事件）、State（会话草稿本，user: / app: / temp: 前缀）、MemoryService（可搜索的长期知识）。

2. PPO 的“裁剪”在防什么？DPO 省掉了哪一步？

防止单次更新离当前策略太远、毁掉已学到的东西（信任区域 = 安全刹车）。DPO 省掉了训练奖励模型这一步，直接用偏好数据优化策略。

3. 同一个 LLM 自写自判有什么风险？

没理解目标却判定成功、幻觉、更难发现自己走错方向、监控太简单可能无限循环；代码仍需真实运行测试。解法：分离出独立的审查、测试角色。
