智能体不是一次调用，是一个循环

第一章回答三个问题：智能体是什么、它怎么跟世界打交道、最小的一个怎么写。答案落在同一个结构上：感知 → 思考 → 行动 → 观察，周而复始。原书用五十行 Python 把这个循环写了出来，没有任何框架；这一篇把这段代码拆开逐行走一遍，后面十二篇的范式、框架、记忆、协议，都是在这个循环的某一环上加东西。

本系列是开源教程《Hello-Agents：从零开始构建智能体》（Datawhale 社区编写的开源教程，CC BY-NC-SA 4.0 协议；本笔记依据 2026 年 10 月 14 日的仓库版本）的学习笔记。原书十六章，按“概念 → 手写范式 → 平台与框架 → 自研框架 → 记忆、上下文、协议、训练、评估 → 综合案例”展开，代码量很大。这里重排成十三篇，用自己的话重讲：代码只保留能看清机制的骨架，做成可以逐行走读、可以填空回忆的互动；每篇末尾配原书面试题清单里的相关题目做口述演练。每节标出对应的原书章节，演示数值标“示意”。笔记同样按 CC BY-NC-SA 4.0 共享。

智能体是什么

原书 1.1.1–1.1.2 节

原书沿用经典教科书《Artificial Intelligence: A Modern Approach》的定义：智能体是能通过传感器感知环境、并自主通过执行器采取行动以达成目标的实体。四个要素里最关键的是“自主”：它不是被动响应刺激、照着指令执行的程序，而是基于感知和内部状态自己做决定。传感器不一定是摄像头，API 返回的数据流也算；执行器不一定是机械臂，执行一段代码、调用一个服务也算。

在 LLM 出现之前，智能体已经走过一条清晰的演进路线，每一级都是为了补上一级的缺口：简单反射只看当前输入（恒温器）；看不到的东西怎么办？于是有了基于模型的反射，内部维护一个世界模型（隧道里看不见前车，但知道它还在）；光理解世界不够，还得知道往哪走，于是有了基于目标（GPS 规划路线）；到达目标的路不止一条，选哪条？于是有了基于效用（在时间、费用、舒适之间权衡）；最后，学习是一种可以加给以上任何一类的元能力。

LLM 智能体和它们的根本区别在能力的来源：传统智能体的能力来自工程师显式编写的规则和知识，行为确定、有边界；LLM 智能体的能力来自海量数据预训练得到的隐式世界模型，能直接接住“规划一次厦门之旅”这种模糊、高层的自然语言指令，自己拆解任务、发现信息缺口、调用工具、按用户反馈修正。原书的一句话概括了这个转变：核心不再是编写代码，而是引导一个通用的“大脑”去规划、行动和学习。

三种分类，各看一个侧面

原书 1.1.3 节

分类不是为了背名词，而是给设计时的权衡起名字。原书给了三个互补的维度。第一个是内部决策架构，就是上面那条阶梯。第二个是时间与反应性：反应式智能体几乎即时响应，开销低但“短视”，安全气囊和高频交易靠它；规划式（审议式）智能体行动前先在世界模型里推演多步后果，像棋手，有远见但慢；混合式两者兼得。

LLM 智能体恰好是一种灵活的混合：在“思考”阶段分析局面、规划下一步，这是审议；在“行动、观察”阶段与工具交互并立即拿到反馈，这是反应。一个长期目标就被拆成一串“规划—反应”的微循环。

第三个维度最根本：知识以什么形式存在。符号主义把知识写成人可读的规则和知识图谱，透明可追溯，但脆弱，规则覆盖不到的情况就失灵（知识获取瓶颈）；亚符号主义（连接主义）把知识隐含在神经网络的权重里，擅长模式识别、对噪声鲁棒，但是黑箱，还会幻觉；神经符号主义想两者兼得。原书借卡尼曼的双系统作类比：系统 1 快、凭直觉，对应神经网络；系统 2 慢、讲逻辑，对应符号推理。LLM 智能体是神经符号的一个好例子：内核是神经网络，工作时却会产出思考、计划、API 调用这些明确的符号。

易混辨析：基于模型的反射 vs 规划式

两者都有“世界模型”。基于模型的反射用世界模型回答“世界现在是什么样”，然后仍按条件—动作规则立即反应，属于反应式；规划式用世界模型推演“如果我这样做，未来会怎样”，在多个行动序列里挑最好的。区别不在有没有模型，而在模型用来补全当下还是预演未来。

先描述环境，再设计智能体

原书 1.2.1 节，表 1.2

设计智能体之前，先把它要面对的任务环境说清楚。经典做法是 PEAS：Performance（性能度量，什么算做得好）、Environment（环境）、Actuators（执行器，能做什么）、Sensors（传感器，能看到什么）。四项写完，“这个 Agent 需要哪些工具、怎么评估”就有了骨架。

原书接着点出 LLM 智能体所处的数字环境的四个特性，每个都直接决定一项设计：部分可观察（一次 API 只看到一部分航班，所以要记忆和探索）；随机性（两次查价结果不同，所以要处理不确定、监控变化）；多智能体（别的用户、航司调价系统也在行动，可能抢走最后一张特价票）；序贯且动态（现在的动作影响未来，环境在你思考时也在变）。

选一个智能体，先自己写出它的 PEAS，再对照；然后看它的环境有哪些特性。

五十行代码里的智能体循环

原书 1.2.2–1.3 节

智能体不是一次完成任务，而是在智能体循环（Agent Loop）里一轮轮推进：感知（接收观察：用户指令或上一步行动的结果）→ 思考（规划下一步、选择工具和参数）→ 行动（调用工具，改变环境）→ 环境产生新的观察，进入下一轮。

要让 LLM 驱动这个循环，需要一个交互协议：规定模型每次输出的格式。原书用的是最朴素的文本协议，模型每次输出一对 Thought: … 和 Action: …；外部的解析器用正则抠出 Action，调用对应 Python 函数；函数结果被包装成一段简短的自然语言 Observation: … 追加回历史。注意分工：Thought 和 Action 是模型写的，Observation 是你的代码写的。模型从来没有真正“调用”过任何东西，它只是写出了一行文字。

整段程序只有四块：一个系统提示词（角色、工具清单、输出格式、何时 Finish）；两个工具函数（wttr.in 查天气、Tavily 搜景点）和一个名字到函数的字典；一个兼容 OpenAI 接口的 LLM 客户端；一个最多跑 5 轮的主循环。原书说这正是 LangChain 等框架的设计精髓，框架只是把这四块做得更健壮。

合上书，补全系统提示词的关键约束

这几条约束各防一种真实故障：不限定“只输出一对”，模型会一口气把 Observation 也编出来；不要求 Action 在同一行，正则就抠不全；不规定 Finish 格式，循环不知道何时结束。主循环里那段“截断多余 Thought-Action”的正则，就是为第一种情况兜底。

易混辨析：Observation 是谁写的

初学最容易误以为模型“执行了”工具。实际上模型只输出 Thought（推理）和 Action（一行调用意图的文本）；Observation 是宿主程序执行真实函数后拼出来、再塞回 prompt 的。所以模型如果在一次输出里自己写了 “Observation: 晴”，那是幻觉，必须截掉。后面讲的 Function Calling 只是把这行文本换成了结构化 JSON，分工没变。

Workflow 与 Agent：谁来决定下一步

原书 1.4 节

原书把智能体的应用分成两种协作模式。一种是开发者工具：Copilot、Claude Code、Cursor、Trae 这类，增强人的工作流而不是取代人；另一种是自主协作者：把高层目标委托出去，由智能体自己规划、执行、反思直到交付，关系从“命令—执行”变成“目标—委托”。后者的实现大致三类：单智能体自主循环（AutoGPT 一类）、多智能体协作（CAMEL 的角色扮演对话，MetaGPT、CrewAI 的组织化 SOP 流程，AutoGen、AgentScope 的灵活对话网络）、高级控制流（LangGraph 把执行建模成状态图）。这些在第 6 章会一个个上手。

另一条更实用的分界线是 Workflow 与 Agent。原书一句话：Workflow 让 AI 按部就班执行指令，Agent 赋予 AI 自由度去自主达成目标。Workflow 是预先画好的流程图，每个分支条件都写死（报销金额小于 500 元经理批，大于 500 元再转财务总监）；Agent 的下一步由模型根据实时信息决定，没有“如果晴天就推荐颐和园”这种规则，雨天它会自己推荐博物馆。

原书习题 3 追问：两者能不能结合？可以，而且常常应该：流程骨架和高风险关口（金额阈值、审批）用 Workflow 固定，需要理解和判断的环节（读用户描述、看商品照片、写回复）交给 Agent。这和《AI Agent Handbook》第 3 篇里的 Hybrid 是一回事。

题目取自原书 Extra01《面试问题总结》

能讲出来才算真的会。下面的题目来自原书附带的面试问题清单，要点是我根据本章内容整理的。先合上页面在心里（或者出声）答一遍，再展开对照；给自己打个分，标“有点模糊”和“讲不出”的题会在系列总览页汇总，方便集中复习。

你如何定义一个基于 LLM 的智能体？它通常由哪些核心组件构成？Extra01 · Agent 第 1 题

  • 定义：能感知环境、自主决策并通过行动达成目标的系统；LLM 智能体用 LLM 作为决策核心，在“思考—行动—观察”循环里推进任务。
  • 组件：LLM（推理与规划）、工具（执行器，扩展能力边界）、记忆（短期上下文 + 长期存储）、规划（任务分解、反思）、交互协议与解析器（把文本意图变成真实调用）、控制循环（最大轮数、终止条件）。
  • 加分：说明 Observation 由宿主程序产生、模型只产出意图；提到与 Workflow 的区别在于下一步由谁决定。

在构建一个复杂的 Agent 时，你认为最主要的挑战是什么？Extra01 · Agent 第 7 题

  • 可靠性：输出格式漂移、解析失败、幻觉出 Observation，需要格式约束、截断、重试和错误回填。
  • 不终止与成本：没有最大轮数时可能死循环（原书习题 6 的问题），要有步数、预算和终止条件。
  • 环境特性：部分可观察、随机、动态、多智能体，要求记忆、探索和对变化的监控。
  • 评估：只看最终准确率不够，还要看过程（步数、成本、工具调用正确性），第 12 篇展开。

退款审批该用 Workflow 还是 Agent？有没有方案 C？原书第 1 章习题 3

  • Workflow：规则清晰、可审计、成本低、结果可预测；但遇到规则外的情况（描述含糊、证据是图片）只能转人工。
  • Agent：能理解非结构化信息、处理例外；但不可预测、难审计，金额决策直接交给模型风险大。
  • 方案 C：Workflow 骨架 + Agent 节点。金额阈值、特殊商品拒退、超期等硬规则写死；Agent 只负责理解诉求、核对证据、给出建议和理由，高金额或低置信度转人工审批。

动手练（原书习题 4）

  1. 给旅行助手加“记住用户偏好”：偏好存在哪里？怎么进入下一次的 prompt？
    思路

    最简单是在 prompt_history 前面加一段“用户画像”，每次 Finish 后让模型或规则抽取偏好写回一个字典或文件；跨会话就要持久化。第 8 篇会讲记忆系统的正式做法。

  2. 门票售罄时自动给备选：要改工具还是改提示词？
    思路

    两处都改：工具返回结构化的“售罄”状态而不是一句空话；提示词里告诉模型遇到售罄应换一个景点重新查询。Observation 写得清楚，模型才知道该换路。

  3. 用户连续拒绝 3 次后反思策略：计数放在哪？
    思路

    计数是确定性状态，放在宿主代码里，不要指望模型自己数；达到 3 次时往 prompt 插入一条反思指令（“前三次推荐都被拒，先总结用户可能的偏好再推荐”）。这就是第 4 篇 Reflection 的雏形。

回扣开头的三个问题

先自己答，再点开
1. 智能体的四个要素？LLM 智能体和传统智能体的根本区别？

环境、传感器（感知）、执行器（行动）、自主性（基于感知和内部状态独立决策）。根本区别在能力来源：传统智能体靠工程师显式编写的规则与知识，行为确定有边界；LLM 智能体靠预训练得到的隐式世界模型，能直接处理模糊的高层自然语言指令，自己分解任务、调用工具、按反馈修正。

2. 最小 LLM 智能体由哪几块组成？TAO 分别由谁产生？

系统提示词（角色、工具清单、输出格式、终止约定）、工具函数和名字到函数的映射、LLM 客户端、带最大轮数的主循环（拼 prompt → 调模型 → 截断 → 解析 Action → 执行或 Finish → 追加 Observation）。Thought 和 Action 由模型生成；Observation 由宿主程序执行真实工具后生成并追加回历史。

3. Workflow 和 Agent 的分界线？什么时候不该用 Agent？

分界线是下一步由谁决定：Workflow 由预先编排的流程决定，Agent 由模型根据实时信息决定。步骤和分支事先能写清、需要可审计和可预测、错误代价高的环节，用 Workflow 或把它们固定在 Workflow 骨架里，Agent 只负责需要理解和判断的节点。
