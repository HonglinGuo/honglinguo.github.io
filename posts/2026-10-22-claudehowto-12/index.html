一条 claude -p，就是一个可编程的接口

交互式会话之外，Claude Code 还是一个标准的命令行程序：claude -p 接一段提示词，跑完就退出，能读管道、能输出 JSON、能按 Schema 返回结构化结果、能限制轮数和花费。这让它可以塞进 shell 脚本、Makefile 和 CI 流水线。这一篇用一个命令拼装器把常用参数串起来，再把几组最容易混的开关（限制工具的三个参数、三种“精简启动”）讲清楚。

本系列是开源教程《Claude How To》（luongnv89 与社区贡献者编写，MIT 协议；本笔记依据 2026 年 10 月 20 日的仓库版本（commit 188f468），原文标注对应 Claude Code v2.1.302）的学习笔记。原教程按十个模块（01-slash-commands 到 10-cli）组织，配了大量可复制的模板。这里重排成十二篇：先用一篇讲清七种扩展机制的分工，再逐个拆开，每个功能按“它解决什么问题、最小可用配置放在哪个路径、什么时候不该用”来写，并配上“读配置猜行为”、模拟器和场景判定题。功能与字段取自原文（主要依据英文原版，中文版是它的缩写译本），每节标出对应的原文目录；为演示设的场景和数值标“示意”。Claude Code 更新很快，原文里带版本号的细节以原文和官方文档为准。

两种模式

原文 10-cli「CLI Commands」「Interactive vs Print Mode」

交互模式是默认的：claude 进入 REPL，claude "解释一下这个项目" 带一个初始提示进入。打印模式 claude -p "…" 是非交互的：执行完就退出，输出打印到 stdout，适合脚本、批处理、CI。它取代了更早的 --headless 参数。打印模式能读管道：cat error.log | claude -p "解释这个错误"、git log --oneline -50 | claude -p "总结最近的开发活动"；也能把输出接给别的命令：claude -p "列出 todo" | grep URGENT。

两种模式都能续接会话：claude -c 继续最近一次，claude -c -p "检查类型错误" 在打印模式里续接，claude -r "名字" "提示" 恢复指定会话。几个管理子命令也值得知道：claude update（升级）、claude install 版本（装指定版本）、claude auth login / status、claude mcp …、claude plugin …、claude agents（后台会话的 Agent View）、claude purge 路径（删除某项目的全部本地状态，先加 --dry-run 预览）。

一张功能卡。

打印模式claude -p

解决什么问题
把 Claude 当成一个命令行工具，放进脚本、定时任务、CI：读管道输入，返回文本或 JSON，可限轮数、限花费、限工具。
最小可用配置
什么时候不该用
需要来回讨论、边看边改的工作（用交互模式）；没有任何限制就在共享机器或外部触发的 CI 里跑（至少加 --max-turns、--max-budget-usd 和工具限制，外部输入用 --restricted）；靠在提示词里“请输出 JSON”来拿结构化结果（用 --output-format json 和 --json-schema）。

命令拼装器

原文「Core Flags」「Output & Format」「Tool & Permission Management」「Flag Combinations」

打印模式的参数按用途分几组。输出：--output-format text | json | stream-json（流式还可加 --include-partial-messages、--verbose），--json-schema '{…}' 返回经校验的结构化结果。预算：--max-turns N 限制自主轮数，--max-budget-usd 2.00 限制花费（v2.1.217 起到上限时连后台子代理也停）。权限与工具：--permission-mode、--tools、--allowedTools、--disallowedTools。模型：--model、--fallback-model、--effort。其他：--no-session-persistence（不保存会话）、--append-system-prompt、--mcp-config。

原文末尾的“参数组合”表给了几种常用搭配：快速审查 cat 文件 | claude -p "review"；结构化输出 -p --output-format json；安全探索 --permission-mode plan；CI 集成 -p --max-turns 3 --output-format json；限额运行 -p --max-budget-usd 2.00。

输入方式

输出与 jq

原文「JSON API Integration」「jq Parsing Examples」

--output-format json 输出的是一个 JSON 对象，回答文本在 .result；加了 --json-schema 之后，经过校验的结构化对象在 .structured_output。所以 jq 的写法分两种：jq -r '.result' 取文本，jq '.structured_output.issues[]' 取结构化字段。原文的排障建议也是这一条：JSON 格式不对时，用 --json-schema 约束结构、用 --output-format json，不要只在提示词里要求“输出 JSON”。

stream-json 一行一个事件，适合实时处理长报告；配合 --verbose 时，init 事件里还有 mcp_server_errors，能看出哪些 MCP 服务器因配置校验失败被跳过了（第 6 篇）。原文给的脚本模式：把结果存进变量，用 jq -e 判断某个布尔字段，决定脚本走哪条分支。

读命令猜行为

工具限制与三种精简启动

原文「Tool & Permission Management」「Core Flags」「Restricted Mode」

限制工具的三个参数作用不同：--tools 限定有哪些内置工具可用（不在列表里的不存在）；--allowedTools 是不用确认就能执行的工具，支持 "Bash(git log:*)" 这样的前缀写法；--disallowedTools 把工具从上下文里拿掉，如 "Bash(rm:*)"。--dangerously-skip-permissions 跳过所有确认（原文：只在一次性沙箱里用）。

还有三个“精简启动”容易混：--bare 是最小模式，跳过 hooks、skills、plugins、MCP、auto memory、CLAUDE.md，适合快速的一次性查询；--safe-mode（或 CLAUDE_CODE_SAFE_MODE=1）关掉所有自定义，用来排查是你的配置有问题还是 Claude Code 本身有问题；--restricted（v2.1.248+）是给不可信输入用的锁定模式：去掉 Bash、PowerShell、REPL 和 WebFetch（除非 --tools 点名）、忽略用户/项目/本地设置文件（托管设置和显式 --settings 仍生效）、文件工具限制在工作目录内、拒绝 bypassPermissions 和创建云端会话。原文说它比 --permission-mode 更粗：直接拿掉工具而不是询问，会话里无法放宽。

系统提示词与代理

原文「System Prompt Customization」「Agents Configuration」

系统提示词有两类参数：替换 --system-prompt "…" / --system-prompt-file 文件，把默认的系统提示词整个换掉；追加 --append-system-prompt "…"，在默认提示词后面加一段。两类都在交互和打印模式下可用。只想加一条规则（比如“回答都附单元测试”）就用追加，替换会丢掉 Claude Code 默认的软件工程指令。打印模式下还有 --append-subagent-system-prompt（及 -file 版），给每个子代理追加同一段话。

--agents '{…}' 用 JSON 为本次会话定义子代理，每个必须有 description 和 prompt，可选 tools、model；可以 --agents "$(cat ~/.claude/agents.json)" 从文件读。它的优先级高于项目、用户和插件里的同名定义；JSON 无效时直接报错退出（v2.1.243）。--agent 名字 则是让整个会话以某个子代理作为主代理运行。

放进 CI

原文「High-Value Use Cases」「CI/CD Integration」，09「Headless Mode」

原文给了 GitHub Actions 和 Jenkins 的例子：在 PR 触发的流水线里装好 Claude Code，用 ANTHROPIC_API_KEY（存在仓库 secrets 里），跑 claude -p --output-format json --max-turns 3 "审查这个 PR 的……按 JSON 输出" 写进文件，再用下一步把结果发成 PR 评论。如果要把审查当作 PR 的门禁，可以用 claude ultrareview PR号 --json --no-post（v2.1.227+）：干净时退出码 0，有发现时 1，默认 45 分钟超时。

原文还列了几类批处理用法：逐个文件 for f in src/*.ts; do claude -p --model haiku "总结：$(cat $f)" >> summaries.md; done；安全审计 claude --permission-mode plan --tools "Read,Grep,Glob" "审计安全漏洞"；限制命令 --disallowedTools "Bash(rm:*)" "Bash(curl:*)"。对于外部贡献者触发的 CI，原文的 restricted 模式说明里专门举了这个场景。

安装、模型与环境变量

原文「Runtime & Packaging」「Models」「Key Environment Variables」「Troubleshooting」

安装：原文说 npm 安装在官方 README 里已标为弃用，推荐原生安装脚本（curl -fsSL https://claude.ai/install.sh | bash）、Homebrew 或 WinGet；v2.1.113 起 CLI 是按平台分发的原生二进制。公司网络要放行 downloads.claude.ai，否则安装和 claude update 会失败。命令找不到时检查 PATH 里有没有 ~/.local/bin，再跑 claude doctor（只读诊断）或会话里的 /doctor（会提出修复）。

模型用别名最省事：--model opus、sonnet、haiku，opusplan（Opus 规划、Sonnet 执行）；--fallback-model 在主模型过载时自动换（settings 里 fallbackModel 最多配三个）。具体型号、上下文窗口、默认强度原文有一张随版本变化的表，以原文和 /model 为准。常用环境变量：ANTHROPIC_MODEL（固定模型）与 ANTHROPIC_DEFAULT_MODEL（新会话的起始模型，/model 仍可改）、CLAUDE_CODE_EFFORT_LEVEL、MAX_THINKING_TOKENS、CLAUDE_CODE_SUBAGENT_MODEL、MAX_MCP_OUTPUT_TOKENS、CLAUDE_AUTOCOMPACT_PCT_OVERRIDE、DISABLE_AUTOUPDATER。

回扣开头的三个问题

先自己答，再点开
1. 交互模式与 -p 的区别？怎样用管道？

交互模式（claude、claude "提示"）进入 REPL 来回对话；-p 打印模式执行完就退出，输出到 stdout，适合脚本和 CI，取代了旧的 --headless。管道：cat error.log | claude -p "解释"；输出也能接给 grep 等。-c、-r 在两种模式下都能续接会话。

2. 结构化结果用哪两个参数？在哪个字段？

--output-format json 加 --json-schema '{…}'。回答文本在 .result，经过 Schema 校验的结构化对象在 .structured_output，用 jq '.structured_output.字段' 取。不要只在提示词里要求输出 JSON。

3. --tools、--allowedTools、--disallowedTools 区别？--bare、--safe-mode、--restricted 何时用？

--tools 限定有哪些内置工具；--allowedTools 是免确认执行的工具（可写 Bash(git log:*)）；--disallowedTools 把工具从上下文拿掉。--bare 是最小模式，做快速一次性查询；--safe-mode 关掉所有自定义，用于排查配置问题；--restricted 是给不可信输入的锁定模式：去掉执行命令的工具和 WebFetch、忽略用户/项目/本地设置、文件工具限于工作目录、拒绝 bypassPermissions 和云端会话。
