平时只露一行描述，用到才展开

Skill 是一个目录：一份 SKILL.md 写说明，旁边可以放脚本、模板和参考资料。它和 CLAUDE.md 最大的区别是加载方式：启动时 Claude 只知道每个 Skill 叫什么、什么时候该用（约 100 tokens），真正需要时才读正文，正文里提到的文件再用到时才读。这让你可以装很多 Skill 而不把上下文塞满。原教程把自定义斜杠命令也并进了 Skill，所以这一篇其实是“怎么给 Claude 写可复用的说明书”。

本系列是开源教程《Claude How To》（luongnv89 与社区贡献者编写，MIT 协议；本笔记依据 2026 年 10 月 20 日的仓库版本（commit 188f468），原文标注对应 Claude Code v2.1.302）的学习笔记。原教程按十个模块（01-slash-commands 到 10-cli）组织，配了大量可复制的模板。这里重排成十二篇：先用一篇讲清七种扩展机制的分工，再逐个拆开，每个功能按“它解决什么问题、最小可用配置放在哪个路径、什么时候不该用”来写，并配上“读配置猜行为”、模拟器和场景判定题。功能与字段取自原文（主要依据英文原版，中文版是它的缩写译本），每节标出对应的原文目录；为演示设的场景和数值标“示意”。Claude Code 更新很快，原文里带版本号的细节以原文和官方文档为准。

Skill 是什么

原文 03-skills「Overview」「Creating Custom Skills」

原文的定义：Agent Skills 是可复用、基于文件系统的能力，把某个领域的专业知识、工作流程和最佳实践打包成可发现的组件，Claude 在相关时自动使用。和普通提示词相比，提示词是一次性的、对话级的指令；Skill 按需加载，省掉了在每次对话里重复交代同一件事。

Skill 遵循开放标准 Agent Skills（agentskills.io），能在多个 AI 工具间通用；Claude Code 在标准之上加了调用控制、子代理执行、动态上下文注入等扩展。所以有些字段只在 Claude Code 里有效：上传到 claude.ai 或通过 Skills API 创建的 Skill，只认 name、description、license、compatibility、metadata、allowed-tools 这几个字段。

原文把 Skill 的内容分成两类：参考型（规范、模式、风格指南、领域知识，和当前工作一起生效）和任务型（一步步的操作说明，常用 /名字 直接调用）。前者像“背景知识”，后者像“操作手册”。

一张功能卡。

Skill.claude/skills/名字/SKILL.md

解决什么问题
同一套专业知识或多步流程要反复交代；写进 CLAUDE.md 又会每次都占上下文。Skill 平时只露描述，相关时才加载。
最小可用配置
什么时候不该用
一次性任务；和已有功能重复；范围太宽（“文档处理”不如“PDF 表单填写”）；需要隔离上下文、限定工具的专职角色（用 Subagent）；必须执行的检查（用 Hook）；来源不可信的 Skill 不审计就装。

三级加载与描述预算

原文「How Skills Work: Progressive Disclosure」「Automatic Discovery」

原文用“渐进式披露”描述 Skill 的加载：第 1 级 元数据（frontmatter 里的 name 和 description），启动时就加载，每个约 100 tokens；第 2 级 指令（SKILL.md 正文），Skill 被触发时加载，原文给的量级是 5k tokens 以内；第 3 级 资源（附带的脚本、模板、参考文件），需要时才读，脚本通过 bash 执行时内容不必进上下文，所以“实际上没有上限”。

但第 1 级也不是免费的：每个列出来的 Skill 每一轮都带着它的描述。原文给了预算：所有 Skill 描述合计约占上下文窗口的 1%（取不到时按 8,000 字符），单个 Skill 的 description 加 when_to_use 在列表里最多显示 1,536 字符。Skill 装多了，名字都会保留，描述会被缩短——所以关键用途要写在描述的最前面。超预算时 /context 会给警告，/skill-doctor 能看到哪些 Skill 没用上、各花多少上下文。

位置与优先级

原文「Skill Types & Locations」「Automatic Discovery」

Skill 有四种位置：企业（托管设置，全组织）、个人 ~/.claude/skills/名字/SKILL.md（你所有项目）、项目 .claude/skills/名字/SKILL.md（随 git 共享给团队）、插件 <插件>/skills/名字/SKILL.md。同名时企业 > 个人 > 项目，也就是说你个人目录里的同名 Skill 会盖过团队仓库里的。插件 Skill 带 插件名: 前缀，不会冲突。

发现机制有几个细节：在子目录里干活时，Claude Code 会顺带发现嵌套的 .claude/skills/（monorepo 里每个包可以有自己的 Skill）；嵌套目录里和根目录同名的 Skill 两个都加载，/deploy 跑根目录的，/apps/web:deploy 跑嵌套的。--add-dir 加进来的目录里的 Skill 改了立即生效；其他情况改完用 /reload-skills 重新扫描，不必重启。v2.1.133 起，Subagent 也能和主会话一样发现项目、个人、插件 Skill。

判断这几种情况下生效的是哪一个。

谁能调用

原文「Controlling Skill Invocation」「Restricting Claude's Skill Access」「skillOverrides」

默认情况下，你和 Claude 都能调用任何 Skill。两个 frontmatter 字段组合出三种模式：disable-model-invocation: true 时只有你能调用（用 /名字），适合有副作用的 /commit、/deploy、/send-slack-message——原文的原话是“你不会希望 Claude 因为代码看起来准备好了就决定去部署”；user-invocable: false 时只有 Claude 能调用，Skill 从 / 菜单隐藏，适合不构成“动作”的背景知识。

在 Skill 文件之外还有两层控制。权限规则：在 deny 里写 Skill 禁用全部，或用 Skill(commit)、Skill(review-pr *) 放行、Skill(deploy *) 禁止特定 Skill。skillOverrides（v2.1.129+）是按名字设置的“可见性”表，不改优先级：on（默认）、name-only（只列名字）、user-invocable-only（对 Claude 隐藏，菜单里还在）、off（两边都隐藏）；/skills 菜单会帮你写进 .claude/settings.local.json。插件 Skill 不受它影响，用 /plugin 管。

勾一勾两个字段，看谁能调用、适合什么。

字段与字符串替换

原文「Optional Frontmatter Fields」「String Substitutions」「Stacking Skills」

SKILL.md 的 frontmatter 字段全部可选，原文只推荐必写 description（不写时取正文第一行非空内容）。name 默认取目录名，可移植的写法是小写字母、数字、连字符，最长 64 字符。其余字段按用途分几组：调用（disable-model-invocation、user-invocable、argument-hint、arguments、paths：用 glob 限定什么时候自动激活）；工具（allowed-tools 运行期间免确认、disallowed-tools 运行期间拿掉）；模型（model、effort）；执行（context: fork、agent、background、shell）；挂钩（hooks，Skill 被调用时注册、本会话余下时间一直生效）。

正文里可用的替换变量：$ARGUMENTS、$ARGUMENTS[N] 或 $N、${CLAUDE_SESSION_ID}、${CLAUDE_SKILL_DIR}（SKILL.md 所在目录，引用自带脚本时很有用）、${CLAUDE_PROJECT_DIR}、${CLAUDE_EFFORT}（当前强度，可以让 Skill 按强度分支），以及 !`命令` 动态注入。在终端里还能叠加调用：/write-tests /fix-issue 123 会加载开头的全部 Skill（第一个加最多 5 个）并把尾部参数传给每一个；遇到以分叉子代理运行的 Skill（如 /code-review）就停止展开。

在子代理里跑：context: fork

原文「Running Skills in Subagents」「Skill Content Types」

给 Skill 加上 context: fork，Skill 的内容就变成一个专用子代理的任务，在它自己的上下文窗口里执行，主对话保持干净。agent 字段决定用哪类子代理：Explore（只读调研、代码分析）、Plan（出实施计划）、general-purpose（需要全部工具的宽泛任务），或你自定义的 Subagent。从 v2.1.218 起，fork 类 Skill 默认在后台运行，要前台跑就写 background: false。

原文的典型例子是 pr-summary：用 !`gh pr diff`、!`gh pr view --comments` 现取 PR 内容，context: fork + agent: Explore，让一个只读子代理去读、去总结。这样一个大 diff 不会进主对话。一个容易混的点：context: fork 是 Skill 的字段，写在 Subagent 的定义文件里会被静默忽略（第 5 篇）。

写好描述

原文「Best Practices」「Troubleshooting」

Claude 靠 description 决定什么时候激活 Skill，所以原文的最佳实践几乎都围绕描述：具体（“帮忙处理文档”不行，“从 PDF 提取文本和表格、填表、合并文档；处理 PDF 或用户提到表单、文档提取时使用”才行）；聚焦（一个 Skill 一种能力）；包含触发词（用户自然会说的词，如 Excel、spreadsheet、.xlsx）。原文的模板句式是“做什么。在……时使用。”

排障也围绕描述：Claude 不用你的 Skill，就把描述写得更具体、加上触发词，或者先用 /名字 直接调用确认它本身能跑；Skill 触发得太频繁，就把描述写窄，或加 disable-model-invocation: true 改成只能手动调用。正文控制在 500 行以内，详细资料放进 references/ 等子目录，在 SKILL.md 里用相对路径链接过去。

随附 Skill 与安全开关

原文「Bundled Skills」「Security Considerations」

Claude Code 自带一批 Skill，不用安装：/batch（用 git worktree 编排大规模并行修改）、/code-review（找正确性 bug，v2.1.218 起作为后台子代理运行）、/simplify（只清理不找 bug）、/loop（按间隔重复执行）、/debug（读调试日志排查当前会话）、/fewer-permission-prompts、/claude-api（检测到 anthropic SDK 导入时自动激活）、/run 与 /verify（启动应用、实际观察修复是否生效，不只是测试通过）。原文还提到一个约定：如果你的项目或个人 Skill 里有一个叫 verify 的，Claude 会在提交前自动运行它（纯文档、纯测试的提交除外，v2.1.286，以原文为准）。

安全上，原文的态度很明确：只用可信来源的 Skill，把安装 Skill 当作安装软件来对待。恶意 Skill 可以指挥 Claude 调用工具、执行代码；会从外部 URL 拉东西的 Skill 也可能被篡改。两个开关值得知道："disableSkillShellExecution": true 让所有 !`命令` 被替换成“策略禁用”的占位文字，去掉这一层注入面而不禁用 Skill 本身；"disableBundledSkills": true（或 CLAUDE_CODE_DISABLE_BUNDLED_SKILLS=1）对模型隐藏随附 Skill，减少噪声。

回扣开头的三个问题

先自己答，再点开
1. 三级加载各在何时、花多少？装太多会怎样？

第 1 级元数据（name + description）启动即加载，每个约 100 tokens；第 2 级 SKILL.md 正文在触发时加载，5k tokens 以内；第 3 级资源（脚本、模板、参考）用到才读，脚本执行时内容可以不进上下文。所有描述合计预算约为上下文窗口的 1%（缺省 8,000 字符），单个描述加 when_to_use 最多 1,536 字符；装多了描述会被截断，名字保留。用 /context 看警告，/skill-doctor 看哪些没用上。

2. 个人与项目同名谁生效？两个调用字段各控制什么？

企业 > 个人 > 项目，个人的同名 Skill 盖过项目的；插件 Skill 有前缀不冲突。disable-model-invocation: true 让 Claude 不能自动调用，只能你 /名字 调用（适合有副作用的）；user-invocable: false 从 / 菜单隐藏，只给 Claude 自动用（适合背景知识）。skillOverrides 调可见性，不改优先级。

3. context: fork 做了什么？好描述包含哪两部分？

context: fork 让 Skill 的内容成为一个分叉子代理的任务，在独立上下文窗口执行，agent 字段选 Explore、Plan、general-purpose 或自定义子代理；v2.1.218 起默认后台运行。好描述 = 做什么 + 什么时候用（含用户自然会说的触发词），关键用途放最前面。
