先证明是模型的错，再去训练模型

从这一篇进入原书的“调优”篇。模型是 Agent 的决策核心，但工具协议含混、上下文缺失、权限失效、外部服务异常都不该靠训练模型去补。原书第 17 章的主线是：先把问题归到正确的层，再按学习信号选 SFT、Agentic RL 或蒸馏，最后在完整 Agent 里用同一口径验收、灰度、可回滚。章末附了一篇通俗的推理框架导读，解释了为什么输出比输入贵、缓存命中能打一到两折。

先归因：执行环境、Harness 还是模型

原书 17.1.1 节

Agent 的端到端能力由三层共同形成：模型在给定信息和动作空间内理解任务、作出决策；Harness 负责上下文、工具协议、任务状态、路由、反馈、重试与停止；执行环境实际承载动作并返回结果。三者可能表现为相似的失败现象，对应的手段却不同。原书的归因原则：先看模型作出错误决策时是否已经拿到准确充分的信息、是否有清晰可用的动作接口、执行环境是否正常；只有信息、动作空间和反馈都明确稳定，同类决策错误仍跨任务变体反复出现，才有充分理由列为模型优化目标。

原书的例子：数据分析 Agent 反复生成错误 SQL。没给字段含义，改数据字典检索；工具对时间范围的描述有歧义，改工具协议；查询服务不可用，修环境；字段、口径、执行反馈都清楚，模型仍在不同任务中混淆去重或关联逻辑，才评估模型优化。排查顺序是先排除能独立复现的环境故障，再看 Harness，最后判断模型。边界不清时做四组对照：原模型 × 原 Harness、原模型 × 候选 Harness、候选模型 × 原 Harness、候选模型 × 候选 Harness，在一致任务集和预算下分出各自的贡献和交互项。模型优化也可以由成本驱动：高频任务已经靠长提示、反复纠错或多模型复核完成，但开销超预算，任务分布稳定、有效行为可学习时，可以评估 SFT 或蒸馏。

能力要求、优化目标与方法选择

原书 17.1.2–17.1.4 节

归给模型之后，再细分是哪类决策能力不足。原书分四类：任务理解与约束识别（把“比较两个季度的客户增长”转成客户口径、时间范围、去重规则，必要条件不明时澄清）、工具使用与反馈理解（调用成功只说明接口完成了请求，还要判断结果是否完整、口径是否一致）、多步决策与状态利用（τ²-Bench 把用户和 Agent 都能操作共享环境的情形纳入评估）、失败恢复与合理终止。这些是模型的决策表现；工具执行、状态持久化、权限校验和动作放行仍属于 Harness 与执行环境。

目标要落到三个维度：质量（关键动作、业务口径、约束，最终回到完整任务）、可靠性（多次运行、输入变化、长交互、工具异常，权限或边界违规单独报告）、成本（单位成功任务成本：统计期内全部任务成本 ÷ 成功任务数，失败任务也计入分子；固定任务构成并同时报告成功率，防止靠放弃难题“降成本”）。效率驱动不意味着训练必然省钱：只有减少提示长度、重试与复核次数，或让更小的模型胜任时才可能；低频或多变的任务，轻量 Harness 调整往往更经济。指标之外还要安全护栏：模型负责识别约束、提出动作，但不能只靠模型自己遵守。

方法按学习信号选：有明确示范 → SFT；需要交互探索且环境能提供可靠反馈 → Agentic RL；教师已经会、目标是迁移、压缩或部署 → 蒸馏。三者不互斥：输出或轨迹蒸馏通常就是在教师数据上做 SFT，SFT 后的模型也可以继续做 RL。

回答三个问题，看该选哪种方法。

SFT：让验证过的行为更稳定地出现

原书 17.2 节

面向 Agent 的 SFT，监督的不只是最终答案，还有执行中的关键决策：要不要调工具、选哪个、参数怎么填、反馈怎么解释、何时继续、澄清、求助或终止。它改变的是模型的条件行为分布，不替代 Harness 的状态维护和权限控制，也不靠探索发现未知的最优策略。原书例子：比较两个季度的新增付费企业客户，口径已经明确，模型仍可能先筛季度内订单再算首次付费时间，把老客户算成新增；SFT 的目标不是背下某条 SQL，而是通过多样化示范学会“先在全量有效付费记录上确定首次付费时间，再按季度统计”。适用前提：同一状态下有稳定、可核验的正确行为；路径优劣只能通过交互判断时，考虑 RL。

轨迹不等于监督目标。构造样本的铁律：每个目标行为只能依赖该决策时刻已经可见的信息，工具还没返回，目标动作就不能用它的结果；用户后来补充的条件，不能提前进入早期决策的输入，否则离线训练的信息条件优于线上，上线就复现不了。样本要覆盖直接回答、发起调用、请求澄清等不同选择，避免模型养成“遇到任务就调工具”的习惯。任务成功也不代表每一步都值得模仿：纠错场景里可以把错误动作留在上下文中、但屏蔽它的损失，只监督验证过的后续恢复行为。配比上保留原本可以直接完成的简单任务，防止训练后普遍增加工具调用；训练与推理的对话模板、工具调用格式、结束标记要兼容。

验收不能看训练损失：损失下降只说明模型更容易生成样本里的内容。要让候选模型在固定的 Harness、工具接口和预算下自主运行，由环境返回真实反馈，观察早期决策如何影响后续；如果每一步都喂标准历史、只检查下一条续写，就暴露不了错误累积。测试集按任务族、模板、数据来源分组，避免近似改写同时进入训练和测试。

Agentic RL：用环境反馈优化策略

原书 17.3 节

Agentic RL 用模型在环境中执行任务的轨迹作为样本，依据结果、过程状态或验证器反馈更新策略。和 SFT 的区别在信号来源：SFT 要求行为能被可靠示范，RL 允许多条可行路径，但要求路径优劣能被稳定评价。准入要同时满足：失败来自模型的动作选择或恢复策略；有效路径不唯一、难以逐步标注；结果或关键中间状态可由规则、测试或可靠评审判断；环境可执行、可重置、可复现、可审计、可隔离；模型已能产生一定比例的有效轨迹（连工具参数格式都不稳就先 SFT）；收益能覆盖 Rollout 和环境维护成本。原书强调，“结果可验证”比“过程能完整标注”更重要。

奖励可以写成 R(τ) = w₁R_task + w₂R_process − λC_execution − μP_violation：结果奖励是核心；过程奖励只奖励可客观判断的关键状态，不规定唯一流程；成本在成功前提下优化，不能诱导提前终止；高风险约束不能只靠负奖励，必须由 Harness 设置不可绕过的控制。主要风险是奖励投机（找评分漏洞而不是完成任务）、代理目标偏移、评审器漂移。原书的典型反例：退款验证器只检查“是否生成退款记录”，模型就可能学会更快地创建不合规退款。所以要把训练奖励、独立评测、系统约束分开：奖励提供学习信号，独立评测判断能力是否真提升，系统控制保证任何版本都越不过边界。

训练循环是任务采样 → Rollout → Verifier 评分 → 信用分配（Advantage）→ 策略更新 → 版本注册。PPO 用价值模型估计优势并裁剪策略变化；组相对方法对同一任务采多条轨迹、用组内相对回报当基线，省掉价值模型，但如果组内结果几乎一样，优势会趋近于零。长程任务的难点是反馈更晚、早期错误改变后续状态：用课程式采样、只在可验证的阶段性状态给过程反馈、同任务多轨迹比较，并显式覆盖参数修正、工具切换、请求澄清、合理终止。最后用独立评测确认真实收益：开发集设计奖励、验证集选版本、锁定留出集只在冻结后验收一次，长期用同一留出集挑版本也会间接过拟合；训练回报涨而独立成功率没涨，先查奖励、验证器偏差、环境泄漏答案和分布差异。

蒸馏：迁移能力，算清单位成功任务成本

原书 17.4 节

蒸馏不是让小模型“说得像”强模型，而是把强模型在任务执行中的有效决策迁移过去，让它以更低成本独立承担可界定、可评测的工作，并在超出能力边界时交还教师。设计从线上职责出发：教师在目标任务上要稳定可靠（不稳定的教师只会被更高效地复制错误），学生要在质量、时延、显存、吞吐和单价间平衡。可以先建“任务—职责—风险”矩阵，分成学生独立执行、学生执行教师校验、教师直接执行三类；首次落地更适合技能级迁移（工具路由、查询生成、参数抽取、结果核验）而不是完整 Agent 行为迁移。

教师信号从粗到细：最终输出、标签与理由、结构化动作、多轮轨迹、概率信号。黑盒（序列级）只要教师生成的文本或轨迹，跨厂商跨词表都能用，DeepSeek-R1 的蒸馏阶段和 Qwen3 的长思维链冷启动都是这条路；白盒（分布级）要 logits 或 log-prob，监督更稠密，通常要求共享 tokenizer。离线示范的问题是学生一旦走出不同动作，就进入教师从没示范过的状态，误差累积；在线策略蒸馏（OPD）让学生先在环境里生成，再由教师对学生实际到达的状态逐 token 打分，最小化反向 KL，有“模式寻求”倾向，能收敛到一条连贯路径，但也可能复制教师偏差、压低探索，要和任务成功验证一起用。补强时定位学生相对有效路径的首个关键偏离，分知识、决策、执行、恢复四类缺口补数据。

收益核算是本节的重点：单位成功任务成本 = 全部任务所有尝试的（学生 + 教师兜底 + 验证器 + 工具 + 运行时）成本 ÷ 成功任务数，重试通过对每次尝试求和已经计入。“单次推理成本 × 平均重试 ÷ 成功率”只是极简近似。再加上一次性投入 F（数据、训练、评测、部署、迁移），成功率不同时先算单任务净收益 g = pV − (1−p)L − C̄，盈亏平衡任务量 N* = F / (g_new − g_old)；若新方案的 g 不更高，就没有有限的盈亏平衡点。保留一部分教师兜底不是蒸馏失败，而是目标架构的一部分（级联路由）；蒸馏出的小模型还可以当投机解码的草稿模型。

验收与上线：在完整 Agent 里证明收益

原书 17.5 节

训练完成不等于可以上线。如果候选模型同时用了新的 Prompt、更宽松的工具权限或更简单的环境，成功率提高了也说不清收益来自哪里。所以先冻结一个候选发布单元：模型配置（检查点、训练方法与数据、超参、模板、tokenizer、推理参数）、Harness 配置（Prompt、Skill、上下文策略、工具 Schema、路由、重试、停止、权限、人工介入）、执行环境配置、评测配置（任务集、种子、预算、验证器、重复次数、口径、阈值）。至少保留纯模型对照（同 Harness 同环境）和部署组合对照（适配后的 Harness 对比当前生产）。候选模型只有靠大幅扩写 Prompt、额外重试或放宽权限才更高分，这些要作为成本和风险单独报告。

系统适配检查工具协议、上下文、执行行为、预算、安全边界五方面兼容，顺序是固定输入 → 标准历史前缀单步 → Sandbox 中自主运行完整任务 → 故障注入。准入用“硬门槛 + 目标收益”而不是一个加权总分：接口兼容、目标收益（预先设定的最小改善和置信区间）、能力回归（非劣效界值）、运行预算、安全硬门禁，任一硬门禁失败就阻断；所有门槛在查看候选结果之前确定。安全门禁还要区分两件事：模型提出违规动作的频率（策略风险），违规动作穿透系统被实际执行的频率（防护有效性）。

灰度依次是影子验证（多步写操作要在隔离副本重放，或只比较候选动作不执行）、低风险灰度、分阶段扩量（高风险写操作晚于只读任务开放）、稳定替换后保留旧版本一个完整业务周期；每一档预设扩大、暂停、回滚条件，按用户、会话或任务分桶，避免同一长任务在新旧模型间切换。回滚对象是完整的候选发布单元，只回退模型权重可能形成不兼容组合；回滚也撤销不了已经在外部系统完成的写操作。上线后的问题重新按三层归因，只有稳定复现、影响明确、可验证的问题才进入下一轮。

推理框架：为什么输出更贵、缓存更便宜

原书 17 章附《深入浅出推理框架》

推理框架把训练好的模型加载到硬件上，接收请求、组织计算、返回结果。“好”有五个方面，而且相互牵制：快（首字和生成速度）、多（同样硬件服务更多请求）、省（显存与算力用足，算过的不重复算）、稳（高峰、超长请求、硬件故障下仍可用）、准（输出与模型本来能力一致、格式正确、需要时可复现）。它不只在上线时出现：RL 训练里最耗时的“生成”一步、评测和合成数据，也都靠推理引擎。训练是一次性投入，推理是持续支出：训练决定能力上限，推理决定这份能力每用一次花多少钱。

几个概念：Prefill 是“读题”，所有输入 token 并行计算，吃算力；Decode 是“作答”，一次一个 token，每生成一个都要把权重从显存读一遍，吃带宽，所以输出更贵。连续批处理以每一步为单位调度，写完的请求随时下车、新请求随时上车。KV Cache 是模型的草稿纸，大小与上下文长度和并发成正比，往往是显存里最紧张的资源：“能不能部署看权重的账，能服务多少人看 KV Cache 的账”。TTFT、TBT（TPOT）、吞吐此消彼长，目标是在可接受的延迟内把有效吞吐（Goodput）推到最高。MoE 让每个 token 只激活一部分参数，但所有专家都要常驻显存，跨卡通信和负载均衡成了新问题。

智能体的推理负载有三个特点：输入很长、输出相对短、前后请求高度重复；一次任务调用模型十几到几十次，端到端耗时是每步之和。所以在智能体场景，比拼的不只是算得快，还有少算：前缀缓存复用已算过的 KV Cache，厂商通常对命中部分的输入打一到两折。原书给了一条很实用的经验：把固定不变的系统提示词和工具定义放在最前面，新增内容追加在末尾；如果在系统提示词开头插入当前时间这类每次都变的信息，后面所有内容的缓存都会失效。“在智能体场景里，缓存命中率就是成本。”集群层面还有 PD 分离（Prefill 和 Decode 用不同机器）、感知前缀缓存的路由、多级 KV 缓存池；采样环节有确定性推理、结构化输出（每步只允许语法合法的 token）和投机解码。

回扣开头的三个问题

先自己答，再点开
1. 何时归因于模型？三种方法怎么选？

先排除能独立复现的执行环境故障，再确认 Harness 已提供充分信息、清晰动作接口和完整反馈；在这些条件明确稳定时，同类决策错误仍跨任务变体反复出现，或固定 Harness 换模型后显著变化，才归因于模型；边界不清就做四组对照。有可靠示范选 SFT；路径多样、需要交互探索且结果可稳定验证选 Agentic RL；教师已会、目标是迁移压缩部署选蒸馏；三者可组合。

2. 奖励为什么会被投机？训练奖励为何不能当发布依据？

策略会最大化“评分规则”而不是“真实目标”：验证器只查是否生成退款记录，模型就会学会更快创建不合规退款。训练奖励上升只说明更会拿当前奖励；发布要看冻结后在锁定留出集上的独立评测（质量、可靠性、成本、安全），训练验证器与独立评测器尽量分离，再做消融解释收益来源，并用分阶段灰度验证真实流量。

3. 单位成功任务成本怎么算？为何缓存命中率就是成本？

全部任务所有尝试的学生、教师兜底、验证器、工具、运行时成本之和 ÷ 成功任务数，失败和重试都计入；有一次性投入时，用单任务净收益 g = pV − (1−p)L − C̄ 算盈亏平衡 N* = F/(g_new − g_old)。智能体每步都要重发系统提示词、工具定义和历史，输入长、前后高度重复；命中前缀缓存的部分跳过 Prefill，价格通常一到两折，所以 Prompt 要固定内容在前、新增在后，避免在开头放每次都变的信息。
