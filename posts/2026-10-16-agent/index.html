一个公式，三种说法

原书引言 · 第一章

原书的核心公式只有一句：Agent = LLM + 上下文 + 工具。直觉的说法是大脑、眼睛、手脚；强化学习的说法是策略、观察空间、动作空间。三种说法描述的是同一个对象，只是抽象层次不同。公式只描述 Agent 边界以内的东西，与它交互的环境（文件、网页、用户、其他 Agent、物理世界）在边界之外。

生产形态下，原书把它展开为 Agent = Model + Harness：Harness 是“Agent 边界内、模型之外”的运行与治理层，包括上下文管理、工具接口，以及约束、验证、纠正三层保障。原书认为，模型能力越接近，竞争优势就越转移到 Harness 上。

点公式里的三个部件，看它们分别在哪几篇展开。

贯穿全书的五个设计模式

原书 1.3 节

原书在第一章一次性命名了五个模式，后面九章反复出现。读任何一篇时都可以问一句：这里用的是哪个模式？

提议者—审核者产出与评判由不共享上下文的两个角色承担，评判方只看产物和独立证据。前提是自审不可靠。第 3、4、5、7、9、10 篇都会出现。
渐进式披露先给可检索的目录，再按需加载细节：Skills、分层检索、主动工具发现。
只增不改状态只追加不回改，换来可缓存、可重放、可审计：KV Cache 前缀、事件式记忆、原始证据层。
边界集 + 保留集修改要同时在“该变的样本”和“不该受影响的样本”上验证：回归任务、训练评估隔离、更新提案验证。
最小 diff + 可回滚每次修改小、带来源、能单独回滚，让归因成为可能：知识更新 PR、代码补丁、Prompt 更新。
