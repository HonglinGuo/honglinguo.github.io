动手拆一个大语言模型 · 01约 10 分钟5 个小实验

说到底，它只是在猜下一个词

聊天机器人看起来什么都会，但拆开看，核心程序只做一件事：读一段前文，给出“下一块文字”的概率表。这一篇用五个小实验，把这件事拆开摸一遍。

本系列受《三万字长文：大语言模型从零入门》（腾讯技术工程公众号，作者 flyflywang）启发。原文是一篇系统扎实的长文，推荐对照阅读；这里不复述原文，而是把其中的概念换成能动手试的小实验。

切块概率表接龙当裁判填空

模型读的不是字，是“块”

token

我们说“模型在猜下一个字”，其实不太准确。模型处理文字之前，要先按一张固定的词表把句子切成一块块，每块叫一个 token，再换成整数编号。一个 token 可能是单个字，也可能是一个常用词，英文里还常常是半个单词。

为什么不干脆一个字一块？一是省步数：模型每生成一个 token 都要从头到尾完整算一遍，块越大，同样一句话要算的次数越少。二是常一起出现的字本来就该当作整体，“今天”“天气”这类搭配，合并以后模型就不必每次重新去猜“今”后面跟“天”。

所以后面说的“下一个词”，严格讲都是“下一个 token”。这也埋下了一个伏笔：模型看到的是块，不是字母。

下面是一个只有几十项词表的玩具分词器。改改句子，或者切到“一个字一块”，对比要走的步数。

概念

token
模型读写文字的最小单位，可能是一个字、一个词，也可能是一个词的一部分。
词表 vocabulary
所有 token 的固定清单，每个 token 对应一个整数编号；大模型的词表通常有 5 万到 25 万项。
分词 tokenization
按词表把一段文字切成 token 序列、再换成编号的过程。
BPE
一种常用的建词表方法：从单个字符出发，反复把语料里最常相邻出现的一对合并成新 token。

要点

生成一个 token = 整个模型完整算一遍
所以 token 越少，生成越快、越省钱。
常见词并成一块，生僻词拆成碎片
同样一句话，在不同模型里的 token 数可能不同。
模型看不到 token 内部的字母
这是它数字母、做逐位运算容易出错的根源。

有的空只有一个答案，有的空有一百个

概率分布

把一句话停在半截，问“下一个是什么”，人心里其实会浮出好几个候选，只是把握大小不同。语言模型做的就是把这种“把握”明确地写成数字：给词表里每个 token 一个概率，全部加起来等于 1。

这张概率表就是语言模型的全部输出。有的空几乎只有一个答案，比如“一年有十二个”后面；有的空可以接几百种说法，比如“周五晚上想去”。表是“尖”还是“平”，取决于前文给了多少约束。

这些数字不是谁规定的，而是模型从海量人写的文本里统计、学习出来的“人在这里通常接什么”。

点三个不同的开头，看概率表的形状怎么变；留意“凑够 90% 需要几个候选”。

一段话，是一块一块接出来的

自回归生成

模型每次只吐一个 token，那一整段回答是怎么来的？办法朴素得出奇：从概率表里选一个 token 接到前文末尾，把加长后的整段再交给模型，算出下一张表，如此循环，直到选中一个表示“结束”的特殊 token。

这种“自己的输出变成下一步的输入”的方式叫自回归生成。它有一个重要后果：写出去的字收不回来。前面一旦选了一个不太好的词，后面只能顺着它往下圆，模型并不会回头改。

聊天框里逐字蹦出来的效果，正是这个循环在一步步跑。

下面是一个手写的小模型，你来替它做选择：点候选词，或者让它按概率抽，多跑几次看看同一个开头能长出多少种句子。

多试几次“按概率抽”：同一个开头会长出不同的句子。偶尔抽到 1% 的“冰淇淋”，后面每一步都只能顺着它往下编，已经写出的字不会被撤回。

概念

自回归生成
每次只生成一个 token，接到前文末尾，再把整段当作新输入继续预测。
结束标记
词表里一个特殊 token，模型选中它就表示这段话写完了。
上下文
模型当前能看到的全部文本，包括提示词和它已经写出的内容。
提示词 prompt
用户或系统给出的开头文字，是生成循环的第一段前文。

公式与要点

前文 → 概率表 → 挑一个 → 接上 → 重复
聊天回复就是这个循环跑几百次。
写出的 token 不会撤回
一步走偏，后面只能顺着它往下写。
停止条件
选中结束标记，或达到预设的最大长度。

猜得和人一模一样，裁判就分不出来

模仿游戏

“预测下一个词”听上去像高级输入法，它凭什么和“智能”扯上关系？答案要回到 1950 年。图灵觉得“机器能不能思考”太难定义，于是换了个能操作的问法：让裁判隔着屏幕只通过文字和人、机器分别聊天，如果反复测试也分不出谁是机器，就可以认为机器表现出了人的智能。

注意裁判只看得到文字。对语言模型来说，这等于问：它给出的概率表，和人写作时的概率表有多接近。如果两张表完全一样，它一个 token 一个 token 写出来的东西就和人写的没有区别。

所以把“预测下一个 token”做到极致，就是在逼近图灵测试的标准。

拖动滑块让模型“学得更好”，看最聪明的裁判命中率怎么降向 50%，再亲自当几回裁判。

裁判的最佳策略是：看到的词在哪边概率更高，就判给哪边。两张表重合得越多，这个策略越接近抛硬币。看的句子越多，差异会累积，所以真正的测试会聊很久。

概念

图灵测试
只通过文字交流，如果裁判反复测试也分不清哪个是机器，就认为机器表现出了人的智能。
行为标准
只看输出像不像人，不问内部怎么实现。
分布接近
模型的概率表与人写作时的概率表越接近，写出的文字越难与人区分。
模仿游戏
图灵 1950 年提出的原始说法：裁判通过打字与看不见的人和机器对话。

公式与要点

最佳裁判只看一个词的命中率 = ½ + ½·TV(p, q)
TV 是两张概率表的“总变差距离”，重合越多越接近 50%。
看的文字越多，差异越会累积
所以测试需要长时间对话。
“分不出”不等于“真理解”
机器是否理解，至今仍有争论。

想把空填对，光背搭配不够

预测逼出理解

光会背字词搭配，能把下一个词猜准吗？不能。人写下的句子里装着各种东西：要填出某国首都，得有知识；要从几句比较里得出谁最矮，得会推理；要知道手机进水后先关机，得懂常识；要读懂一句话里的情绪，得明白人。

想在所有这些位置上都猜得准，模型就被迫把这些东西也一并学进去。“预测下一个词”这个看似简单的目标，实际上是一个包罗万象的考试，知识、逻辑、常识和情感都在题里。

当然，“猜得准”是否等于真正“理解”，至今仍有争论；但它给了我们一个清晰、可以打分的目标。

下面四道填空，每道都会告诉你它考的是哪种能力。

    • 所以“把下一个词猜准”这个看似朴素的目标，是一条通往知识和推理的路，这也是这类模型能力的起点。
    • 它到底算不算真的“理解”，学界还在争论；但“猜得多准”可以被精确打分，下一篇就讲怎么打分。
