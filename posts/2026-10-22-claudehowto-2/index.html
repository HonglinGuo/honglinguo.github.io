一个 / 后面，有四种来源

在 Claude Code 里敲一个斜杠，弹出来的列表其实混着四种东西：Claude Code 自带的内置命令、你写的 Skill（以前叫自定义命令）、插件带来的命令、MCP 服务器暴露的 prompt。它们长得一样，背后的机制完全不同。这一篇先把内置命令按用途整理成一张能查的表，再讲怎么写自己的命令，以及参数、动态上下文和文件引用到底是怎么展开的。

本系列是开源教程《Claude How To》（luongnv89 与社区贡献者编写，MIT 协议；本笔记依据 2026 年 10 月 20 日的仓库版本（commit 188f468），原文标注对应 Claude Code v2.1.302）的学习笔记。原教程按十个模块（01-slash-commands 到 10-cli）组织，配了大量可复制的模板。这里重排成十二篇：先用一篇讲清七种扩展机制的分工，再逐个拆开，每个功能按“它解决什么问题、最小可用配置放在哪个路径、什么时候不该用”来写，并配上“读配置猜行为”、模拟器和场景判定题。功能与字段取自原文（主要依据英文原版，中文版是它的缩写译本），每节标出对应的原文目录；为演示设的场景和数值标“示意”。Claude Code 更新很快，原文里带版本号的细节以原文和官方文档为准。

四种来源

原文 01-slash-commands「Overview」「Command Architecture」

原文给斜杠命令下的定义是：在交互会话中控制 Claude 行为的快捷方式。按来源分四类：内置命令（/help、/clear、/model，Claude Code 自带）；Skills（你写的 SKILL.md，如 /optimize、/pr）；插件命令（/插件名:命令名）；MCP prompt（/mcp__服务器__prompt名）。

原文用一张流程图说明敲下命令以后发生什么：内置的直接执行；Skill 要先读 SKILL.md、解析 frontmatter、替换变量、执行其中的 shell 片段，再把结果作为提示词交给 Claude；插件命令加载插件里的定义；MCP 的则去执行服务器提供的 prompt。所以“内置命令”是程序功能，而其余三种本质上都是生成一段提示词。

一个容易踩的细节：从 v2.1.236 起，敲错的命令或当前会话不可用的命令按回车会报错，不再悄悄执行最接近的那个；无歧义的前缀和定义好的别名仍然可以用（以原文为准）。

四类命令各自从哪来、谁执行，点开看。

内置命令速查

原文「Built-in Commands Reference」「Bundled Skills」

原文列了六十多个内置命令和约二十个随附 Skill（随附 Skill 像命令一样用 / 调用，但实现上是 Skill，比如 /code-review、/loop、/batch）。在 Claude Code 里敲 / 能看到完整列表，敲 / 加几个字母可以过滤。

平时真正高频的其实不多。我按用途重新分了组，挑了原文表里对日常写代码最有用的条目；每条的说明是我对原文的转述。几个值得专门记住的：/cd 换工作目录不会打掉 prompt cache（以前换目录会让下一轮变慢变贵）；/context 用彩色网格看上下文占用；/goal 注册一个会话级的完成条件，Claude 会跨多轮一直做到满足为止；/fewer-permission-prompts 分析你最近的 Bash 和 MCP 调用，生成一份允许清单写进 .claude/settings.json。

按分组看，或者直接搜关键词（比如“上下文”“review”“权限”）。

据原文 v2.1.302 版本的命令表转述，命令的增删很频繁，以原文和 /help 为准。已移除：/pr-comments（直接让 Claude 看 PR 评论）、/vim（改到 /config 的 Editor mode）、/ultraplan（改用 plan mode）；/agents 的创建向导已移除，改为让 Claude 创建或直接编辑 .claude/agents/。

易混辨析：/code-review、/review、/simplify、/security-review

/code-review 找正确性 bug（随附 Skill），可带强度 low…max、ultra（云端多代理深度审查），--fix 直接改，--comment 发成 PR 行内评论。/review 现在是它的完整别名。

/simplify 只做清理（复用、简化、效率、抽象层次）并直接应用修改，不找 bug。/security-review 专门分析分支的安全漏洞。

分叉与旁问：/branch、/fork、/subtask、/btw

原文 01「Recent Changes」、09-advanced-features「Forking and Branching Sessions」

这四个命令最容易混，因为它们都在“不打乱当前对话”的前提下做点别的事。原文的区分方式是看副本在哪里跑、结果回不回来：/branch [名字] 是你自己切进一个从当前点复制出来的对话，原对话保留，之后用 /resume 回去；/fork [提示] 把对话复制成一个独立的后台会话去跑，从此两边各走各的，结果不回来；/subtask <任务> 起一个继承完整对话的分叉子代理，你继续干活，它干完把结果交回当前对话；/btw [问题] 是一个临时的旁问，问完不污染主对话上下文。

原文专门提醒：/fork 和 /subtask 在 v2.1.212 互换了角色。在那之前有一段时间 /fork 起的是分叉子代理（也就是现在 /subtask 的行为），更早它又只是 /branch 的别名。网上的老教程很可能说的是旧行为。

四个场景，各该用哪一个？

命令副本在哪跑你在哪结果回到当前对话？
/branch当前终端（你切进去）副本里不需要，原对话用 /resume 找回
/fork新的后台会话（在 claude agents 里有一行）原对话不回来，各自独立
/subtask分叉子代理（继承完整对话）原对话回来，完成后交回结果
/btw一次性旁问原对话不写进主对话上下文

写自己的命令：现在就是写 Skill

原文「Custom Commands (Now Skills)」「Frontmatter Reference」

原文最重要的一条更新是：自定义斜杠命令已经并入 Skills。老位置 .claude/commands/名字.md 继续有效、不用改；新写的推荐放 .claude/skills/名字/SKILL.md。两者都生成 /名字，如果同名，Skill 优先。迁移只需要把文件挪进同名目录、改名为 SKILL.md。

为什么推荐 Skill 形式？原文列了五点：能带目录（脚本、模板、参考文件）；Claude 可以在相关时自动调用；能控制谁可以调用；能用 context: fork 在隔离的子代理里跑；能渐进式加载附带文件。也就是说，命令只是 Skill 的一个子集：一个“只允许你手动调用”的 Skill，就是传统意义上的命令。

下面是一张功能卡，以及 frontmatter 里和“命令”相关的字段。

展开模拟：参数、shell 片段与文件引用

原文「Arguments」「Dynamic Context with Shell Commands」「File References」

命令文件里有三种会被提前替换的东西。$ARGUMENTS 是调用时跟在命令后面的全部参数，$0、$1… 是按空格切开的第几个参数（从 0 开始）。!`命令` 会在提示词发给 Claude 之前先在本机执行，把输出原样塞进去，Claude 只看到结果；所以原文的 /commit 示例里，git status、git diff HEAD、当前分支和最近五次提交都是现取的。@路径 把文件内容引进来。

两个和安全相关的细节：shell 片段要能执行，相应的工具得在 allowed-tools 里放行（比如 Bash(git *)）；从 v2.1.299 起，UserPromptSubmit 类型的 Hook 在命令展开之前运行，所以 Hook 拦下这条提示词时，里面的 ! 片段也不会执行。另外 ${CLAUDE_PROJECT_DIR} 会被替换成项目根目录的绝对路径。

插件命令与 MCP 命令
原文「Plugin Commands」「MCP Prompts as Commands」「MCP Permission Syntax」

  

    
插件带来的命令写作 /插件名:命令名，没有命名冲突时可以直接写 /命令名；从 v2.1.136 起也可以用空格代替冒号（/myplugin review），脚本里推荐冒号形式。MCP 服务器可以把它的 prompt 暴露成命令，格式固定为 /mcp__服务器名__prompt名 [参数]，比如 /mcp__github__list_prs。

    
MCP 的权限规则写法和命令名同一套前缀：mcp__github 是整个服务器，mcp__github__* 是它的全部工具，mcp__github__get_issue 是单个工具。v2.1.299 之后一条规则只匹配它点名的那个服务器，mcp__github 不会再顺带匹配名叫 github__x 的服务器（以原文为准）。

回扣开头的三个问题
先自己答，再点开

  

    
1. 斜杠命令的四种来源？自定义命令放哪，同名谁生效？
内置命令、Skills（自定义命令）、插件命令（/插件名:命令名）、MCP prompt（/mcp__服务器__prompt）。自定义命令推荐放 .claude/skills/名字/SKILL.md，旧位置 .claude/commands/名字.md 仍可用；同名时 Skill 优先。

    
2. /branch、/fork、/subtask、/btw 的区别？
/branch：你切进当前对话的副本，原对话保留，用 /resume 回去。/fork：把对话复制成独立的后台会话，各走各的，结果不回来。/subtask：起一个继承完整对话的分叉子代理，你继续干活，它完成后把结果交回当前对话。/btw：临时旁问，不污染主对话上下文。/fork 与 /subtask 在 v2.1.212 互换过角色。

    
3. $ARGUMENTS、$0、!`命令`、@文件 何时由谁展开？
都在提示词发给 Claude 之前由 Claude Code 展开：$ARGUMENTS 是全部参数，$0/$1 是按位置的单个参数（从 0 开始）；!`命令` 在本机先执行，输出原样插入（需要 allowed-tools 放行对应工具，且 UserPromptSubmit Hook 先于展开运行，拦下提示词时片段不执行）；@路径 引入文件内容。Claude 只看到展开后的结果。
