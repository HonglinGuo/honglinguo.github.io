敢让它大改，是因为能退回去

原教程把 Checkpoints 排在学习路线的第三位，理由很实在：有了随时可退的快照，你才敢让 Claude 去试一个激进的重构。Claude Code 在你每次提交提示词时自动打一个快照，按两下 Esc 或敲 /rewind 就能选择回到哪一步、恢复代码还是对话。但它有清楚的边界：Bash 命令造成的文件变化、你在编辑器里的修改、子代理改的文件，都不在快照里。这一篇用模拟器把六个回退选项和这些边界走一遍，再讲会话怎么继续、恢复和分叉。

本系列是开源教程《Claude How To》（luongnv89 与社区贡献者编写，MIT 协议；本笔记依据 2026 年 10 月 20 日的仓库版本（commit 188f468），原文标注对应 Claude Code v2.1.302）的学习笔记。原教程按十个模块（01-slash-commands 到 10-cli）组织，配了大量可复制的模板。这里重排成十二篇：先用一篇讲清七种扩展机制的分工，再逐个拆开，每个功能按“它解决什么问题、最小可用配置放在哪个路径、什么时候不该用”来写，并配上“读配置猜行为”、模拟器和场景判定题。功能与字段取自原文（主要依据英文原版，中文版是它的缩写译本），每节标出对应的原文目录；为演示设的场景和数值标“示意”。Claude Code 更新很快，原文里带版本号的细节以原文和官方文档为准。

它解决什么

原文 08-checkpoints「Overview」「Accessing Checkpoints」「Automatic Checkpoints」

Checkpoint 是会话状态的快照，原文列的内容包括：交换过的消息、做过的文件修改、工具使用记录、会话上下文。它是自动的：你每提交一次提示词就创建一个，随会话保存，所以恢复会话以后 /rewind 依然可用；默认 30 天后自动清理。打开方式两种：连按两下 Esc，或者 /rewind（别名 /checkpoint、/undo），会列出所有快照，每个显示时间、改了哪些文件、消息数、用过的工具。

原文给的典型用法有四种：探索不同方案（做完方案 A，退回起点再做方案 B，比较）、安全重构（重构、跑测试，挂了就退）、A/B 设计对比、从错误中恢复（发现改坏了，退到最后一个好的状态）。v2.1.191 起 /clear 也不再是硬边界，可以回退到 clear 之前的快照。

六个回退选项

原文「Rewind Options」

选中一个快照后有六个选项。前三个是“恢复”：恢复代码和对话（文件和消息都回到那一刻）、恢复对话（只退消息，代码保持现状）、恢复代码（只退文件，完整对话保留）。后两个是“总结”，不改动磁盘上的任何文件，原始消息仍保留在会话记录里：从此处总结把选中点之后的对话压成一段 AI 摘要（之前的保持原样，可以附带“重点总结什么”的指令）；总结到此处反过来，把选中点之前的压成摘要，之后的保持原样。最后一个是算了。

两个“总结”合起来就是双向、有针对性的压缩：比 /compact 一把压全部更精细。还有个交互细节：恢复对话或“从此处总结”之后，选中那条消息的原始提示词会放回输入框，方便你改一改再发；“总结到此处”则留在对话末尾、输入框为空。

        易混辨析：/rewind、/compact、/clear 与两个“总结”

        /rewind 恢复类：真的回到过去，可以撤销文件改动。/compact：把整个对话压成摘要，不动文件，可以附带重点指令。/clear：清空对话重新开始，不动文件（v2.1.191 起还能回退到 clear 之前）。

        从此处总结 / 总结到此处：只压选中点之后或之前的那一段，另一段原样保留，不动文件，原始消息仍在会话记录里。想精细地腾出上下文，用它们；想撤销代码，用恢复类。

        边界与 git

        原文「Limitations」「Integration with Git」

        checkpoint 追踪的是 Claude 用文件编辑工具做的修改。原文列出的追踪不到的情况：Bash 命令造成的变化（rm、mv、cp 这类操作）、Claude Code 之外的修改（你在编辑器或终端里改的）、子代理编辑的文件（rewind 时保持原样；例外是前台运行的 context: fork Skill，它的改动和主会话一样会被恢复）。v2.1.216 起 rewind 遇到经由软链接或硬链接的路径会跳过，并报告跳过了几个。

        所以原文的结论是两者配合：checkpoint 用来快速试验，git 用来保存定稿。checkpoint 作用于“对话加文件”、任意一步都能退、即时、基本不能分享；git 作用于文件系统、按提交、永久、可分享。原文推荐的做法：做 git 操作之前先有个快照；试验成功的状态及时提交到 git。

        保留设置

        原文「Configuration」「Checkpoint Retention」

        checkpoint 默认开启，不需要配置。两个相关设置：fileCheckpointingEnabled（默认 true，每次编辑前给文件打快照，/rewind 才能恢复代码；在 /config 里叫 Rewind code，环境变量 CLAUDE_CODE_DISABLE_FILE_CHECKPOINTING）和 cleanupPeriodDays（默认 30 天）。另外只保留最近 100 个快照，更早的即使在保留期内也会被丢掉。

        cleanupPeriodDays 管的不只是 checkpoint：v2.1.117 起会话记录、file-history/（快照实际存放处）、plans/、tasks/、shell-snapshots/、backups/ 等 ~/.claude/ 下的数据都按同一个天数在启动时清理。原文特意说明：没有 ~/.claude/checkpoints/ 这个目录。

        两道小题。

        会话管理：继续、恢复、改名、分叉

        原文 09-advanced-features「Session Management」，10-cli「Session Management」

        会话自动保存，可以随时接着做。claude -c 继续最近一次对话；claude -r "名字或ID" "接着做什么" 恢复指定会话，并把后面的提示词作为下一轮发出去；会话里 /resume 打开选择器（包括从列表里移除的会话）。要让 -r 好用，先用 /rename auth-refactor 给会话起个名字，或者启动时 claude -n "auth-refactor"。

        想保留原会话、另起一条线试别的方案，用 claude --resume auth-refactor --fork-session "试 OAuth"：原会话不变，分叉出一个新的独立会话。会话里还有 /branch、/fork、/subtask 三种复制方式（见第 2 篇）。离开一阵子再回来，Claude 会自动给一段前情摘要（/recap 手动触发，/config 里可关）；被 claude.ai 用量上限卡住的会话，v2.1.234 起会在额度重置后自动继续。原文的最佳实践：不同任务用不同会话，不要把无关的工作混在一个会话里。

        会话间消息

        原文 09-advanced-features「Cross-Session Messaging」

        v2.1.224 起会话之间可以互发消息，不用再在新会话里把背景重讲一遍：把问题交给已经装着相关上下文的那个会话。ListAgents 列出所有能联系到的对象：你派出的子代理、本机其他会话、你的云端会话，以及（连着 Remote Control 时）你其他机器上的会话；每一行的名字就是地址。SendMessage 发消息，加 notify_when_idle: true 可以让对方下次空闲时通知你一次（一次性，不轮询）。更简单的写法是在提示词里直接 @auth-refactor 迁移测试过了吗？。

        收不收由 crossSessionInbound 控制：accept（投递）、hold（只提示有消息，不投递）、refuse（丢弃）。三档从松到严，项目和本地设置只能比用户设置更严，仓库不能替你放宽。限制：云端会话能收你的消息，但还不能回消息给本地会话，要去它自己的记录里看回答。

        回扣开头的三个问题

        先自己答，再点开
        1. checkpoint 何时创建、有什么？六个选项各改变什么？

        每次提交提示词自动创建，包含消息、文件修改、工具记录、会话上下文，随会话保存，默认保留 30 天、最多 100 个。Esc 两下或 /rewind 打开。恢复代码和对话：两者都回去；恢复对话：只退消息，代码不动；恢复代码：只退文件，对话保留；从此处总结：选中点之后压成摘要；总结到此处：之前压成摘要；两个总结都不动文件、原始消息仍在记录里；算了：取消。

        2. 哪些变化追踪不到？和 git 怎么分工？

        Bash 命令造成的变化（rm、mv、cp）、Claude Code 之外的修改、子代理编辑的文件（前台 context: fork Skill 除外），以及经软链/硬链的路径。checkpoint 用于快速试验（对话+文件、任意一步、即时），git 用于保存定稿（永久、可分享）；git 操作前先有快照，成功的状态及时提交。

        3. -c、-r、--fork-session、/rename 各在何时用？

        claude -c：继续最近一次对话。claude -r "名字" "提示"：恢复指定会话并发出下一轮。/rename 或 claude -n：给会话起名，方便以后 -r。claude --resume 名字 --fork-session "提示"：从某会话分叉出新的独立会话，原会话不变。
