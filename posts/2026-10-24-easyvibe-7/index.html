“好看”可以被量化，所以可以被描述

第二阶段从前端开始。原教程的核心问题是：面对一款设计精美的页面，如何分析它是怎么设计出来的，并借助 AI 把它临摹到以假乱真？答案落在一个事实上：色值、字号、间距、圆角、阴影全是数字。会拆，就会描述；会描述，AI 就抄得像。这一篇把原教程前端部分的八章压成一条线：怎么看、怎么说、参考什么规范、用什么工具、怎样沉淀成自己的设计系统。

前端设计的第一课是临摹

原教程 UI 设计 第 1 章

原教程说：前端设计的第一课，不是创造，而是复刻。就像学书法先临帖。理由有三：设计的“好”可以被量化，色值、字号、间距、圆角、阴影全是数字；逐像素复刻一套成熟设计，会逼你搞懂它背后的每个决策（留白怎样制造呼吸感、配色为什么协调、主次怎样排出来）；抄到像了，下次遇到类似场景就知道往哪个方向抄。一句话：能临摹出一款好产品，说明有了基本功；能在此基础上改动，说明出师了。

参考本来就是设计师的日常（Pinterest 找灵感、Dribbble 看趋势、竞品分析看结构），AI 时代只是把参考变成了可执行能力：Claude Design 能导入参考网站按风格出稿，Open Design 内置上百套开源设计系统，UI design Skill 把大厂规范打包成 AI 指令。所以问题不是能不能抄，而是怎么抄得专业、合法、抄出自己的东西。原教程推荐先建一个参考库，按落地页、组件、配色、动效分类存截图和链接：Awwwards（顶级创意）、Godly、Landbook 和 Lapa Ninja（落地页）、Mobbin（真实 App 界面和流程）、Dribbble、Behance。

边界是一句话：抄“规则”可以，抄“结果”危险。布局结构、视觉风格、设计规范可以学，理解后重做；品牌 Logo、专属图标、原创插画、文案不要直接复制。商用前还要确认素材版权、字体授权（商用字体要买）、AI 生成内容的平台条款，品牌和广告物料必须人工把关。

这些做法，属于参考还是抄袭？

会看才会设计：三层拆解

原教程 UI 设计 第 2、4 章

原教程的拆解框架分三层。结构：绝大多数现代网页可以拆成导航栏（Logo、菜单、登录或 CTA）、首屏 Hero（主标题、副标题、主按钮、产品图）、内容区（特性卡片、数据、评价、定价）、页脚四块，先用眼睛画出骨架。视觉：四个可量化的要素，色彩（主色、背景、文字色的 Hex 值）、字体（标题和正文的字体、字号、字重）、间距（区块之间、卡片内部，常见 8 / 16 / 24 / 48 px 的节奏）、圆角与阴影。组件：把按钮、卡片这类可复用零件的样式参数逐个记下来，拆完三五个页面就有了自己的组件样式库。

原教程特别提醒：开发者天生就有设计分析仪。浏览器里右键“检查”，任何页面的色值、字号、间距、圆角都暴露无遗；也可以把截图交给多模态模型让它提取规范。拆完之后把“看到的设计”翻译成 AI 听得懂的结构化描述，看得越细，翻译得越准，AI 抄得越像。临摹的验收标准很客观：原图和临摹版并排放大逐区块对比，色值、字号、间距、圆角肉眼看不出差异，缩到 50% 仍分不清。第一版通常“神似而形不似”，这不是失败，正好告诉你该调哪里。

AI 默认回到“统计平均”
原教程 用 LLM 和 Skills 让界面变好看 第 1–3 节

  

    
为什么 AI 生成的界面常常“很普通”？训练数据里海量的前端代码大多做了“安全”的选择：字体是 Inter、Roboto，颜色是紫色渐变和蓝色主色，布局是对称网格加卡片堆叠，动画是淡入淡出，背景是纯色或简单渐变。单看都不错，但所有 AI 页面都这么做，就成了“AI 味”。原教程的关键洞察：AI 不是不会设计，而是默认回到统计平均，你要明确告诉它偏离平均值的方向。

    
描述风格要覆盖五个维度：字体（标题用有个性的展示字体，正文用易读字体）、颜色（主色加点缀色，避免平均分布）、布局（不对称、重叠、Bento Grid、打破网格）、动画（编排过的加载顺序、微交互）、细节（背景纹理、阴影、边框）。第二种办法是装 Skills，让 AI 每次自动加载一套设计规范，原教程介绍了 UI/UX Pro Max 和 Anthropic 官方的 frontend-design 等，还演示了把自己的设计系统做成一个 Skill（第 12 篇细讲 Skills）。

    
还有一个更省事的升级：在提示词里点名一个组件库。原教程用同一个仪表盘需求做了对比，唯一区别是加上“用 shadcn/ui 组件库来做”，结果在一致性、交互细节和打磨程度上明显不同。

参考大厂规范：先看主次，再看按钮
原教程 参考 UI 设计规范设计页面和按钮

  

    
原教程建议参考 Apple（定义得足够细、层级和克制感）、Material（清晰的页面结构）、Fluent（组件边界和按钮层级）、Atlassian（系统化管理页面和按钮）这些设计规范，但看的时候别先问“好不好看”，先问三个问题：页面第一眼主次是否明确（主信息、辅助信息、次级操作三层要拉开，否则“都重要”等于“都不重要”）；布局是否服务任务而不是堆模块（标题说明页面目标、操作按钮贴近相关内容）；操作是否有优先级。

    
按钮最容易被随手设计，也最能暴露系统成不成熟。原则是先分语义，再分样式：Primary 是当前区域最关键的动作（实心、高对比）；Secondary 是支持性动作（描边或低一级）；Tertiary 是弱操作（文字按钮）；Destructive 是删除、停用、清空等风险操作（警示色）；Icon button 是局部工具操作。一个区域通常只保留一个主按钮，页面上有四个主按钮等于没有主按钮；取消、返回不和确认抢同级；风险动作不要和主动作长得一样。按钮还要有默认、悬停、聚焦、禁用、加载、危险六种状态；文案也是设计：“保存”“保存更改”“立即发布”“移到回收站”传达的预期完全不同。

两条工具路线，三条转代码路径
原教程 UI 设计 第 3、5 章；Figma 与 MasterGo 入门；从设计原型到项目代码；组件库

  

    
原教程把设计工具分成两条路线。路线一：Figma / MasterGo，专业设计稿工具，产出可编辑、可协作、像素级可控的设计稿，适合严谨交付和复杂交互。入门要掌握两个概念：Auto Layout 把一组元素变成带规则的容器（横排还是竖排、间距、内边距），按钮设成 Hug contents 后文字变长按钮自动变宽；组件是可复用的母版，改母版的颜色圆角，所有实例同步更新。路线二：Claude Design / Open Design，对话式设计画布，一句话产出可交互的 HTML 原型（Claude Design 默认给三个方向的变体，可在画布上圈选评论局部修改，定稿后交给 Claude Code 写成代码；Open Design 是本地优先、自带模型 Key 的开源平替）。现实中常混用：对话式工具出方向 → Figma 精修 → 交给编码 Agent。

    
设计稿变代码有三条路径：① 截图交给多模态模型直接还原，灵活、无需特定工具，还原精度中等，适合快速验证和简单页面；② 平台自身能力或插件导出（Figma Make、MasterGo AI），还原度高，适合团队主用 Figma 或 MasterGo、需要频繁协作；③ 平台结合 MCP 导出，编码 Agent 直接读取设计文件里的图层、样式和组件信息，还原度和自动化程度最高，但要配置环境，适合频繁从设计迭代到代码的标准化流程。

    
组件库是前端的“宜家”：样式、交互、响应式、无障碍都已打磨好，全局风格统一。原教程介绍了四个：Ant Design（企业级中后台的事实标准）、shadcn/ui（不装 npm 包，把组件代码复制进项目，基于 Tailwind，定制最自由）、HeroUI（默认样式精美，适合落地页）、Material UI（最老牌，生态最成熟）；Vue 有 Element Plus、Ant Design Vue、Naive UI。选一个顺手的就够了。

    
回答几个问题，看设计转代码该走哪条路径。

  

  

  

  






  
把规范沉淀成 DESIGN.md
原教程 UI 设计 第 6 章；LLM 与 Skills 第 6 节

  

    
临摹三个页面后会发现：好看的页面背后都有一套稳定的设计系统。原教程把它概括为一个公式：DESIGN.md = 颜色 Token + 字体规范 + 间距节奏 + 组件样式 + 使用约定（Do / Don't）。Open Design 把 Linear、Vercel、Stripe、Apple 等的设计系统做成了这样的文件，Claude Design 则会从你的代码仓库或设计文件里自动提取。

    
建立自己的设计系统分三步：选基底（套一个你认可的大厂系统，比如 Linear 的克制暗色、Apple 的留白）→ 改参数（换成品牌色，调圆角和间距）→ 沉淀成文件（保存为 DESIGN.md 或封装成 Skill，让 AI 每次生成都自动遵守）。之后一句“使用 my-brand 的设计规范生成三个功能页的首屏”就能保持风格一致。商业交付时，原教程建议把“参考”变成“自己设计系统的再创作”，并保留生成记录。

    
这是一份可以直接改的模板。

  

  
# Design System: 我的产品
## Colors
- background: #08090A
- primary: #5E6AD2
- text: #F7F7F8
## Typography
- heading: 22px / 600, letter-spacing -0.4px
- body: 14px / 400
## Radius
- card: 8px
- button: 6px
## Spacing
- 4 / 8 / 12 / 16 / 24 / 32 px
## Do / Don't
- Do: 大量留白，克制用色；一个区域只有一个主按钮
- Don't: 不使用渐变、不堆叠阴影

  

    
易混辨析：设计规范、设计系统、组件库

    
设计规范（Apple HIG、Material、Fluent）是写给人看的原则和标准：层级怎么排、按钮怎么分、状态怎么定义。设计系统是一个产品自己的一整套可执行约定，DESIGN.md 就是它的文字版：具体到色值、字号、间距和 Do / Don't。组件库（Ant Design、shadcn/ui）是把一套设计系统实现成代码的零件，拿来就能用。从规范里学原则，写成自己的系统，再用组件库或 Skill 落到代码里。

  

  






  
素材生产：把“理解”和“执行”拆开
原教程 从 NanoBanana 出发，搭建自己的素材生产 Agent

  

    
页面里还需要图标、Logo、头像、配图。原教程观察到，生图模型在实际工作中更多用于高效产出设计素材，而非创作单张艺术品，主要两类：文生图（从 0 到 1），当作即时生成的图库，填补空状态、头像、配图（毛玻璃 3D 图标、极简线条 Logo、SaaS 官网常用的 3D 虚拟头像以规避真人版权、扁平风文章插画）；有图参考生图（从 1 到 N），基于已有素材做变体和系列。

    
直接把一篇长文章丢给画图模型要配图，效果通常很差。原因不在“画得不行”，而在图像模型只有执行能力，不擅长理解长文本，判断不出哪些内容才是画面要表达的。原生 API 是指令式的：让它画一个具体对象可以，让它“策划一套完整的游戏素材”它不会主动拆解。Lovart 这类产品的差异就在中间加了一层 Agent：先识别意图、拆解任务、重写提示词，再执行生成。原教程带着自己搭了一个最简单的版本：语言模型做决策核心（理解文章、判断意图、写视觉提示词），图像模型只做执行，用户可以中途改提示词或加参考图，Gradio 和后端 API 负责承载。

回扣开头的三个问题
先自己答，再点开

  

    
1. 拆解页面看哪三层？哪四个视觉要素可量化？
结构（导航、首屏 Hero、内容区、页脚四块）、视觉、组件（按钮、卡片等可复用零件的样式参数）。可量化的视觉要素：色彩（Hex 值）、字体（字体、字号、字重）、间距（8 / 16 / 24 / 48 的节奏）、圆角与阴影。浏览器开发者工具就是分析仪，拆完翻译成结构化描述交给 AI。

    
2. AI 界面为什么普通？描述风格的五个维度？
训练数据中大多数前端代码选择安全的默认值（Inter 字体、紫蓝渐变、对称卡片、淡入淡出），AI 默认回到统计平均，于是千篇一律。要明确给出偏离方向，覆盖字体、颜色、布局、动画、细节五个维度；或者装设计类 Skill、在提示词里点名组件库。

    
3. 设计转代码三条路径？DESIGN.md 装什么？
① 截图交给多模态模型直接还原：灵活、上手最简单，精度中等，适合快速验证；② 平台能力或插件导出：还原度高，适合主用 Figma / MasterGo 的团队；③ 平台结合 MCP 让编码 Agent 直接读设计文件：精度和自动化最高但需配置，适合频繁迭代的标准化流程。DESIGN.md 是颜色 Token、字体规范、间距节奏、组件样式和 Do / Don't 使用约定。
