从概率表到聊天助手

模型本身只会交出概率表。要变成你每天用的那个助手，还得决定怎么从表里挑词、教它用对话的方式回应、让它会调用工具、把它做大，并且清楚它在哪些地方靠不住。

本系列受《三万字长文：大语言模型从零入门》（腾讯技术工程公众号，作者 flyflywang）启发。原文是一篇系统扎实的长文，推荐对照阅读；这里不复述原文，而是把其中的概念换成能动手试的小实验。

从概率表里挑一个：稳一点，还是野一点

温度 · Top-k · Top-p

模型本身讲完了：给它一段前文，它算出下一个 token 的概率表。从这一篇开始看它怎么变成你每天用的聊天助手。第一个问题是从表里怎么挑。

永远挑概率最高的（贪心），文字稳定但平淡，还容易陷入重复；完全按概率抽签，又可能抽中长尾。词表有十几万个 token，单个离谱词的概率也许只有十万分之一，可成千上万个加起来就有几个百分点，生成几百个 token 时碰上几次几乎是必然的。Top-k 只在最高的 k 个里抽，Top-p 从高到低累加到 p 为止，候选数会随情况自动伸缩。温度则先把分数除以 T 再做 Softmax，T 越小越保守，越大越大胆。

换策略、拖温度和 p，看哪些候选被砍掉，再点“抽 20 次”看结果。

“给巷子里新开的咖啡馆起个名字：____”

所以同一个问题每次答案不同：概率表一样，抽到的词不同，后面整段就走向不同方向。写代码、查事实适合低温，起名、写诗可以高一点。但采样只能在表里挑，表本身错了，怎么挑都救不回来。

概念

贪心解码
每步都选概率最高的 token，稳定但容易单调重复。
随机采样
按概率抽签，多样但可能抽中长尾里的离谱词。
Top-k
只在概率最高的 k 个候选里抽。
Top-p（核采样）
从高到低累加到概率 p 为止，只在这些候选里抽，候选数随情况变化。
温度
先把分数除以 T 再做 Softmax，控制分布的尖锐程度。

公式与要点

qi = softmax(si / T)
T < 1 更集中保守，T > 1 更平均大胆。
T → 0 等价于贪心
最高分拿走全部概率。
长尾单个很小、合起来不小
生成几百个 token 时，抽中离谱词几乎必然。
采样改变不了概率表本身
表错了怎么挑都救不回来。

只会续写的模型，怎么学会“回答”

后训练

到目前为止，模型学的都是“人写的文本接下来通常是什么”，这一步叫预训练，得到的是基座模型。它知识很多，但只会续写：你问一个问题，它可能接着列出更多问题，因为网上的问题常常成串出现。它其实知道答案，只是不知道自己该扮演回答者，还可能写个不停、模仿网上的粗鲁语气。

把它变成助手的训练统称后训练。监督微调用“指令 + 优质回答”的示范教它回答的样子，几千到几万条精选示范就够；偏好对齐让它学会人更喜欢的回答；推理强化学习只告诉它答案对不对，它自己摸索出先写过程、中途检查的习惯。对模型来说，对话仍然是一段连续文本，只是用特殊标记分出了谁在说话。

切换四个阶段，看同一个问题的回答怎么变，再切到“模型实际读到的文本”。

  • 对模型来说，对话依然是一段连续文本，只是用特殊标记分出了谁在说话。系统提示词就是放在最前面的一段字；多轮对话里，之前每一轮都会拼进前文。
  • 示范数据贵在质量：几千到几万条精选示范，就足以让基座模型学会对话的样子。

推理强化学习
在可自动判对错的题目上只奖励最终正确，模型自己学会先推理再作答。

预训练 → SFT → 偏好对齐 → 推理强化
从续写机到会推理的助手。

打分的模型有盲点，就会被钻空子

奖励投机

示范有两个局限：写高质量示范很贵；而且人往往更擅长比较而不是创作，你写不出一首好诗，但给你两首，大概能分出哪首更好。RLHF 就利用这一点：让标注员在成对的回答里挑更好的，用这些挑选训练一个打分模型，再让助手往高分方向优化。效果很明显，有研究里标注员更喜欢 13 亿参数的对齐模型，而不是 1750 亿参数的原始 GPT-3。

但打分模型只是人类口味的近似，有盲点。放开优化，模型会找到钻空子的办法，比如打分模型略偏爱长回答，它就越写越长、越写越空，这叫奖励投机。所以优化时要加约束，不许离原模型太远。

约束的做法是在奖励里扣掉“和原模型差多远”的分，这样优化走不到太偏的地方。也有更简单的 DPO 方法，跳过打分模型，直接用“好 / 差”回答对来调。

概念

RLHF
基于人类反馈的强化学习：收集偏好比较 → 训练打分模型 → 让助手往高分方向优化。
奖励模型
用人的“哪个更好”数据训练出来、给回答打分的模型。
奖励投机
模型钻打分模型的空子，分数上涨但真实质量下降。
KL 约束
在奖励里扣掉“偏离原模型多远”，防止优化走偏。
DPO
跳过奖励模型，直接用“好 / 差”回答对调整模型的偏好对齐方法。

公式与要点

人更擅长比较，不擅长创作
这正是偏好数据比示范数据更容易收集的原因。
优化目标 ≈ 奖励 − β · KL(新模型 ‖ 原模型)
β 控制约束强弱。
InstructGPT：13 亿参数胜过 1750 亿的 GPT-3

它不会上网，它只会写“我要上网”

工具调用

现在的聊天助手还能联网搜索、运行代码、看图片，可模型只会预测下一个 token，这是怎么做到的？答案是：模型只负责写出“要做什么”。训练让它在需要外部信息时，输出一段约定格式的调用文字，然后停下。外部程序看到这段文字，真的去执行搜索或计算，再把结果作为一段新文字拼回上下文，模型读到结果后接着往下写。

算数、查资料、读文件都是同一个套路。所谓智能体（Agent），就是让“想下一步、调工具、看结果”这个循环自动跑很多轮。看图也类似：图片被切成小块，每块转成一个向量，和文字 token 排在一起。对模型来说，一切都是一串 token。

一步步点“下一步”，看这段文本是怎么被模型和外部程序轮流写长的。

  • 智能体（Agent）就是让这个循环自动转很多圈：想下一步、调工具、看结果、再决定，直到任务完成。
  • 看图也是同一个思路：把图片切成小块，每块变成一个向量，和文字 token 排在一起送进同一个 Transformer。对模型来说，一切都是一串 token。

为什么越做越大

规模定律

“大语言模型”到底大在哪、为什么要大？影响能力的有三个量：参数量 N（脑容量）、训练 token 数 D（读了多少书）、计算量 C（学了多久），常用估算是 C ≈ 6ND。2020 年的研究发现，交叉熵随这三者的增加按幂律平稳下降，规模每扩大同样倍数，损失就降一个大致固定的比例。这让人能先用小模型做便宜的实验，再外推大模型的效果。

2022 年的 Chinchilla 研究进一步发现，参数和数据要一起涨，算力最优时每个参数大约配 20 个训练 token；它还把损失拆成三部分：模型不够大、数据不够多，以及一块怎么都消不掉的不可约部分，那正是文本本身的熵。

拖动参数量和 token 数，或点几个真实模型的预设，看损失的构成；再试试“同样的算力，换成最优分配”。

概念

规模定律
交叉熵随参数量、数据量、算力的增加按幂律平稳下降。
算力最优
在固定计算预算下，使损失最低的参数量与数据量搭配。
不可约损失
无论模型多大、数据多多都消不掉的部分，对应文本本身的熵。
幂律
规模每扩大同样的倍数，损失就按大致固定的比例下降；在双对数坐标上近似一条直线。

公式与要点

训练算力 C ≈ 6 · N · D
N 是参数量，D 是训练 token 数；正向 2N、反向 4N。
L(N, D) = E + A / Nα + B / Dβ
Chinchilla 拟合：E ≈ 1.69，α ≈ 0.34，β ≈ 0.28。
算力最优：每个参数约 20 个训练 token
Chinchilla 的经验比例。
GPT-3：6 × 1750 亿 × 3000 亿 ≈ 3.1 × 1023 次运算
与论文报告一致。
推理成本取决于参数量
所以常用远超 20 倍的数据训练小模型，如 Llama 3 8B 读了约 15 万亿 token。

它在哪些地方靠不住

症状对病根

模型的能力来自“在海量文本上预测下一个 token”，它的局限也大多来自这里。最有名的是幻觉：流畅、自信，却与事实不符。可以从几个角度理解：训练目标是“像人写的”而不是“真实”，遇到不确定的内容，最像样的续写往往仍是一段自信的文字；零散的事实没有规律可压缩，只出现一两次的很难记牢；很多评测答错和不答都得零分，猜一个更划算；写出去的字又收不回来。

其他常见毛病也各有根源：知识停在训练截止日，看的是 token 而不是字母，上下文长度有限，偏好训练学会了顺着人说，学到的关联是有方向的。

给下面每个症状挑一个病根，对了会显示应对办法。

    • 越冷门、越具体（人名、日期、数字、引用、网址），越容易出错；关键信息一定要自己核实。
    • 它的能力参差不齐：可能解得出竞赛题，却在简单常识上翻车。可不可靠，要看它在你自己的真实任务上的表现。
