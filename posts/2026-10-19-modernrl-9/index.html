跟同一道题的其他回答比

PPO 问“这个回答比 Critic 预估的好吗”，GRPO 问“这个回答比同一道题的其他回答好吗”。DeepSeekMath 提出 GRPO 时明确说它 foregoes the critic model：同一个 prompt 采 G 个回答，组内均值当基线、标准差做归一化，其余照搬 PPO 的比值和裁剪。再配上 RLVR——数学答案对不对、代码测试过不过直接当奖励——奖励模型也省了。原教程用一句话概括：GRPO = 在线组采样 + 规则 / 奖励打分 + 组内相对优势 + PPO 式裁剪更新。

组内相对优势：没有 Critic 怎么知道好坏

原文 docs/chapter18_grpo/grpo-practice-and-mechanism.md（15.1 节）

Critic 在 LLM 训练里有三个问题（原文）：吃显存——和 Actor 同等规模，PPO 要同时装 Actor + Critic + Reference + RM；不稳定——要从“写到一半的文本”预测 500 个 token 之后才出现的分数；工程复杂——四套优化器和超参。但 Critic 的本职只是提供基线来降方差（第 3 篇）。GRPO 的想法是：同一个 prompt 采 G 个回答，它们的平均分就是 V(prompt) 的 G 次蒙特卡洛估计，直接拿来当基线。

组内优势 Âj,i = (rj,i − r̄j) / (sj + ε)：减均值替代 Critic，保证优势的正负与“是否好于同组平均”一致、组内期望为 0；除标准差把不同难度题目的优势拉到同一尺度（z-score）。原文的苹果题：4 个回答得 1.5、1.0、0、0，均值 0.625，前两个该多生成、后两个该少生成。一条回答只有一个结果奖励，所以它的所有 token 共享同一个 Â；但比值、裁剪、KL 仍然逐 token 计算。

原文用一个 diff 说明“到底换了哪几行”：生成、打分、比值、裁剪都不变，只是删掉 values = critic(...) 和 advantages = rewards − values，换成按组 reshape 后减均值、除标准差。GRPO 也没有继承 GAE：奖励只在序列末尾、又没有逐 token 的 V，多步 TD 退化为单步，和“最终奖励减均值”没有本质区别。显存上，原文给的经验是比 PPO 省约 30–40%。

算法卡 · GRPO

Group Relative Policy Optimization（DeepSeekMath, Shao et al., 2024）

解决什么问题
PPO 的 Critic 吃显存、难训、工程复杂，而 LLM 的奖励只在末尾。
核心做法
每个 prompt 在线采 G 个回答 → 打分 → 组内 z-score 作为每个回答的优势 → 逐 token 比值、裁剪、KL → 只更新 Policy。
关键公式
Âi = (ri − mean(r)) / (std(r) + ε)；J = (1/G)Σi(1/Ti)Σt[min(ρi,tÂi, clip(ρi,t, 1 ± ε)Âi) − βD̂i,t]
何时用
有可计算奖励（规则验证器或 RM）的在线后训练，尤其是数学、代码等长推理任务。
代价与坑
每题采 G 次，生成成本高；全对 / 全错的组没有信号；除以 std 和按长度平均会带来偏差（Dr.GRPO）；奖励稀疏时样本浪费。
相关
REINFORCE + 基线（第 3 篇）、PPO 裁剪（第 4 篇）；DAPO / Dr.GRPO / GSPO / VAPO（下文）。

哪些题提供学习信号：全对和全错都学不到东西

原文 15.1“组内方差的演化”“k 值的选择”、deepseek-dapo.md（15.2）

组内标准差为 0 时（全对或全错），所有优势都是 0，这道题这一轮没有任何梯度。原文把训练后期的这种现象叫“毕业”：模型已经全会的题自然退出训练，信号转移到还没掌握的题上。反过来，太难的题全错，同样没有信号。所以真正有用的是“有对有错”的题：单次正确率为 p、组大小为 G 时，这个概率是 1 − pG − (1 − p)G。

原文给的组大小经验：G = 2 均值和标准差极不稳定，只适合快速验证；4 资源有限时用；8 是默认推荐；16 更稳；DeepSeekMath 正式实验用的是 64。DAPO 的“动态采样”直接针对这个问题：采样后过滤掉已经全对（或全错）的 prompt，只保留有梯度信号的，补满 batch 再训练。

逐 token 的比值、裁剪与 KL

原文 15.1“策略比值与 PPO Clip”“KL 惩罚”、grpo-family.md（GSPO）

原文专门纠正了一个常见的实现错误：GRPO 原始定义（DeepSeekMath 式 3）是每个 token 分别算比值 ρt = πθ(ot)/πold(ot)、分别裁剪，再对一段回答的有效 token 求平均，最后对组内回答求平均。如果先把整段 logp 求和再取指数，得到的是所有 token 比值的连乘：长度被带进比值，整段只裁剪一次——那不是 GRPO。原文的例子：三个 token 比值 [1.1, 0.9, 1.5]，逐 token 裁剪得 [1.1, 0.9, 1.2]；连乘是 1.485，裁成 1.2。

GSPO（Qwen3 采用）则是有意地改用序列级比值，但必须做长度归一化：si = (Πtρt)1/|y|，即 token 比值的几何平均——原文说这对 MoE 模型训练的稳定性很重要，代价是单 token 的信用分配变粗。另一个细节是归约方式：原始 GRPO 每段回答先除以自己的长度（TRL 的 loss_type="grpo"），把整个 batch 的 token 一起平均则是 bnpo，长回答权重更大。

KL 惩罚也逐 token 计算，用的是 k3 估计：D̂ = eΔ − Δ − 1，Δ = log πref − log πθ。原文证明了它的三条性质：恒非负（u − log u − 1 是凸函数，最小值 0 在 Δ = 0）；无偏（在 πθ 下期望正好等于 KL(πθ ‖ πref)）；小偏差处约等于 Δ²/2。朴素估计 −Δ 虽然也无偏，但单个样本可能为负。DeepSeekMath 用 β = 0.04。

RLVR：规则就是裁判

原文 docs/chapter18_grpo/rlvr.md（15.3）、rl-environments.md（15.5）

数学有标准答案、代码能跑单元测试、形式证明能用 Lean 检查——这些任务可以直接把验证结果当奖励，这就是可验证奖励强化学习（RLVR）。原文的 GSM8K 例子：抽出 \boxed{…} 里的答案，有框 +0.5（格式），数值对 +1.0（正确性），满分 1.5。不用训练 RM，不用偏好标注，奖励确定、可复查。训练后模型从“直接猜答案”变成“先列算式再计算”——不是谁教的，而是因为展示步骤更容易拿到高分。

原文给验证器定了三条标准：确定性、正确性（等价表示要判对：22/7 与 3.1428…、(x+1)(x−2) 与 x² − x − 2，需要数值容差和符号化简）、高效（不能成为训练瓶颈）；还要抗作弊。RLVR 被 hack 的方式和 RM 不同：模型利用的是验证器遗漏的条件——只检查格式、只匹配最后一个数字、单元测试覆盖不全、甚至去改测试本身（第 12 篇）。原文也记录了一个开放争议：RLVR 究竟是在“注入新推理能力”，还是只是提高了模型在已有能力里搜到正确答案的效率？

算法卡 · RLVR

Reinforcement Learning with Verifiable Rewards

解决什么问题
RM 需要标注、有噪声、会被 hack；而很多任务本身就能自动判对错。
核心做法
用确定性验证器（答案匹配、单元测试、形式证明）给回答打分，通常配合 GRPO / PPO 在线训练；格式分 + 正确性分。
关键公式
r = 0.5·1[格式合规] + 1.0·1[答案等价于标准答案]（原文 GSM8K 示例）
何时用
数学、代码、工具调用参数、逻辑推理等有客观对错的任务。
代价与坑
不适用主观偏好；验证器漏洞会被利用；奖励稀疏（太难全错、太易全对）；“提升能力还是提升搜索效率”仍有争议。
相关
GRPO（本篇）；PRM 给每一步打分（第 10 篇）；验证器漏洞与评测泄漏（第 12 篇）。

R1-Zero、DAPO 与 GRPO 的改进路线

原文 docs/chapter18_grpo/deepseek-dapo.md（15.2）、grpo-family.md（15.4）

在 DeepSeek-R1 之前，几乎没人质疑“必须先 SFT 再 RL”。R1-Zero 证明：在有客观规则奖励的领域，可以直接对 base 模型做大规模 GRPO，不需要 SFT 冷启动——只要偶尔答对一次拿到奖励，RL 就会强化那条路径。训练中出现了长思维链、自我检查（“等等，让我重新算一下”的 aha moment）等涌现行为。原文的解读是：推理的“原材料”来自预训练，RL 把它们组织成可用的解题策略。R1-Zero 的缺点是语言混杂、可读性差，所以正式的 DeepSeek-R1 用了多阶段流程（见下）。SimpleRL-Zoo 等开源工作在多种 base 模型上复现了“zero RL”，也说明 base 模型的选择决定了起点和上限。

DAPO 针对 GRPO 的四个工程痛点：Clip-Higher（上下界解耦，给低概率但有潜力的 token 更多上升空间，防止探索被压死）；动态采样（过滤全对 / 全错的 prompt）；token 级损失（按 token 而非按序列平均，长回答里的 token 不被稀释）；超长奖励塑形（用平滑的长度惩罚代替硬截断）。原文给的结果是 DAPO 用 R1-Zero 一半的训练步数在 AIME 2024 上达到 50 分。

原文把 2025 年之后的变体按“修补哪一处”归为几条路线：Dr.GRPO 指出除以 std（以及按回答长度平均）会引入偏差、助长回答变长，改为只减均值；GSPO 改用长度归一化的序列级比值（MoE 更稳）；CISPO 裁剪重要性权重本身而不是丢弃 token 的梯度；VAPO 反其道而行，重新引入 value model + GAE 做 token 级信用分配——原文的评语是“critic-free 是工程妥协，不是算法必然”。原文最后的建议是建立一种判断力：看到新变体时，先问它修补的是归一化、比值层级、裁剪对象，还是价值估计。

算法卡 · DAPO

Decoupled Clip and Dynamic Sampling Policy Optimization

解决什么问题
GRPO 在长思维链训练中的熵坍缩、零信号样本、长回答 token 被稀释、长度失控。
核心做法
上下裁剪界解耦（上界放宽）；过滤全对 / 全错的组；token 级平均；平滑的超长惩罚。
关键公式
clip(ρ, 1 − εlow, 1 + εhigh)，εhigh > εlow；loss 对 batch 内全部有效 token 求平均
何时用
数学 / 代码 RLVR 的长推理训练；多轮工具调用（原文选型树）。
代价与坑
动态采样要多生成来补满 batch；token 级平均会给长回答更大权重。
相关
GRPO、Dr.GRPO；超长塑形与第 10 篇的思考预算控制。

易混辨析：GRPO 与 PPO、DPO、REINFORCE

GRPO vs PPO：基线从 Critic 的 V(s) 换成组内均值；保留比值与裁剪，不用 GAE；模型从 4 个变成 2 个（Policy + Reference，用规则奖励时无需 RM）。

GRPO vs DPO：GRPO 在线生成、按奖励在组内比较；DPO 离线、按人标的偏好对比较。两者都在“比较”，但比较的对象来源不同。

GRPO vs REINFORCE：GRPO 本质上是“组内均值当基线 + 归一化 + PPO 裁剪 + KL”的 REINFORCE；同一组的回答共享 prompt，唯一差异是采样随机性，所以组内比较是一个很好的控制变量。

token 比值 vs 序列比值：GRPO 逐 token 裁剪；整段 logp 求和取指数是连乘、不是 GRPO；GSPO 用的是长度归一化后的几何平均。

1. GRPO 用什么替代了 Critic？为什么组内均值能当基线？

同一 prompt 的 G 个回答的平均奖励（再除以组内标准差）。Critic 的本职是估计“这个 prompt 下平均能拿多少分”来降方差，而同一 prompt 的 G 个回答正是 V(prompt) 的 G 次蒙特卡洛样本，均值就是它的估计；组内回答只在采样随机性上不同，比较起来是很好的控制变量。

2. 全对或全错时会怎样？G 怎么选？DAPO 的动态采样解决什么？

组内标准差为 0，所有优势为 0，这组没有梯度（“毕业”或太难）。有信号的概率是 1 − p^G − (1 − p)^G，G 越大越不容易落空，原文默认 8、大规模用到 64；G 太小统计量不稳。DAPO 动态采样过滤掉全对 / 全错的 prompt、补满 batch，避免算力浪费在零信号样本上。

3. RLVR 的奖励从哪来、会被怎样钻空子？R1-Zero 证明了什么？

来自确定性验证器：答案匹配、单元测试、形式证明。会被利用的是验证器遗漏的条件——只看格式、只查框里的数、测试覆盖不全、改测试本身。R1-Zero 证明在有规则奖励的领域可以跳过 SFT 直接对 base 模型做大规模 GRPO，并涌现长思维链和自我检查；但可读性差，正式版 R1 用了冷启动 SFT → GRPO → 拒绝采样 → SFT → 二次 RL 的多阶段流程。
