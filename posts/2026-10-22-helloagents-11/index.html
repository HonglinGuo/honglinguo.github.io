为什么要用强化学习

原书 11.1.1–11.1.2 节

把“Janet 的鸭子每天下 16 个蛋，早餐吃 3 个、做松饼用 4 个，剩下的每个卖 2 美元，每天赚多少”这道题映射到 RL：智能体是 LLM 推理系统，环境是题目和验证系统，状态是题目加已有推理步骤，行动是生成下一步推理或最终答案，奖励是答案对不对（对 +1，错 0）。监督学习的三个局限是：质量完全取决于数据（只能模仿，难以超越）、缺乏探索、难以直接优化多步推理的中间过程。RL 让模型自己生成多个候选、按正确性拿奖励，从而学会哪些推理路径更好，甚至找到比人工标注更好的解法。

原书还铺了一遍 LLM 训练全景：预训练在海量文本上做下一个词预测（自监督），学到语言规律和世界知识；后训练让模型学会听指令、对齐人类偏好，分三步：SFT（用 prompt–completion 对学会指令和格式）、奖励建模（用 chosen / rejected 偏好对训练一个打分模型，目标是让好回答得分高于差回答）、强化学习微调（经典是 PPO：最大化奖励，同时用 KL 散度约束不要离参考模型太远）。人工标偏好太贵，于是有了 RLAIF：用强模型代替人打分，原书说效果接近甚至超过 RLHF。

Agentic RL：从单步打分到多步轨迹

原书 11.1.3–11.1.4 节，表 11.1

传统后训练原书称为 PBRFT（基于偏好的强化微调）：给一个问题，模型生成一个完整回答，按质量打一次分，本质是单步。Agentic RL 把 LLM 当成嵌在顺序决策循环里的可学习策略：多步与环境交互，每一步改变状态，每一步都可以有反馈，优化整条轨迹的累积奖励。原书的例子：分析一个 GitHub 仓库的代码质量，调 API 拿到结构 +0.1，读到代码 +0.1，分析合理 +0.2，报告质量高 +0.6，总分 1.0。

用 MDP 五元组（S, A, P, R, γ）对比就很清楚：PBRFT 的状态只是 prompt、时间跨度 T = 1、没有状态转移、只有终局奖励；Agentic RL 的状态是 (prompt, o1, …, ot)、T ≫ 1、行动既有文本也有工具调用、状态随行动演化、奖励可稀疏可密集，目标是最大化 Σ γt r(st, at)。原书列了 Agentic RL 想赋予的六种能力：推理、工具使用、记忆、规划、自我改进、感知，正好对应本书前面几章靠工程手段实现的那些能力，现在换成用训练把它们写进参数。

HelloAgents 的实现：集成 Hugging Face 的 TRL，模型用 Qwen3-0.6B（普通 GPU 就能训）；四层结构是数据集层（GSM8KDataset、create_sft_dataset、create_rl_dataset）、奖励函数层（Accuracy、LengthPenalty、Step）、训练器层（SFTTrainerWrapper、GRPOTrainerWrapper），对外仍然是一个工具 RLTrainingTool，用 action 区分 load_dataset、create_reward、train、evaluate。

GSM8K 与三种数据格式

原书 11.2.1、11.2.3 节，表 11.2–11.3

为什么拿数学题练？答案明确、能自动判对错，不需要人工标注或奖励模型；解题天然是多步推理；学到的推理能力可迁移。GSM8K 有 7473 道训练题、1319 道测试题，小学 2 到 8 年级难度，需要 2 到 8 步推理。原始答案里用 <<48/2=24>> 标中间计算，用 #### 72 标最终答案。

同一道题要变成两种训练格式。SFT 格式：prompt 套上模型的对话模板（Qwen 的 <|im_start|>），completion 是完整解题过程加 “Final Answer:”，模型学的是怎么组织输出。RL 格式：prompt 相同，但只给 ground_truth（最终答案），不给过程，模型必须自己生成推理，奖励只看答案。自定义数据只要准备 question 和 answer（以 #### 结尾）两个字段，用 format_math_dataset(raw, format_type="sft" | "rl") 转换，可以直接传入训练，也可以 register_dataset 注册后按名字复用；自定义奖励函数签名是 f(completions, **kwargs) -> List[float]，从 kwargs 里取 ground_truth。

奖励函数：定义什么是好
原书 11.2.2 节，表 11.4

  

    
好的奖励函数要能清楚定义成功、提供梯度信号、方差不过大、容易调整组合；坏的奖励只在结束时给分、可被“作弊”、多目标互相矛盾、方差大到不收敛。HelloAgents 内置三种：准确率奖励，答对 1 答错 0（提取答案时要处理 “Final Answer:”、“####”、取最后一个数字，以及 72.0 与 72 视为相同）；长度惩罚，r = racc − α · max(0, l − ltarget)，α 默认 0.001；步骤奖励，r = racc + β · s，s 是检测到的推理步骤数，β 默认 0.1。后两者都只在答对时生效，防止模型为了少扣分写一个错的短答案、或者为了多拿分在错误答案里堆步骤。

    
三者可以组合：准确率 + 长度惩罚适合对话和问答（要简洁），准确率 + 步骤奖励适合教育和可解释场景（要过程），三者平衡则要仔细调 α、β，避免某一项主导。准确率奖励的缺点是稀疏：训练初期几乎全错，没有梯度信号，所以原书的自定义示例给了一个带容差的版本（误差小于 0.01 得 1，小于 1 得 0.8……）。

SFT 是桥梁，LoRA 省显存
原书 11.3 节，表 11.5

  

    
为什么不直接上 RL？原书对比了两段输出：预训练模型对 Natalia 卖发夹那道题，回答冗长、没有结构、没有明确答案（“我不确定怎么算 48 的一半，也许该用计算器？”）；SFT 之后变成 “Step 1 … Step 2 … Final Answer: 72”。前一种输出无法提取答案、无法计算奖励，RL 根本无从下手。所以 SFT 的作用是：学会输出格式、学会基本推理模式、建立基线能力、缩小 RL 的探索空间。它是从预训练模型通往强化学习的桥梁。

    
全量微调 0.6B 模型约需 12 GB 显存（FP16），7B、13B 在消费级显卡上几乎不可能。LoRA 的假设是微调带来的权重变化是低秩的：ΔW = BA，B 是 d × r，A 是 r × k，r 远小于 d 和 k；冻结原权重 W，只训练 B 和 A，前向是 h = Wx + BAx。关键超参：rank（典型 4 到 64，默认 8）、alpha（实际更新为 (α / r)·BA，常取等于 rank）、target_modules（通常是注意力的 q、k、v、o 投影，也可加 MLP 的 gate、up、down）。优点是显存大降、训练更快、部署方便（只存小适配器）、不易过拟合；代价是效果通常略逊于全量微调。

易混辨析：SFT 的 loss 和预训练的 loss

    
公式几乎一样，都是负对数似然。区别在于数据和计算范围：预训练在海量无标注文本上对每个 token 计算；SFT 在少量 prompt–completion 对上，通常只对 completion 部分计算 loss（prompt 部分被掩掉），目的是学“给定这种输入，该输出什么样的回答”，而不是继续学语言本身。

  

  






  
GRPO：和同组的自己比
原书 11.4 节，表 11.6

  

    
PPO 在 LLM 上的麻烦：要训练一个价值模型来估计优势 A(s, a)，训练时同时维护四个模型（策略、参考、价值、奖励），工程复杂、显存吃紧，还容易奖励崩塌。GRPO（DeepSeek 提出）的核心想法：对同一个问题采样一组答案，用组内平均奖励当基线，相对奖励 ri − r̄ 就代替了优势函数，不再需要价值模型，只剩策略和参考两个模型，方差也更小；再加上 KL 惩罚 −β · DKL(πθ ‖ πref) 防止偏离 SFT 模型太远、忘掉学到的格式。

    
训练循环五步：采样（每题生成 num_generations 个答案组成一组）→ 算奖励 → 算相对奖励 → 带 KL 惩罚更新策略 → 重复。kl_coef 太小（0.01）策略会跑偏、格式混乱，太大（0.5）学不动、难以超越 SFT，原书建议 0.05 到 0.1。训练时盯四个数：平均奖励应逐渐上升（不升查学习率、KL 系数、奖励设计；先升后降可能是过拟合或奖励崩塌）；KL 应在 0.01 到 0.1（大于 0.5 说明跑太远，小于 0.001 说明几乎没更新）；准确率应提升；生成质量要人工抽查。可以接 Weights & Biases 或 TensorBoard 看曲线。

评估与错误分析
原书 11.5 节，表 11.7

  

    
评估分三类指标。准确性：准确率；Accuracy@K（采样 K 个，有一个对就算对，反映模型的“潜力”）；数值误差（区分“差一点”和“完全错”）。效率：平均长度（推理成本）、推理步骤数（2 到 5 步说明能系统分解，太多说明冗余）、推理时间。质量：格式正确率（基本要求）、推理连贯性、可解释性（后两者常需人工或评估模型）。

    
只看准确率不够，要看错在哪。原书把错误分四类：计算错误（思路对、算错，如 48/2 = 25）、推理错误（思路错，如该先除后加却先加后除）、理解错误（没读懂题，如问“总共”只算了一部分）、格式错误（答案对但缺 Final Answer 标记）。原书的示例分布是计算 42.1%、理解 28.9%、推理 23.7%、格式 5.3%；按难度分，1–2 步题 78.5%、3–4 步 58.3%、5 步以上只有 31.6%。结论：格式错误少说明 SFT 有效，计算错误多说明可以给它一个计算器工具，难题差说明多步推理还要加强。

完整流程、调参与分布式
原书 11.6 节，表 11.8

  

    
端到端流水线六个阶段：数据准备 → SFT 训练 → SFT 评估 → GRPO 训练 → GRPO 评估 → 部署，原书把它写成一个读 config.json 的 AgenticRLPipeline 类，每阶段记日志、存结果。快速上手时只用 10 个样本、1 个 epoch 跑通流程，准确率很低是正常的，因为模型只见过 0.7% 的训练样本。

    
调参三法：网格搜索（遍历组合，简单但贵）、随机搜索（随机采样，参数空间大时更高效）、贝叶斯优化（如 Optuna，用概率模型指导搜索，样本效率高）。常调的是学习率、LoRA rank、kl_coef。分布式基于 Accelerate：单机 2–8 卡用 DDP（每卡一份完整模型，数据切分）；大于 7B 用 DeepSpeed ZeRO-2 或 ZeRO-3（切分优化器状态、梯度乃至参数）；多节点用 ZeRO-3 + Offload。训练脚本本身不用改，换配置文件和启动命令即可。

你知道 DeepSeek 的 GRPO 吗？它和 PPO 的主要区别是什么？优劣是什么？Extra01 · RLHF 第 10 题

      
    
        
  • 核心区别：PPO 用价值模型估计优势；GRPO 对同一问题采样一组回答，用组内奖励的均值（通常再除以标准差）做基线，去掉了价值模型。
    • 
        
  • 优点：少一个与策略同规模的模型，显存与工程复杂度下降；组内相对比较方差小；特别适合有可验证奖励的任务（数学、代码）。
    • 
        
  • 缺点：每题要多次采样，生成开销大；组内全对或全错时优势为 0，没有学习信号；奖励只在序列末尾，信用分配粗。
    • 
        
  • 补充：仍保留 KL 约束（或放进 loss），原式也保留了 PPO 的 clip；原书公式是简化写法。
    • 
      

    

    

      
如何解决信用分配问题？token 级和序列级奖励有何不同？Extra01 · RLHF 第 12 题

      
    
        
  • 问题：只在最后判对错时，不知道是哪一步推理或哪次工具调用带来了成功或失败。
    • 
        
  • 序列级：整条回答一个分，简单、不易被钻空子，但信号稀疏、方差大（GRPO 默认如此）。
    • 
        
  • token / 步骤级：每步给分（如原书例子里工具调用成功 +0.1），信号密集，但需要过程奖励模型或规则，容易被奖励黑客利用。
    • 
        
  • 手段：价值函数与 GAE、过程奖励模型（PRM）、按步骤的中间奖励、对多轮轨迹做回合级折扣。
    • 
      

    

    

      
什么是 RLAIF？它的潜力和风险分别是什么？Extra01 · RLHF 第 13 题

      
    
        
  • 定义：用强 AI 模型代替人类给候选回答打分或排序，再训练奖励模型或直接做偏好优化。
    • 
        
  • 潜力：成本低、速度快、可规模化，原书称效果接近甚至超过 RLHF；评审标准可以写成显式的原则（宪法式）。
    • 
        
  • 风险：继承并放大评审模型的偏见（偏好长回答、偏好自己的风格）；评审模型被钻空子；与真实人类偏好脱节。需要人工抽检、多评审交叉和对抗测试。
    • 
      

    

    

      
有微调过 Agent 能力吗？数据集怎么收集？Extra01 · Agent 第 13 题

      
    
        
  • SFT 数据：用强模型在目标环境里跑出成功轨迹（含思考、工具调用、观察），过滤掉失败和格式错误的，统一成训练模板；也可以从线上日志中挑人工确认过的好轨迹。
    • 
        
  • RL 数据：只需要任务和可验证的成功标准（测试用例、标准答案、环境状态），让模型自己探索。
    • 
        
  • 流程：先 SFT 学格式和工具调用协议，再 RL 提升成功率；评估看任务成功率、步数、工具调用正确率、格式正确率，并做错误分类。

回扣开头的三个问题
先自己答，再点开

  

    
1. PBRFT 与 Agentic RL 的区别？为何先 SFT？
PBRFT 的状态只有 prompt，T = 1，无状态转移，只有终局奖励，优化单个回答；Agentic RL 的状态包含历史观察 (prompt, o1, …, ot)，T ≫ 1，行动含文本与工具调用，状态随行动演化，奖励可稀疏可密集，优化轨迹的累积折扣奖励。先 SFT 是因为预训练模型输出没有结构、无法提取答案和计算奖励；SFT 教会格式和基本推理，建立基线、缩小 RL 的探索空间。

    
2. 三种奖励怎么算？奖励黑客？
准确率：答对 1 答错 0。长度惩罚：答对时 1 − α · max(0, l − ltarget)，答错为 0。步骤奖励：答对时 1 + β · s，答错为 0。组合时 r = racc − α · max(0, l − ltarget) + β · s。奖励黑客是模型找到拿高分的捷径却没真正完成任务，如为步骤奖励堆砌空洞的“Step”、为长度惩罚只输出一个数字；对策是附加奖励只在答对时生效、给附加项设上限、人工抽检、多指标监控。

    
3. GRPO 为何不需价值模型？KL 与奖励怎么看？
GRPO 对同一问题采样一组回答，用组内平均奖励做基线，ri − r̄（常再除以标准差）代替优势函数，因此不需要价值模型，只保留策略与参考模型。平均奖励应逐渐上升，先升后降警惕过拟合或奖励崩塌；KL 应在 0.01–0.1，大于 0.5 说明偏离过远需增大 kl_coef 或降学习率，小于 0.001 说明几乎没更新；kl_coef 建议 0.05–0.1。
