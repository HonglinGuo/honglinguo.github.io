从 KL 正则目标到 DPO 损失

原文 docs/chapter17_dpo/dpo-objective-derivation.md（14.1 节）、dpo-theory-and-family.md“DPO 推导三步走”

原文先把后训练的三种数据形态摆出来：预训练是纯文本（学会续写），SFT 是问答对（“好回答长什么样”），对齐阶段是 (prompt, chosen, rejected) 三元组（“好回答比坏回答好在哪”）。SFT 只有正面示范：它能让好回答概率变高，却不保证远离坏回答——原文的例子是模型学会了礼貌，却在用户说“学数学没用”时盲目附和（谄媚）。偏好对的对比结构信息密度更高：DPO 通常几千到几万条偏好对就能明显改变行为。

推导的起点就是 RLHF 的目标：max 𝔼[r(x, y)] − β·KL(π ‖ πref)。第一步，这个约束优化问题有闭式解：π*(y|x) = πref(y|x)·exp(r(x,y)/β) / Z(x)——最优策略就是在参考策略上按 exp(r/β) 重新加权。第二步，两边取对数反解奖励：r(x,y) = β log(π*(y|x)/πref(y|x)) + β log Z(x)。Z(x) 要对所有可能回答求和，算不出来——但它只依赖 x。第三步，代入 Bradley–Terry：只关心同一个 x 下两个回答的奖励差，β log Z(x) 正好相减抵消。

于是 LDPO = −log σ(β log(πθ(yw)/πref(yw)) − β log(πθ(yl)/πref(yl)))。原文对“为什么用比值而不是绝对概率”的解释很直观：两个模型对同一回答都受“生成难度”（罕见词多则概率低）影响，相除后难度被约掉，只剩训练带来的变化。整个过程只需要策略模型和一份冻结的参考副本：TRL 的 DPOTrainer 只传一个 model，内部自动复制参考模型。

逐步看推导；再拖动 β，看最优策略怎样在参考策略上重新加权。

推导三步走

  1. RLHF 目标（KL 正则）
    max_π 𝔼_{y~π}[r(x,y)] − β·KL(π(·|x) ‖ π_ref(·|x)) = max_π 𝔼_{y~π}[r(x,y) − β log(π(y|x)/π_ref(y|x))]
  2. 闭式解：在参考策略上按 exp(r/β) 重新加权
    π*(y|x) = π_ref(y|x)·exp(r(x,y)/β) / Z(x)，Z(x) = Σ_y π_ref(y|x) exp(r(x,y)/β)
  3. 反解奖励：奖励 = 对数概率比 + 只依赖 x 的常数
    r(x,y) = β log(π*(y|x)/π_ref(y|x)) + β log Z(x)
  4. 代入 Bradley–Terry：同一 x 下取差，β log Z(x) 抵消
    r(x,y_w) − r(x,y_l) = β log(π*(y_w|x)/π_ref(y_w|x)) − β log(π*(y_l|x)/π_ref(y_l|x))
  5. 用 π_θ 代替 π*，最大化偏好似然 = DPO 损失
    L_DPO = −𝔼 log σ(β log(π_θ(y_w)/π_ref(y_w)) − β log(π_θ(y_l)/π_ref(y_l)))

DPO 损失、隐式奖励与 β

原文 dpo-objective-derivation.md 14.1.4.2、metrics.md（14.2）、dpo-hands-on.md 14.4.4

损失括号里的两项叫隐式奖励：rchosen = β log(πθ(yw)/πref(yw))，rrejected 同理；两者之差就是 Reward Margin。它们不是真的 RM 打分，而是从概率比推出来的。训练开始时 πθ = πref，margin = 0，σ(0) = 0.5，所以 loss 从 ln 2 ≈ 0.693 开始——原文日志第 5 步是 0.6821。梯度的大小正比于 σ(−margin)：模型已经分得很开的样本几乎不贡献梯度，还没分开（或分反了）的样本梯度最大。

附录 B.3 的速记：“4 条 logp（2 个模型 × 2 个回答）：每条算‘当前 − 参考’；好减坏、乘 β、过 sigmoid、取负 log。”常见坑：用了 raw log-prob 而不是比值；参考模型的 logp 忘了 detach；chosen / rejected 弄反；手写 log σ 溢出（用 logaddexp 或 F.logsigmoid）。

β 是最关键的超参，作用和 RLHF 里的 KL 系数相同：控制能偏离参考模型多远。原文的经验表：0.01 几乎没有约束，快但可能语言退化；0.1 是默认；0.5 约束强、变化慢；1.0 几乎学不到东西。还有一个读日志时容易误判的现象：margin 在涨，可能是 chosen 和 rejected 的 logp 都在下降、只是 rejected 降得更多——所以 TRL 会把 rewards/chosen 和 rewards/rejected 拆开记录。

输入两条回答相对参考模型的 logp 变化，算 DPO 的每一项。

DPO 损失计算器（每条回答取整段 logp 之和）

损失随 logp 比值之差 Δ 的变化

横轴 Δ = (logπ_θ − logπ_ref)(y_w) − (logπ_θ − logπ_ref)(y_l)，不含 β。β 越大，同样的 Δ 损失降得越快——更少的偏离就能“分开”好坏回答。

算法卡 · DPO

Direct Preference Optimization（Rafailov et al., 2023）

解决什么问题
PPO-RLHF 要训 RM、四模型同台、在线采样、超参敏感。
核心做法
利用 KL 正则目标的闭式解，把奖励写成 β·对数概率比；在偏好对上直接最小化 BT 负对数似然。
关键公式
L = −log σ(β[(logπθ − logπref)(yw) − (logπθ − logπref)(yl)])
何时用
已有可靠偏好对、想快速验证数据和流程、显存有限时的首选基线。
代价与坑
离线：不能探索，上限受数据覆盖限制；偏好标错照样学进去（loss 照常下降）；Accuracy 很快到 100% 往往是过拟合；可能学到长度等表面特征。
相关
IPO / KTO / SimPO（下文）；Iterative DPO（周期性用新模型生成新偏好对）；离线 RL 的分布偏移（第 6 篇）。

DPO 家族：每次都在问“哪个组件可以安全去掉”

原文 dpo-theory-and-family.md“DPO-style 离线偏好优化家族”、附录 docs/appendix_code_cheatsheet/dpo-family.md

DPO 的局限原文列了三条：依赖数据质量（offline）、无法探索（只能看到数据里已有的回答）、偏好冲突会让它困惑。于是有一族“沿着 DPO 继续简化或修补”的方法，原文按“去掉了什么”来记：KTO 去掉成对数据——只要单条回答的点赞 / 点踩（生产日志里几乎免费），借前景理论对坏样本罚得更重（λU > λD），用一个基线 zref 把好样本推上去、坏样本压下来；SimPO 去掉参考模型——用长度归一化的平均 logp 当隐式奖励，并减一个目标 margin γ，省一个完整模型的显存，也消除了“长回答 logp 天然更低”的偏差，代价是少了安全绳；IPO 保留偏好对和参考模型，但把 −log σ 换成平方损失 (Δ − 1/(2β))²——差距达到目标就够了，不会无限拉开，小数据（原文说少于约 1000 条）下更稳。

和 PPO 比，DPO 是“看录像学开车”，PPO 是“边开边学”：DPO 不需要 RM、不需要 Critic、不需要在线采样，同时只跑 2 个模型，显存约为 PPO 的 1/2–1/4，实验迭代以分钟到小时计；PPO / GRPO 能在线探索、理论上限更高。原文的建议是项目初期先用 DPO 快速验证数据和流程，确认可行后再考虑在线方法。

选型练习

易混辨析：DPO、SFT 与 PPO-RLHF

DPO vs SFT：SFT 只拉高 y_w 的概率；DPO 要求 y_w 相对 y_l 的比值上升——如果两者概率一起涨（模型变“话多”），DPO 的损失不会下降。没有 rejected，DPO 跑不了；原文还提醒，高质量的 rejected（看似合理、实则有错的 hard negative）往往比 chosen 更难找、更重要。

DPO vs PPO-RLHF：两者优化同一个 KL 正则目标；PPO 显式训练 RM、在线生成、用 Critic 估优势，DPO 把 RM 隐含在策略里、只用固定偏好对。DPO 是 offline，PPO 是 online（第 1 篇的四种数据形态）。

隐式奖励 vs RM 分数：前者 β log(π_θ/π_ref) 由策略自身给出，训练中随策略变化；后者是独立网络的输出。

DPO 的 β vs RLHF 的 β：是同一个 β——KL 正则的系数，推导中直接继承下来。

IPO：(Δ − 1/(2β))²；SimPO：−log σ(β(logp_w/|y_w| − logp_l/|y_l|) − γ)
KTO：好样本 −log σ(β·logr − z_ref)，坏样本 −log σ(z_ref − β·logr)，λ_U > λ_D
1. DPO 凭什么跳过奖励模型？消掉的是哪一项？

KL 正则的 RLHF 目标有闭式最优解 π* ∝ π_ref·exp(r/β)，反解得 r = β log(π*/π_ref) + β log Z(x)。Bradley–Terry 只用同一 prompt 下两个回答的奖励差，β log Z(x) 只依赖 x，相减抵消；奖励差完全由两个模型的对数概率比决定，于是可以直接在偏好对上优化策略，不需要单独的 RM。

2. β 控制什么？几条指标各说明什么？

β 是 KL 正则系数：越大越不敢偏离参考模型（0.01 易跑偏、0.1 默认、1.0 几乎不动）。Loss 从 0.693 下降并趋稳；Accuracy 从 0.5 升到 0.8–0.95；Margin 从 0 上升；Chosen Reward 应升、Rejected Reward 应降——两者同升同降时要结合 margin 看，可能是两者 logp 都在降、只是降得不一样多。

3. IPO、KTO、SimPO 各改了什么？什么时候用 PPO / GRPO？

IPO 把 −log σ 换成回归到 1/(2β) 的平方损失，避免无限拉开、小数据更稳；KTO 不要成对数据，只要单条好 / 坏标签；SimPO 去掉参考模型，用长度归一化 logp 加 margin。追求上限、需要模型在线探索新回答、有可计算奖励（尤其可验证奖励）时，用 PPO / GRPO。
