把 LLM 生成写成 MDP

原文 docs/chapter15_rlhf/base-model-to-assistant.md（13.1 节）

同一套 MDP 语言可以直接套到语言模型上：状态是 prompt 加上已生成的 token (x, y<t)，动作是从词表里选下一个 token，策略就是语言模型的 next-token 分布，转移是把选中的 token 拼到上下文后面（几乎确定），回合从开始回答到 EOS 或长度上限，奖励由奖励模型 / 人 / 规则对完整回答打分。和 CartPole 最大的不同不是随机性，而是奖励来得极晚：几百个 token 只有末尾一个分数，回答得了低分，是第 3 个 token 错了还是第 80 个开始跑偏？这就是信用分配。

原教程始终比较三个版本。Base 学的是 next-token prediction：有语言、知识、代码模式，但会重复 prompt、不一定回答。SFT 在指令—回答数据上继续做同样的似然训练：学会按格式回答、模仿高质量示范——本质是行为克隆（第 6 篇）。RLHF 用偏好奖励 + PPO：更贴近偏好、少出坏回答，风险是 reward hacking、能力回退、过度迎合。

为什么 SFT 之后还要 RLHF？原文给了四个原因：SFT 只模仿单条示范，学不到“这个比那个好在哪”的偏好边界；SFT 数据覆盖不了模型自己会犯的错（分布偏移），RLHF 在模型自己生成的回答上给反馈；“更有帮助、更诚实、更安全”很难写成唯一标准答案，人却很容易比较；SFT 容易只学到表面格式。同时原文也划清了边界：RLHF 主要改变模型在已有能力空间里的选择偏好，不是知识注入的主力；reward 越高也不等于模型越好。

奖励模型：从“哪个更好”学出一个分数

原文 docs/chapter10_ppo/gae-reward-model.md“奖励模型”、chapter15_rlhf/standard-rlhf-pipeline.md

人很难给一个回答打绝对分（“87 分”），但很容易比较（“A 比 B 好”）。Bradley–Terry 模型把成对比较变成标量分数：P(yw ≻ yl | x) = σ(r(x, yw) − r(x, yl))，两个分数差越大，高分者被选中的概率越接近 1。训练损失就是 −log σ(rchosen − rrejected)。注意它只约束差值：所有回答同时加一个常数，损失不变——所以 RM 的分数只有相对意义，PPO 前通常要归一化。

原文把训练 RM 称为整个 RLHF 中“最沉重的负担”，列了三大痛点：标注成本（InstructGPT 约 40 名标注员、数万条偏好）；奖励作弊（RM 学到的可能是“看起来好”而不是“真的好”——更长、术语更多、格式更花）；分布漂移（RM 在旧策略的回答上训练，策略被 RL 改变后，新回答落在 RM 没见过的区域）。原文的思考题还提醒：RM 在训练集上“太完美”反而可能是过拟合——宁可钝一点。

主观偏好（礼貌、安全、有帮助）需要 RM；数学、代码这类有客观答案的任务可以直接用规则验证当奖励——那是第 9 篇的 RLVR。下面的实验模拟“标注员略偏爱长回答”时，一个线性奖励模型会学到什么。

算法卡 · 奖励模型（Bradley–Terry RM）

InstructGPT（Ouyang et al., 2022）等经典 RLHF 流水线的第二步

解决什么问题
“好回答”写不成规则；人给绝对分不稳定，但比较容易。
核心做法
收集 (prompt, chosen, rejected)；RM 输入 prompt + 回答、输出一个标量；最大化 chosen 比 rejected 分高的 BT 似然。
关键公式
P(yw ≻ yl) = σ(r(x,yw) − r(x,yl))；L = −log σ(rw − rl)
何时用
主观偏好对齐（有帮助、礼貌、安全）；也可作为 GRPO 的奖励函数之一。
代价与坑
标注贵、有噪声；学到长度 / 格式等表面特征；策略一变就分布外；分数只有相对意义需归一化。
相关
DPO 把 RM 隐含进策略里（第 8 篇）；RLVR 用规则验证器替代 RM（第 9 篇）；PRM 给每一步打分（第 10 篇）。

易混辨析：奖励模型 vs Critic

RM 评价完整回答“好不好”，从人类偏好训练、PPO 阶段冻结，给出的是奖励 r；Critic 评价写到一半的前缀“预计最终能拿多少”，从 RL 过程中的回报回归、和 Actor 一起更新，给出的是价值 V(st)，用来算优势。

RM 分数 ≠ 人类偏好：它是偏好的近似，策略会主动搜索它给分高、但人并不喜欢的区域。

SFT ≠ RLHF：SFT 是监督学习（标准答案），RLHF 是强化学习（偏好奖励）；两者都属于后训练，训练信号不同。

PPO-RLHF：四个模型和一条“安全绳”

原文 docs/chapter15_rlhf/ppo-rlhf-loop.md（13.9 节）

经典 RLHF 的 PPO 阶段有四个角色：Actor（从 SFT 模型继续训练，生成回答、被更新）、Reference（冻结的 SFT 模型，提供 KL 约束）、Reward Model（冻结，给回答打分）、Critic（通常从 Actor 初始化，估计价值、降低方差）。原文的一句话总结：Reward Model 给方向，Reference 拉住边界，Critic 降低方差，PPO 控制更新幅度。四个模型同时占资源，7B 模型的 PPO 至少要几张 80GB 卡——这正是 DPO 和 GRPO 想省掉的东西。

RM 只给整段一个分，PPO 却要在 token 级更新。工程上把奖励拆成两部分：每个 token 都扣一点 KL：−β(log πθ(yt) − log πref(yt))；最后一个 token 再加上 RM 分数。原文的直觉：“你可以尝试写得更好，但每一步都要为偏离原来的 SFT 模型付一点成本；只有整段完成后裁判才给总分。”然后 Critic 估计每个位置的 V，GAE 把末尾的分数沿 token 序列传回去，每个 token 得到自己的优势。

原文专门对比了序列级与token 级：序列级把总分 R 平均摊给每个 token，“答案是 21”里的“21”和开头的“这”获得同样的更新；token 级通过 Critic + GAE 让关键 token 拿到更强的信号。原文的结论是 token 级优于序列级、序列越长优势越大，TRL、OpenRLHF、veRL 默认都用 token 级损失。为什么一定要 Reference？RM 是在 SFT 模型附近的回答上训练的，Actor 离得太远，RM 就进入分布外——分布外的高分最危险，因为 PPO 会把它当真奖励继续放大。

原文的例子“这 道 题 的 答 案 是 2 1”：调 β、RM 分数和 λ，看每个 token 拿到的奖励和优势（logprob 与 V 为示意值）。

token 级奖励与优势：r_t = −β·(logπ − logπ_ref)，最后一个 token 再加 RM 分（γ = 1）

算法卡 · PPO-RLHF

InstructGPT 式三阶段：SFT → RM → PPO

解决什么问题
把人类偏好变成可优化的信号，在模型自己的回答上纠正它真实会犯的错。
核心做法
Actor 生成 → RM 打分 → Reference 算 KL → Critic + GAE 算 token 优势 → PPO 裁剪更新 Actor 和 Critic。
关键公式
rt = −β(log πθ − log πref)(yt) + 1[t = T]·rRM(x, y)；目标 𝔼[rRM] − β·KL(πθ ‖ πref)
何时用
主观偏好对齐、需要在线探索、上限要求高时。
代价与坑
四模型同台、显存和工程复杂度高；RM 被 hack；β 难调；数据非平稳（Actor 一更新下一批回答分布就变了）。

PPO 与 GAE（第 4 篇）；DPO 去掉 RM 和 Critic（第 8 篇）；GRPO 去掉 Critic（第 9 篇）。

读训练日志：reward 必须和 KL、长度一起看

原文 ppo-rlhf-loop.md“训练稳定性工具箱”“训练日志解读”、evaluation.md

原文反复强调：健康的 PPO-RLHF 不是 reward 一路狂飙，而是多个指标保持张力——reward 缓慢上升、KL 在目标区间附近波动、回答长度稳定、熵缓慢下降但不塌、value loss 可控、clip fraction 有一定比例、小样本 judge 胜率逐步改善。最典型的危险信号是“reward 上升 + KL 上升 + 长度暴涨 + 人工抽检变差”：这不是“继续训练就好了”，而是 reward hacking，应该暂停 PPO、回去查 RM 数据和长度惩罚。

β 是最关键的旋钮：太大，KL 很低、reward 不动，RLHF 几乎退化成 SFT；太小，reward 快速上升、KL 失控，出现 hacking、乱码、模式坍缩。常见做法是自适应 β：观测 KL 高于目标就拉紧，低于目标就放松。原文给的调参顺序：先固定生成参数（temperature、top_p、长度上限）→ 检查 RM 分数尺度 → 调 β 让 KL 回到目标区间 → 再调学习率和 batch → 看长度与重复率（reward 和长度强相关时先修奖励，不要只调 PPO）→ 每个 checkpoint 跑同一套固定评估集。

回扣开头的三个问题

先自己答，再点开

本篇公式卡

SFT：L = −Σ_t log π_θ(y_t | x, y_<t)
Bradley–Terry：P(y_w ≻ y_l | x) = σ(r(x,y_w) − r(x,y_l))；L_RM = −log σ(r_w − r_l)
RLHF 目标：max 𝔼[r_RM(x,y)] − β·KL(π_θ(·|x) ‖ π_ref(·|x))
token 奖励：r_t = −β(log π_θ(y_t|s_t) − log π_ref(y_t|s_t))，t = T 时再加 r_RM(x,y)
优势：δ_t = r_t + γV(s_{t+1}) − V(s_t)，A_t = Σ(γλ)^l δ_{t+l}；PPO 比率 ρ_t = π_θ(y_t)/π_old(y_t)
自适应 β：β ← β·(1 + (KL_obs − KL_target)/KL_target / horizon)
1. SFT 之后为什么还要 RLHF？RLHF 会注入新知识吗？

SFT 只模仿单条示范，学不到偏好边界；覆盖不了模型自己会犯的错；“更有帮助 / 诚实 / 安全”难以写成唯一答案但容易比较；容易只学表面格式。RLHF 在模型自己的回答上用偏好奖励纠正它。但 RLHF 主要改变已有能力空间里的选择倾向，不是知识注入的主力；新知识要靠预训练、继续预训练、检索或高质量 SFT。

2. 奖励模型怎样从比较里学分数？最容易学歪成什么？

Bradley–Terry：P(chosen 胜) = σ(r_chosen − r_rejected)，最小化 −log σ(差值)；只约束差值，分数需要归一化。最容易学到表面特征：长度、术语、格式、讨好语气——标注员只要略偏爱长回答，RM 就会给长度正权重，策略再顺着它把回答越写越长。

3. 四个模型各干什么？token 奖励怎么构造？β 太大太小会怎样？

Actor 生成并被更新；Reference（冻结 SFT）提供 KL；RM（冻结）给完整回答打分；Critic 估计每个前缀的价值来算优势。每个 token 奖励 = −β·(log π − log π_ref)，最后一个 token 再加 RM 分，然后 GAE 传回每个 token。β 太大：KL ≈ 0、reward 不动、退化成 SFT；β 太小：KL 失控、reward hacking、乱码与坍缩。
