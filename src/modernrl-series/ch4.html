从“一步毁掉策略”到信任域

原文 docs/chapter10_ppo/trust-region-clipping.md（8.2 节）

原文全程用一个微型例子：某状态下两个动作，初始 π(a₁) = 0.6、π(a₂) = 0.4。采到 (s, a₁)，优势 A = 2，学习率 0.5，一次普通策略梯度更新就把 π(a₁) 推到 0.99。如果这个高优势只是采样的偶然，a₂ 已经被压到 0.01，而且策略更新没有撤销键。下一轮更麻烦：数据是在 0.6 下采的，现在策略已是 0.99，这批数据也不再代表当前策略。

想复用旧数据，工具是重要性采样：𝔼a~π_old[πθ/πold · f(a)] = 𝔼a~π_θ[f(a)]。比值 rt = πθ(at|st)/πold(at|st) 叫策略比率，例子里是 0.99/0.6 = 1.65。代理目标 𝔼[rtAt] 让旧数据可以评估新策略，但 r 越大梯度被放大得越多，下一步更新更大——一个正反馈循环。

TRPO（Schulman 2015）直接给距离设上限：最大化 𝔼[rtAt]，约束平均 KL(πold ‖ πθ) ≤ δ，δ 常取 0.01。例子里 0.6 → 0.99 的 KL ≈ 1.18，远超 0.01，会被拒绝。问题在计算：严格求解要用到 Hessian（参数量的平方），只能用共轭梯度近似，慢且难写；对 70B 的语言模型完全不可行。PPO（Schulman 2017）的想法是：既然目的只是“别差太远”，就不必精确测距离，直接把每个样本的比率夹在 [1 − ε, 1 + ε] 里——局部、廉价的近似，只要一个 clamp。

算法卡 · TRPO

Trust Region Policy Optimization（Schulman et al., 2015）

解决什么问题
策略梯度一步走太远会毁掉策略，且旧数据随之失效。
核心做法
最大化重要性采样代理目标，同时把新旧策略的平均 KL 限制在 δ 以内（信任域）。
关键公式
max 𝔼[rtAt] s.t. 𝔼[KL(πold ‖ πθ)] ≤ δ，δ ≈ 0.01
何时用
理论分析、需要严格控制策略变化的小规模问题；理解 PPO 的来历。
代价与坑
需要二阶信息（Hessian / 共轭梯度），慢、实现复杂，大模型上不可行；二阶近似本身也有误差。
相关
PPO-Clip、PPO-Penalty（把 KL 作为惩罚项）；RLHF 里的 KL 惩罚（第 7 篇）。

裁剪目标：clip 管“顺方向别过冲”，min 管“反方向要纠偏”

原文 trust-region-clipping.md“裁剪为何让梯度归零”“min 操作的作用”

PPO-Clip 的目标是 L = 𝔼[min(rtAt, clip(rt, 1 − ε, 1 + ε)At)]。clip 是一条三段折线：两端水平（斜率 0）、中间斜率 1。链式法则里只要中间这一环是 0，整条梯度链就断了——这就是“目标在该区间变成常数”的确切含义：相对 θ 是常数，不是数值不变。

只有 clip 会出问题：好动作（A > 0）的比率反而跌到 0.5（更新方向错了），裁剪项斜率仍是 0，策略会被卡死在错误的位置。外层的 min 解决这件事：它总挑数值更小（更悲观）的那一项，而 clip 的算术结构恰好让“更悲观”等于“方向正确”。原文把四种越界情形逐一验证，并给出一个简短证明：∂L/∂r 只可能是 0 或 A，梯度要么停止，要么与优势同号，永不反向。把 min 换成 max 则两种情形同时失效：顺方向越界时不砍虚高的奖励，反方向越界时还高估错误方向。

ε 的经验取值：游戏和控制默认 0.2；LLM 对齐常用 0.1 甚至更小（参数多、更脆弱，一次坏更新可能丢掉已习得的语言能力）；0.5 原文直接说“不推荐”。原文还提醒：裁剪只约束每个样本的比率，并不直接约束整体 KL，所以 LLM 训练里会同时监控 clip_fraction 和 approx_kl。

易混辨析：PPO 与 TRPO、clip 与 KL

PPO vs TRPO：同一个目标（别让一次更新走太远）。TRPO 用整体 KL 做硬约束、需要二阶近似；PPO 对每个样本的比率做一阶裁剪，一个 clamp 搞定。原文：OpenAI 的实验里 PPO 多数任务与 TRPO 相当甚至更好，而 TRPO 的二阶近似本身也有误差。

PPO-Clip vs PPO-Penalty：后者把 β·KL 作为惩罚项加进目标、β 自适应调节；实践中 Clip 更常用。

裁剪 ≠ 约束了 KL：clip 只管单个动作的比率，所有样本都推到边界时整体分布的变化仍可能超标，所以要同时监控 approx_kl。

policy loss 取 min，value loss 取 max：值裁剪版本的价值损失是 max((V − R)², (V_clip − R)²)，同样是“取更保守的”，方向相反，附录 B.2 把它列为高频易错点。

为什么同一批数据能用 K 轮

原文 ppo-math.md 思考题三；实验为本笔记自设

PPO 默认用同一批 rollout 更新 K = 10 个 epoch、每个 epoch 切成若干 mini-batch。原文的解释是成本权衡：采一批数据要跑环境（LLM 里要生成几分钟），一次梯度更新只要几秒。但从重要性采样的角度看，只有第一轮是无偏的，后面 θ 离 θ_old 越来越远，估计偏差越来越大——裁剪正是为此设计的：偏离过大时梯度自动归零。所以 K 不能无限加大，原文给的常用范围是 3–10。

为了直接看到裁剪在“复用”里的作用，我设了一个小实验：五臂老虎机（期望奖励 1.0、1.3、0.7、1.1、0.9，每次加标准正态噪声），softmax 策略。每轮按当前策略拉 32 次，优势 = 奖励减批内均值，然后比较三种更新：普通策略梯度只更新 1 轮；同一批数据不加裁剪更新 K 轮；PPO 裁剪后更新 K 轮。每种跑 100 个种子。

GAE：在 TD 与 MC 之间连续调节

原文 docs/chapter10_ppo/gae-reward-model.md（8.3 节）

PPO 目标里的 At 怎么来？原文用一个 5 步回合贯穿（只有最后一步奖励 1，Critic 估计 V = 0.1, 0.2, 0.3, 0.5, 0.8，γ = 1），正好是“LLM 生成 5 个 token、只在最后得分”的微缩版。TD 估计 A = δt，只用一步：方差小，但 Critic 不准时偏差直接灌进来，早期步骤的优势被压成 0.1。MC 估计 A = Gt − V(st)：无偏，终点奖励直接算回每一步（早期 0.9），但带着整段的随机性，还得等回合结束。

原文强调一个容易忽略的事实：Gt − V(st) = Σγkδt+k——MC 不是和 TD 并列的另一种信号，而是 TD 误差的无限累加。所以插值应该作用在 δ 的权重上：wk = (γλ)k。λ = 0 回到 TD，λ = 1 回到 MC，中间指数衰减。指数形式的好处是可以递推：Ât = δt + γλÂt+1，从后往前扫一遍，O(N)。

λ 怎么选？原文的思考题给了一个关键视角：如果 Critic 完全是随机噪声，λ = 0 的优势就毫无意义，而 λ = 1 退化成“带噪声基线的 MC”，主体信号还在。所以较大的 λ 对 Critic 质量的依赖更弱；代价是方差。0.95 成为默认值，就是在“Critic 准不准”和“采样噪声大不大”之间取的平衡。

算法卡 · GAE

Generalized Advantage Estimation（Schulman et al., 2016）

解决什么问题
优势估计的偏差—方差两难：TD 依赖 Critic、MC 方差大且要等回合结束。
核心做法
对后续 TD 误差做 (γλ)k 指数加权，倒序递推；在 done 处切断。
关键公式
Ât = Σk(γλ)kδt+k = δt + γλ(1 − done)Ât+1；returns = Â + V
何时用
PPO / A2C 的默认优势估计；LLM 的 PPO-RLHF 用它把末尾的 RM 分数传回每个 token。
代价与坑
必须倒序算；done mask 别漏；values 要有 T + 1 个（最后一个是 bootstrap）；优势通常再做 batch 内归一化。
相关
GRPO 不用 GAE：奖励只在末尾、又没有 Critic，多步 TD 退化为单步（第 9 篇）；VAPO 又把 value + GAE 请了回来。

总损失、超参，以及在浏览器里跑一遍 PPO

原文 ppo-math.md“PPO 损失函数”；代码 code/chapter01_cartpole/2-pytorch_ppo.py

PPO 的总损失三项：L = LCLIP + c₁LVF − c₂H[π]。策略损失让好动作概率升、坏动作降、幅度受裁剪限制；价值损失让 Critic 逼近 GAE 给的 returns（更准的 V → 更准的 A）；熵奖励保持探索，取负号是因为“最大化熵 = 在损失里减去它”。原文的典型值：ε 0.1–0.2，c₁ = 0.5，c₂ = 0.01，γ = 0.99，λ = 0.95，rollout T = 2048，K = 10。完整循环：采 T 步 → GAE → K 轮 mini-batch 更新（每轮重算 r，裁剪动态生效）→ 旧策略更新为当前策略。工业框架（DeepSpeed-Chat、veRL、OpenRLHF）的结构与这份骨架一致。

算法卡 · PPO

Proximal Policy Optimization（Schulman et al., 2017）

解决什么问题
Actor-Critic 更新幅度无约束、训练震荡；TRPO 有约束但二阶计算太贵。
核心做法
重要性采样复用一批 rollout K 轮；策略比率裁剪 + min 保证“只停不反”；GAE 估优势；总损失 = 裁剪策略损失 + 价值损失 − 熵。
关键公式
L = −𝔼[min(rtAt, clip(rt, 1 − ε, 1 + ε)At)] + c₁(V − R)² − c₂H，r = exp(logπ − logπold)
何时用
默认的 on-policy 算法：游戏、连续控制、经典 RLHF；仿真便宜、追求稳定时。
代价与坑
仍是 on-policy，样本效率低；LLM 上要四个模型同台（第 7 篇）；ratio 分母必须是采样时的旧策略、old_logp 要 detach、GAE 要倒序。
相关
TRPO、GAE（本篇）；PPO-RLHF（第 7 篇）；GRPO = 去掉 Critic 的 PPO（第 9 篇）。

本篇公式卡

重要性采样：𝔼_{π_old}[(π_θ/π_old)·f] = 𝔼_{π_θ}[f]；r_t(θ) = π_θ(a_t|s_t) / π_old(a_t|s_t)
TRPO：max 𝔼[r_t A_t] s.t. 𝔼[KL(π_old ‖ π_θ)] ≤ δ
PPO-Clip：L^CLIP = 𝔼[min(r_t A_t, clip(r_t, 1−ε, 1+ε) A_t)]；∂L/∂r ∈ {0, A}
PPO-Penalty：𝔼[r_t A_t − β·KL(π_old, π_θ)]
GAE：Â_t = Σ_k (γλ)^k δ_{t+k} = δ_t + γλ(1 − done_t) Â_{t+1}；returns = Â + V
总损失：L = L^CLIP + c₁(V_θ(s) − V^targ)² − c₂ H[π_θ]，c₁ = 0.5，c₂ = 0.01
1. TRPO 和 PPO 解决同一个什么问题？为什么工业界都选 PPO？

都在限制单次更新让策略变化多少，防止一步毁掉策略、让旧数据可以安全复用。TRPO 用 KL 硬约束，要二阶近似（共轭梯度），慢且难写，大模型不可行；PPO 用逐样本的比率裁剪做一阶近似，一个 clamp 就实现，效果多数任务相当甚至更好。

2. min 为什么不能换成 max？梯度什么时候为零？

min 总选更悲观的一项：顺方向越界（A > 0 且 r > 1+ε，或 A < 0 且 r < 1−ε）时选裁剪项，梯度为 0，停止过冲；反方向越界时选未裁剪项，梯度为 A，把策略拉回来。∂L/∂r ∈ {0, A}，永不反向。换成 max 会放任过冲、还会奖励错误方向。

3. λ 从 0 到 1 优势怎样变？为什么默认 0.95？

λ = 0 只用一步 δ（TD）：方差小、完全依赖 Critic、早期步骤几乎拿不到终点奖励的信号；λ = 1 是 G − V（MC）：无偏、方差大。中间按 (γλ)^k 加权，λ 越大信用回传越远。0.95 偏 MC 一侧：对不准的 Critic 更鲁棒，又比纯 MC 方差小。
