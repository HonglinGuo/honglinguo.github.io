本篇要回答的 3 个问题

  1. 拿到一张模型配置表，怎样算出参数量、一次 prefill 和一次 decode 的 FLOPs？

从矩阵尺寸到参数量和 FLOPs

原书 2.1 节

所有估算都从一条规则开始：m 个 token 每个 k 维，乘一个 k×n 的权重，NW = kn，F = 2mkn，MW = bWkn。m 翻倍，运算翻倍、权重不变（同一模型处理更多输入）；n 翻倍，两者都翻倍（层变宽了）。Qwen3-8B 有 36 层，隐藏维度 4096，FFN 中间维度 12288，32 个查询头、8 个 KV 头、每头 128 维，词表 151936。每层 Q、O 投影各 4096×4096，K、V 各 4096×1024，SwiGLU 三个矩阵各 4096×12288，合计每 token 每层线性运算 385,875,968 FLOPs，其中 FFN 约占 78%。

注意力的 QKT 和 AV 不随参数走，而随查询—键配对数走：已有 S 个 token、新输入 P 个时，Npair = B(PS + P(P+1)/2)，一个长方形加一个三角形；每对每个查询头约 4dh FLOPs，Qwen3-8B 每层 16384·Npair。所以 prefill 长度翻倍，投影行数翻倍，注意力配对约翻四倍；而把一条长输入拆成两条短输入，跨越分界的配对就消失了。保持 BP 不变，只能保持投影不变。

全模型：F = 36(385,875,968·m + 16,384·Npair) + 2·mout·4096·151936。8192 token 的 prefill 约 133.6 TFLOPs；已有 8192 token 再补一个 token 约 20.0 GFLOPs。KV 缓存省掉的是旧 token 的投影和 FFN 重算，当前查询和上下文的注意力仍要算。

KV 缓存：存得不多，读得很多

原书 2.2 节

因果模型里旧 token 看不到后来的 token，所以旧 token 的 K、V 可以保留：把“重算旧 token”变成“保存并读取旧状态”。每个上下文 token 的 KV：cKV = 2·L·nKV·dh·bKV，Qwen3-8B BF16 是 2×36×8×128×2 = 144 KiB，8192 token 即 1.125 GiB。数据按生命周期分三类：权重（多次调用间不变）、上下文状态（随请求追加）、临时数据（用完即释放）。

一批请求共享权重读取，但上下文各读各的。上下文读取超过权重读取的 batch：B* = RW / (cKVH)，Qwen3-8B 权重读取约 15.14 GB，8K 上下文时 B* = 13，2K 时 51。上下文越长，批内复用的收益越早被抵消。

完整回答：prefill 后执行 nd = G − 1 次 decode，第 j 次要读 H + j 个旧 token，累计读取 Rold = cKV[ndH + nd(nd−1)/2]。原书例题：输入 8192、返回 1025 个 token，累计读 KV 约 1224 GiB，而结束时只保存约 1.27 GiB，近千倍。原因是每个进入上下文的 token，后面每次 decode 都要再读一遍。

上下文状态：每 token 存多少，每步读多少

原书 2.3 节

原书用两种记录办法打比方：逐页留记录（按 token 存 K、V，随历史增长），或只留一张不断改写的定长摘要（递推状态）。减少状态的手段各改一个量：GQA / MQA 减少 KV 组数（Qwen3-8B 四个查询头共用一组 KV，若每头单独存是 4 倍，全部共用是 1/8），但查询头仍各自打分，注意力运算不按比例下降；MLA 降低每 token 的表示宽度，靠结合律 qKT = (qUkT)cT 只存潜变量，Kimi K3 的 24 层 MLA 在 8K 下紧凑路径 216 MiB，展开路径约 11.25 GiB；窗口 + 压缩 + 稀疏索引（DeepSeek V4-Flash 的 CSA 4:1、HCA 128:1、窗口 128）减少条目数，但索引扫描仍要遍历所有压缩索引条目；线性注意力 / 递推（Kimi 的 KDA）状态大小固定，K3 69 层 FP32 共 414 MiB，但每步要一读一写 828 MiB。

混合结构的容量：Mstate(H) = Mfixed + cstate·H，两部分相等处 H* = Mfixed/cstate：Qwen3.6 固定 61.875 MiB、每 token 20 KiB，H* = 3168；Kimi K3 固定约 433.4 MiB、每 token 27 KiB，H* 约 16.4K。低于交点缩短上下文省不了多少，远高于交点才该减小每 token 宽度。DeepSeek V4.1 Flash 再进一步：40 层里只有 4 层有独立全局 KV（3 层 2:1 压缩、1 层 1:1），FP4 主记录 288 B + 索引 68 B，平均每 token 890 B，V4-Flash 是 3514.25 B，Qwen3-8B 是 147,456 B。

MoE：保存的参数和读取的参数是两回事

原书 2.4 节

MoE 把 FFN 的参数分给多个专家，路由器为每个 token 选 top-k 个。每层保存 E·Ne 个路由专家参数，每 token 只做约 2ktopNe 的专家运算。Qwen3.6-35B-A3B：40 层、隐藏 2048、每层 256 个路由专家选 8 个、专家中间维度 512；一个专家 3×2048×512 = 3,145,728 参数，BF16 6 MiB，每层全部专家 1.5 GiB，一个 token 选中的 48 MiB。全部文本参数约 346.6 亿，BF16 约 69.3 GB；但 8K 后一步 decode 只要约 7.33 GFLOPs，比 Qwen3-8B 的 20.0 还少。

一批 token 同时路由时，运算看分派总行数，读取看实际访问了多少个不同专家 U：Fexpert = 2Ne·B·ktop，Rexpert = bW·Ne·U。原书例题 2-4：B = 64，共 512 次分派；均匀分到 256 个专家（每个 2 行），每层读 1.5 GiB；集中到同一组 8 个专家（每个 64 行），每层只读 48 MiB，相差 32 倍，运算量却完全一样。专家放在不同卡上时，还要把 token 发过去、把结果收回来（第 6、9 篇）。

网络形状：深度、专家粒度、残差和 MTP

原书 2.5 节

稠密主干参数大致正比于 L·d²：隐藏维度减半、层数增至四倍，参数相近，但逐层依赖链长四倍。专家也能等价变形：单层路由专家总参数 3Edf、单 token 运算 6ktopdf，把 E 减半、f 加倍、ktop 减半，两者都不变，但矩阵变成更少更大的块，路由器参数和每专家接收行数都会变。

连接方式决定哪些张量要同时保存：DeepSeek V4-Flash 的 mHC 把残差扩成 4 路，用 Sinkhorn 迭代归一化混合矩阵，8192 token 时混合投影约 555 GFLOPs、非矩阵约 149 GFLOPs；Kimi K3 的 AttnRes 沿深度做注意力选取浅层表示，增加的是一次前向内的临时存储，而 KV 要跨调用保留。

MTP 让一次前向给出多个候选，配合推测解码由主模型验证。设普通 decode 耗时 Td，一轮草稿 + 验证 Ts + Tv，平均得到 ḡ 个有效输出，有收益的条件是 ḡ > (Ts + Tv) / Td。原书例：Td = 20 ms、草稿加验证 30 ms，每轮 2 个有效输出时每输出 15 ms，只有 1 个时 30 ms。V4-Flash 一次 MTP 辅助计算约 1.80 GFLOPs，其中共享词表头就占 1.06。

整模型比较，和一张卡能放几条请求

原书 2.6 节

整模型只是按层类别加权求和：MW = bWΣ LgNg + 嵌入 + 输出头，F = Σ LgFg + Fhead。原书把五个模型放在同一条件下：总参数（Qwen3.6、V4-Flash、Kimi K3 的路由专家占 93%–98%）决定容量，选中的专家和注意力类型决定单次运算，上下文表示决定状态。所以 Qwen3.6 权重约是 Qwen3-8B 的四倍，单步运算反而更少；V4-Flash 权重更大，8K 状态反而因压缩更小。上下文到 1M 时差距被放大：Qwen3-8B 状态 144 GiB，V4.1 Flash 只有 3.138 GiB。V4.1 的 CED 让大部分输入只过 20 层编码器，8K prefill 从参考全层的 282.4 降到 143.9 TFLOPs。

单卡能放几条请求：Bmax = ⌊(Mdevice − Mweight − Mworkspace) / Mstate/request⌋。原书例：24 GB 的 RTX 4090 跑 Qwen3-8B BF16、预留 2 GiB，8K 上下文 4 条，16K 2 条，4K 9 条；70B 的 4-bit 方案（39.500 GB，含 scale 和高精度部分）放在 H100 上，8K 14 条，32K 只剩 3 条。反过来也能从加速器反推模型：Nmax = (C − M0 − BK) / bW，4090 留 4 条 8K 请求后 BF16 最多约 85.1 亿参数。
