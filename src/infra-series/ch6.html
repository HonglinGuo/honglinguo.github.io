本篇要回答的 3 个问题

  1. 六种并行方式各切哪个维度，各自换来什么、付出什么通信？
  2. TP 卡数翻倍，什么时候就不再划算了？
  3. 四个 128K 会话、八张卡、130 ms 期限，该怎么部署？出一次故障成本涨多少？

五个维度，六种切法

原书 6.1.4、6.2 节

用更多卡通常出于三种需求：权重放不下（容量）、单请求太慢（延迟）、请求太多（吞吐）。一层的输入有三个维度——样本 B、序列位置 S、特征 H；模型本身还有层 L 和 MoE 的专家集合 E。六种并行方式就切在这五个地方。

原书用俄罗斯套娃来理解它们的组合：最外层 DP 决定同时推进多少份独立工作，PP 把连续的层交给不同阶段，进入某一层后 EP 按专家分布、TP 按特征拆矩阵、SP 和 CP 按序列位置分摊。DP2×PP2×TP4 就是 16 张卡；在同一个 TP4 组里再开 SP，卡数不变。

还有一个贯穿全章的区分：沿样本、位置、层、专家切时，各卡负责不同数据，结果靠收集或阶段交接；沿特征切时，各卡贡献同一个输出的一部分，后面必须先求和。这就是第 5 篇单卡里输出维和归约维的跨卡版本。

把这些切法和它们的通信对上号。

先算容量：放得下，才谈快慢

原书 6.1.2 节

每张卡要同时装下权重、KV、激活和工作区：Wi + Ki + Ai + Ui ≤ Ci。贯穿算例是 HGX H100（8 × H100 SXM，80 GB、3350 GB/s、989.4 TFLOP/s，NVLink 每方向 450 GB/s）上的 Qwen3-235B-A22B：94 层、隐藏 4096、64 个查询头、4 个 KV 头、头维 128，每层 128 个路由专家选 8 个、中间维 1536。

BF16 权重约 470.2 GB，每 token KV = 2×94×4×128×2 = 188 KiB，8192 token 约 1.58 GB，加 2 GiB 工作区，单卡要 473.9 GB——接近一张 H100 的六倍。分到八卡后每卡约 61.50 GB（权重比八分之一略多，因为归一化参数和路由器每卡都有一份），整机 492 GB，还剩约 148 GB，每卡剩下的 18.5 GB 够再放 47 个 8192 token 的会话。

速度也先看读取：一层选中的 8 个专家权重 288 MiB，读一遍 90.1 μs，而矩阵只要 0.31 μs——单 token decode 的 MFU 上限只有约 0.3%，与实现好坏无关。全模型一个 token 要读 43.1 GB 权重 + 1.58 GB KV，单卡 13.3 ms，均分八卡 1.73 ms。

先猜每卡要多少 GB，再改卡数和上下文。

KV 按 188 KiB/token；TP 卡数超过 4 个 KV 头后 KV 开始复制，这里按原书八卡分法每卡保存全部 KV 的四分之一（卡数 ≥ 4 时按 1/4，否则按 1/卡数）。

张量并行：本地时间除以 p，通信时间乘上去

原书 6.2.2、6.4.2 节

按权重的列切，各卡算出不同的输出元素，拼接即可；按行切，各卡只有部分和，必须相加。SwiGLU 的两次投影正好首尾相接：上投影按中间维切列，下投影按中间维切行，于是 Y = Z₀Wd,0 + Z₁Wd,1，要一次 AllReduce（或 ReduceScatter，若下游能继续用分片）。注意力按头切，输出投影同样得到部分和。Qwen3-32B 每层两次归约，64 层共 128 次。

所以时间模型是 T(p) = Tlocal/p + 128·TAR(p)，Qwen3-32B 的 128K 会话 Tlocal ≈ 29.35 ms（权重 63.97 GB + KV 34.36 GB，按 3350 GB/s）。卡数从 p 翻到 2p 划算的条件：128·[TAR(2p) − TAR(p)] < Tlocal/(2p)。p 越大右边越小。

环形 AllReduce：T = 2(n−1)α + 2(n−1)M/(nB)。10 KiB、α = 0.822 μs（MSCCL++ 在同款八卡 H100 上实测的 NVLink 单向延迟）、B = 450 GB/s 时，TP8 一次归约 11.55 μs，其中 11.51 μs 全是启动——把带宽翻倍整步只省 2.5 μs，把每轮开销减半能省 0.74 ms。

还有一条硬约束：头是分配的最小单位。Qwen3-32B 只有 8 个 KV 头，TP16 时两张卡共存同一个 KV 头，每卡读的 KV 不再减少；本地时间只从 3.67 降到 2.48 ms，而跨服务器归约实测 32.74 μs/次，TP16 单步 6.67 ms，反而比 TP8 的 5.15 ms 慢。

集合通信：环还是树，交点在哪

原书 6.4 节

四种操作按“开始时各卡有什么、结束时各卡有什么”区分：AllReduce（部分结果 → 完整结果）、ReduceScatter（部分结果 → 结果的不同分片）、AllGather（不同分片 → 完整拼接）、All-to-All（发往不同目的地的数据 → 各源卡发给本卡的）。AllReduce = ReduceScatter + AllGather。MoE 的 combine 还包括恢复 token 顺序和按路由权重求和，不能当成 AllReduce。

环形：2(n−1) 轮，每卡发 2(n−1)M/n；树形：T = 2log₂n·(α + M/B)，轮数少但关键路径上每轮传完整张量。八卡 10 KiB 时环 11.55 μs、树 5.07 μs；换成 80 MiB（8192 token），环 0.34 ms、树 1.12 ms。交点约在 680 KiB。

测量 NCCL 要分清两种带宽：algbw = M/T，busbw = 2(n−1)M/(nT)。原书例：两台 HGX H100 共 16 rank、每卡 64 MiB AllReduce 用时 466.1 μs，algbw 143.99 GB/s，busbw 269.98 GB/s。busbw 是归一化指标，不能当成每张网卡的实际吞吐。

通信还会和计算抢资源。原书用 Gloo 在 4 个 CPU 进程上做实验：4 MiB 归约单独 2.67 ms，与矩阵乘同时跑变成 6.14 ms，但整组仍是 11.58 ms（被计算掩盖）；64 MiB 时通信 36.92 → 45.21 ms、计算 11.03 → 12.89 ms，分开共 48.0 ms，同时跑只省 2.7 ms——不能把各自单独测的时间直接相减。

MoE：批内复用省读取，负载不均拖时间

原书 6.2.6、6.3.2 节

专家并行把不同专家放到不同卡上，dispatch 把 token 送到专家所在卡，combine 把结果送回并按路由权重合并（y = a₁y₁ + a₆y₆）。按目的卡发送而不是按专家发送能省一半：一个 token 选中的 8 个专家若两两分布在 4 张远端卡上，4096 维 BF16 输入 8 KiB，逐专家发 64 KiB，按卡发只要 32 KiB。

一批 token 选中多少个不同专家，直接决定权重读取。均匀随机时的期望是 E[Eactive] = E·[1 − (1 − k/E)m]：E = 128、k = 8、m = 8 时约 52 个活跃专家，读约 1.8 GiB；若 8 个 token 全选同一组 8 个专家，只读 288 MiB。64 个 token 均匀覆盖 128 个专家要读 4.5 GiB，集中时 288 MiB，相差 16 倍而运算量相同。

但读得少不等于快：在 TP2×EP4 布局里，均匀覆盖时每组承担 128 次分派；8 个活跃专家全落在一个组时，该组要扛全部 512 次，计算量是均匀时的四倍，另外三组干等。decode 看权重读取，prefill 看最忙的那个专家组。原书的建议是把热点专家分散到不同 EP 组：既保留批内复用，又减轻单组负担。

原书还给了一个“用容量换通信”的布局：TP2×EP4 下让四个专家组都对同一请求做注意力，各自保存该请求的 KV，于是专家输入就在本组，不用跨组 dispatch。代价是每卡权重 64.8 GB（八卡 518.6 GB，比每参数存一份多 48.4 GB），8192 token 的 KV 每卡 752 MiB，八卡共 5.875 GiB，是该请求实际 KV 的四倍。

流水线并行：利用率 b/(q + b − 1)

原书 6.2.5 节

按层分阶段，阶段之间传激活。q 个阶段、每阶段 t、b 个互不依赖的 micro-batch：T = (q + b − 1)t，η = b/(q + b − 1)。四阶段四个 micro-batch 利用率 4/7 ≈ 57%，十六个时 16/19 ≈ 84%。

阶段不均会积压：四阶段分别 1、1、2、1 ms 时，首个 micro-batch 5 ms 完成，之后最快每 2 ms 一个，上游缓冲满了就得暂停。自回归的麻烦在于：同一会话未来的四个 token 是一条依赖链，不是四个 micro-batch；四个独立会话才能提供四个 micro-batch。

拓扑：环面还是交换网络

原书 6.5 节

64 张卡、每卡六个端口（每方向 50 GB/s，TPU v4 的 ICI 配置）有两条路线：排成 4×4×4 三维环面，端口接邻居；或者端口全接交换芯片。

跳数：环面最远六跳（经 5 颗中间芯片），交换网络两条链路加一次转发（经 1 颗）。按 UALink 2.0 给 128 lane 交换芯片设定的 200 ns 空载延迟目标，环面每次多 0.8 μs；Qwen3-32B 的 128 次归约就多约 0.10 ms，约为八卡 TP 全部归约 1.48 ms 的 7%。

流量模式才是关键。沿维度的归约（把 AllReduce 拆成 x、y、z 三个方向），环面六条链路同时工作，和交换网络一样快。但均匀 All-to-All（MoE 的 dispatch）：环面每份数据平均走三跳，64 卡各发 M 字节，全网承载 3×64M，分摊到 384 条有向链路每条 M/2；交换网络每卡六个端口各分 M/6。M = 32 MiB 时环面约 336 μs、交换约 112 μs，差三倍；512 卡环面平均六跳，差六倍。

硬件代价：64 卡环面 192 条链路、零颗交换芯片；交换网络 384 条链路 + 6 颗 64 端口交换芯片。CloudMatrix384 为 384 个 NPU 用了 448 颗交换芯片（48 个节点各 7 颗一级，7 个子平面各 16 颗二级）。

供电和散热还卡着规模：N ≤ g·⌊(Pb − P₀)/Ps⌋。DGX H100 整机 10.2 kW（平均每卡 1.275 kW，而单卡 TDP 只有 700 W），120 kW 预算最多 11 台 88 张卡。风冷机柜 ASHRAE 给的参考是 40–50 kW 要 5000 cfm 风量而最好的地板送风口只有 1900 cfm，50 kW 机柜风扇本身就要 5 kW；按 40 kW 阈值，一个机柜只能放 3 台 DGX H100（24 卡、30.6 kW）。

UB：连接状态决定能连多少台主机

原书 6.5.5、6.6 节

UB 把事务层（Jetty：提交、接收、完成通知的端点抽象）和传输层（TP Channel：序号、确认、重传、拥塞控制）分开，多个应用端点可以共用一条传输通道。传统 RDMA 的可靠连接 QP 把两类状态绑在一起。

这个区别直接决定规模。网卡片上缓存取 256 KiB，H 台主机、每台 A 个端点：

逐对连接：S_pair(H) = 512·A²·(H−1) + 32A
端点 + 通道：S_UB(H) = 52A + 56(H−1)
缓存一致目录：W·((H−1)/8 + 8)，W = 2²⁰ 个缓存行

A = 8 时，逐对连接每加一台主机多 32 KiB，256 KiB 只装得下 8 台；端点加通道每台只多 56 B，同样的缓存能装四千多台。CloudMatrix384 的 192 台主机：逐对要约 6 MiB（缓存的 24 倍），端点加通道只要约 11 KiB。缓存装不下就得每次操作从主机内存重读，每次多两次 PCIe DMA 读取、约 1 μs。缓存一致互联（NVLink 这一类）还要维护目录，2 台主机约 8 MiB、1024 台约 136 MiB，每次写入还要给所有持有副本的对端发失效消息——这把缓存一致互联的规模限制在几十个对端，NVL72 的 72 张 GPU 正在这个范围。

建连时间也差得远：逐对连接每条要 4 次系统调用 + 1 次带外往返（按 5 μs 和 500 μs 算约 0.52 ms），N = M = 1024 时要建 1,048,576 条，串行 545 s、32 核并行也要 17 s；端点加通道只建 2048 个对象，并行后约 16 ms。每次重启和扩缩容都要重来一遍。

控制器的位置也是同一类问题：PCIe 外设网卡一次 64 B 远程读要五次穿越 PCIe，约 2.2 μs（其中 PCIe 占 1.65 μs）；接在片上总线的控制器约 0.42 μs——省下的不是压缩了原有阶段，而是那些阶段不复存在。

四个 128K 会话、八张卡、130 ms

原书 6.7 节

把前面的结果合起来：Qwen3-32B，四个会话各已有 131,064 个上下文 token，都要再生成八个 token，期限 130 ms、至少完成 75%。

单卡连一个会话都放不下（102.03 GB > 80 GB），直接排除。剩下三种：四个两卡实例每个会话八步 119.1 ms，四个并行，119.1 ms 全完成；两个四卡实例单会话 63.8 ms，但排两轮，127.6 ms 全完成；一个八卡实例单会话最快 41.2 ms，四个会话排队，164.7 ms 才全完成、130 ms 内只完成三个。

按 Con-time = Coccupied / Non-time（占用成本含故障停顿和重做，分母只数按时完成的）：两卡 0.238、四卡 0.255、八卡 0.439 GPU·s。两卡实例最省。

注入一次故障（20 ms 时卡 0 失效、停 40 ms、从八步起点重做）：两卡和四卡方案的按时比例都还是 75%，但每个按时会话的成本翻倍（两卡 0.478、四卡 0.500 GPU·s）；八卡方案 130 ms 内只完成一个。故障被隔离在一个实例内，但占用时间延长、按时数减少，成本照样翻倍——而且两个实例若共用电源或交换机，隔离就失效了。

换条件结论就变：单会话 50 ms 期限要选 TP8（41.2 ms，TP4 的 63.8 已超时）；就算有两台服务器 16 张卡，跨服务器 TP16 要 53.3 ms 仍超时，第二台更适合跑别的实例；四会话 32K、130 ms 时 TP1 能装下却要 173.3 ms，还是选四个 TP2（88.3 ms、0.177 GPU·s）。

选部署方式，看时间线和成本。
