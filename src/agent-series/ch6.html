观察和动作的两根新轴：模态与时机

原书 6.1 节

第 1 篇说过，模型固定时最大的杠杆是扩展观察空间和动作空间。第 2 到 5 篇扩展的是它们的内容：上下文、记忆、工具、代码。这一篇扩展另外两个方向。模态决定观察和动作的形式：只读文本，还是也能听声音、看屏幕、感知力矩；只能输出 token，还是也能发声、点击、驱动关节。时机决定节奏：观察是 Agent 主动去取还是世界主动推来；动作是在一个回合内做完，还是可以跨回合、被打断、被更紧急的事抢占。

原书按时间尺度排了四个场景：异步与事件驱动（秒到天，模态不变、只变时机）、语音（10 毫秒到 1 秒，边听边说）、Computer Use（亚秒到秒，屏幕在两帧之间持续变化）、机器人（毫秒，传感器连续回流，动作要分块并可被抢占）。四者共享同一组系统原语：唤醒、安全点、取消、抢占、快慢路径分离。

先把几个场景放到对应的时间尺度上。

事件驱动：取消、排队，还是并行

原书 6.2 节

同步 Agent 像只会叫号的柜台，异步 Agent 像一位秘书：桌上同时摆着邮件、电话、来访者，按紧急程度决定先处理哪个，处理到一半还能切换。技术上，所有输入（用户消息、工具结果、外部回调、定时触发）统一建模成事件流，由事件循环驱动 Agent。OpenClaw 有三种内置机制：Hooks（框架内部生命周期事件）、Cron（定时）、Heartbeat（每隔 N 分钟醒一次）。但后两种都是时间驱动的；Pine AI 打电话时客服要验证码，等下一次心跳才通知用户，客服早挂了。所以 PineClaw 加了 Channel 机制，让外部事件即时推送。原书的结论是：真正的主动服务，需要事件能主动通知 Agent。

与此配套的是第 4 篇留下的两类工具：事件触发工具（一次性和循环定时器、监控后台命令的 monitor、接外部事件源的 connect_channel）和用户沟通工具（OpenClaw 不直接把模型输出当回复，而是用专门工具发消息，所以有“活人感”）。原书还建议给 Agent 一套独立的虚拟身份（自己的邮箱电话、虚拟电脑和手机），出错只坏虚拟环境；必须用用户本人账号时，让用户通过远程桌面亲自登录。

多个事件同时到达时，按紧急度选策略。取消式用于紧急事件（“停！我说错了”）：中断当前推理和工具，清空队列，把所有事件追加到轨迹，立即重新调用模型，相当于主动制造一个安全点。队列式用于常规事件：等当前步骤到安全点（推理结束或工具返回），再把积攒的事件一次性追加。并行式用于独立的轻量查询（分析数据时被问天气）：另起一个推理会话回答，结果标记为“与主任务并行”追加回来。原书建议用一个轻量分类 LLM 做事件路由，而不是硬编码规则。

同步接口里，怎么表达“还没好”

原书 6.2 节 · 兼容方案与原生异步

很多 API 要求：assistant 发出的工具调用必须先配上 tool result，才能继续。那么工具还没返回、用户突然插话怎么办？原书给出的兼容路线是：常态下让模型看到标准的同步轨迹，只在打断时插入占位符修复格式。五条规则：已完成的 assistant 消息及时记录；工具完成时才记录真实结果；执行中被打断，就给未完成的工具生成一个明确的占位结果（“工具正在后台执行，请优先处理新事件”），再追加打断事件；没有原生续接接口时取消半截生成，不把半截输出硬塞回去；非打断事件进队列批处理。

占位符有语义风险：模型可能把“已启动”当成“已完成”，编造还没到的数据。更好的做法是从工具接口上就表达异步：用 initiate_phone_call 而不是 phone_call，立即返回任务 ID，进展通过 phone_call_connected 等事件到达。批量事件还有注意力问题：模型可能只回应最后一条，可以给每条加“[未处理事件 2/4]”标记并在末尾汇总。

另一条路是模型原生异步：截至 2026 年 9 月，GPT-6 Astra 已提供原生异步工具调用（发起和拿结果分开，等待时能做不依赖结果的事）和回合中途引导（用户在它思考时追加“预算减少了”）。但原书强调，接收到更新不等于正确使用：还要检查结果归属、任务恢复、多条更新能否综合使用；修改计划也不会自动撤销已经发生的动作。

按原书的例子走一遍：起草邮件时搜联系人，搜索还没返回，用户问天气。

语音：从轮流说话到边听边说

原书 6.3 节

说话速度约为打字的四倍，还不占手和眼。原书引用 OpenAI 对语音系统的三分法。级联：VAD 判断说完没 → ASR 转文字 → LLM 生成 → TTS 念出来，模块清晰易调试，但等待层层累加，语气和情绪在转文字时丢失。端到端 Omni：一个模型直接听音频、出语音，延迟更低、保留副语言信息，但仍按轮次，靠 VAD 猜发言权，用户报数字时停顿一下就可能被判为说完。全双工：模型持续听、持续说，自己决定继续、停顿、打断或调用工具（Moshi、Thinking Machines 的交互模型、GPT-Live）。主线是摆脱“轮流说话”和 VAD 对发言权的猜测。

级联也能优化成流式：ASR 边听边转，LLM 拿临时转录做推测执行（最终文本不同就取消重来），LLM 第一段可播报文本一出就交给 TTS，TTS 增量合成。

另一个维度是认知时序：前台要在用户在线时回应，后台可以想得更久。方案一“快思考回应、慢思考回答”会前后矛盾（快模型说买，慢模型发现缺功能）；方案二“快思考交互、慢思考提醒”更稳，但通信间接；方案三把思考和表达统一在一个端到端模型里（Step-Audio R1 的 MGRD 和双脑架构）。原书认为快慢分离有个工程优势：能直接承接慢模型的迭代红利，换个更强的后台模型即可。截至 2026 年 8 月，采用快慢分离的 Pine AI 语音 Agent 在 τ³-Voice 榜单排第一。

快慢思考的三种组织方式

Computer Use：下一步点哪里

原书 6.4 节

Computer Use 的核心是“截图 → 模型思考出一个动作 → 执行 → 等界面响应再截图”的循环。原书强调要区分“看懂界面”和“完成任务”：后者要处理页面加载、状态变化、误操作和不可逆后果，每一步之后都要重新确认现实是否仍符合计划。Anthropic 的参考实现把动作空间分成三类工具：GUI 操作（鼠标、键盘、截图、等待）、持久 bash 会话、字符串匹配的文件编辑器。

最难的是视觉定位：按钮在哪？两大思路。一是把定位变成选择题：Set-of-Mark 用分割模型在截图上切出候选区域并编号，模型只报编号；browser-use 这类 Web Agent 则从 DOM 和无障碍树里枚举可交互元素编号，更精确稳定。二是纯坐标预测（SeeClick、Claude computer use），像人一样看着截图报坐标，但对训练分辨率很敏感。原书的选择逻辑：有结构化信息就用 DOM/无障碍树索引；没有（Photoshop、Canvas、游戏）再在视觉标注和坐标预测之间选。

原书还讲了两个前沿方向：一是重新设计观察接口（只在屏幕显著变化时截关键帧、有声音时转写、把截图描述成一句话留在上下文里），让 Agent 看见两帧之间发生的事；二是 Computer Use 世界模型，在点击前预测桌面会变成什么，像人一样“推测执行”，偏离预期才停下重新观察。移动端最大的障碍则不是技术，而是生态壁垒：Agent 不看广告、不冲动消费，侵蚀了靠流量变现的平台的商业模式。

机器人：走一步，看一步

原书 6.5 节

原书用一个任务贯穿：XLeRobot 把红色杯子放进托盘、黄色废纸放进垃圾盒，最后重新观察确认。第一个关键证据是：这台几百美元的机械臂由人遥操作就能完成，说明对这个任务而言硬件不是瓶颈，算法才是。人会自然地做很多算法必须显式实现的事：靠近时减速、杯子滑动时修正、没夹住就重新看。

机器人系统按时间尺度分层：任务目标（分钟）、长程规划（先杯子后废纸）、基本技能（pick(red_cup)，约 1–3 秒）、VLA 技能策略（约 1–10 Hz 推理）、底层控制与安全层（50–1000 Hz）。模型不应直接输出任意关节角，只在 observe_scene、pick、place、verify_state、stop 这类有边界的技能里选，每完成一个就重新观察检查后置条件，失败只重试当前一步。

VLA（视觉—语言—动作模型）把“当前画面 + 技能指令”变成动作；RT-2、OpenVLA 把动作离散成 token，π₀ 直接生成连续轨迹。大模型每秒只能推理几次，控制器却要每秒几十上千次，所以用动作分块：一次生成一小段，控制线程高频执行，模型在后台准备下一段。代价是段越长越平滑，但这段时间里看到的新画面越少。VLA 回答“现在做什么”，世界模型回答“做了会怎样”：比较候选动作的后果、执行时对照预测发现偏差、训练时减少真机试错。但预测只能帮助选择，最终是否完成必须由新的观察确认。
