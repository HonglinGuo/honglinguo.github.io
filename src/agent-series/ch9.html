保存经历，不等于从经历中学习

原书 9 章引言、9.1 节

原书先厘清一个容易混淆的区别：保存经历不等于从经历中学习。把一百条轨迹放进长上下文或向量库，能帮模型找回某个案例，却不会自动完成跨案例比较：哪些步骤在成功轨迹里反复出现？哪些做法只在旧版接口上有效？某次成功是策略对了还是环境碰巧？学习发生在“评价、对照、归纳、验证”之后，而不是日志写进磁盘的那一刻。第 3 篇的用户记忆沉淀“用户与世界是什么样的”，这一篇要沉淀“在什么条件下应该怎样行动”，前者让 Agent 记得更多，后者让它从聪明变得熟练。

为什么不让模型每次任务后直接训练自己？因为生产环境很少给干净的信号：用户满意不代表合规，局部参数更新可能遗忘、漂移、安全退化，未经验证的反馈和提示注入还会被固化放大。

持续进化的起点是评估。原书把一条轨迹的评价分成三层：结果验证器回答“事情是否真的办成”（读测试、数据库、工具返回，最优先建立）；过程验证器回答“是否以允许的方式办成”（删掉失败测试也能让测试通过，口头承诺“7 天内退款”也能让用户暂时满意，这些要查规则、权限、动作序列）；质量验证器回答“是否让用户舒服”（耐心、变通、简洁，用 LLM-as-a-Judge 按 Rubric 打分并引用证据）。验证器要输出四样东西才能成为学习信号：成败等级、每个维度的结论、每条结论的证据位置、失败类型标签；证据不足时可以拒绝评分，把这个案例排除在学习集外。

把客服 Agent 的七个评价维度放进三层。

经验该写到哪里：四种载体

原书 9.2 节

学习信号只说明 Agent 该改，没说明改在哪里。原书给了四种载体。经验知识库：事实、经验规律、例外和来源，更新快、可追溯，但依赖检索和模型正确应用。Prompt 与 Skill：需要理解语境、例外和优先级、但还能用自然语言说清的判断原则，可解释、作用范围可控，但容易膨胀冲突。程序与 Harness：可确定执行和验证的流程、高风险硬约束，稳定便宜，开发维护成本高。模型参数：高维感知、生成风格、隐式策略，泛化强，更新和回归成本高。

四者常常组合：医疗影像 Agent 靠参数识别病灶，靠知识库提供最新指南，靠代码算风险指标；客服的自然语气来自后训练，企业政策由知识和 Skill 提供，关键合规由服务端代码兜底。原书强调，是否参数化不由“任务是否长期稳定”单独决定，真正决定主要载体的是能力的表示性质：能被外部符号完整表达的，就不必写进参数。

写成知识时，原始轨迹不能直接当知识单元，它又长又嘈杂。更稳妥的是三层：不可变的原始轨迹用于审计，单次运行分析记录成败和经验草案，再对多条同类轨迹做比较、聚类、归纳，形成写清适用场景、推荐策略、禁止做法、例外、证据来源和最近验证时间的 Markdown 文档。真正有迁移价值的内容来自对照：成功轨迹做了什么、失败轨迹缺了什么。Reflexion 式的自然语言反思可以参与起草，但反思本身不是证据。

给几条经验选载体。

把失败轨迹提炼成规则

原书 9.2 节 · 将经验写成指令

Karpathy 把这种做法叫系统提示学习：遇到问题后，用一句清楚的话提醒未来的自己。DSPy、OPRO、GEPA 等方法可以离线批量优化提示；生产中更适合可审计的最小 diff，而不是让模型每次重写整份 Prompt，而且待验证版本必须同时在触发失败的边界集和正常工作的保留集上测试。

原书的例子来自 τ²-bench telecom：关于转接人工，政策只有两条原则。换成较弱的模型，工具报错后 Agent 反复重试，最后转人工收场，提炼集 20 条里有 19 条如此。把这 19 条失败轨迹交给模型归纳规则、追加到政策末尾，在未参与提炼的任务上通过率从 12.3% 升到 19.3%，原本通过的任务一条没被改坏。

这个过程有三个值得记住的发现。提炼材料决定能归纳出什么：只给失败摘要，得到“同一工具反复报错就别再调”这种教训；补上双方各自的工具清单，得到“网络状态、SIM 卡、APN 属于用户设备侧，应引导用户操作”这种对职责的理解。模型会把观察到的行为当成应然的行为：轨迹里最常出现的是转人工，模型就写出“连续三次失败即转人工”，等于把失败写进了规范，所以提炼产物必须经过独立验证才能发布。被修复的往往是很朴素的缺陷：有条轨迹里 Agent 想问用户要电话号码，却把“请您提供电话号码”填进了查询工具的参数，连调五次。

从 19 条失败轨迹到一条规则

另一个例子：需求澄清 Skill。问得太少会返工，问得太多会打扰。Skill 要表达的不是“所有任务都先确认”，而是一条带作用域的判断：低风险、易撤销的小改动说明假设后直接做；涉及架构、数据、权限、公开接口的，集中问少量真正改变方案的问题，再出一份短 Spec 确认。进化时要把反馈和具体轨迹、任务类型、结果关联起来，单独一句抱怨不足以触发更新。Skill 负责理解语境和提问，Harness 负责在缺少确认时否决高风险写入。

把重复的探索编译成程序

原书 9.2 节 · 将经验写成程序

当经验描述的是稳定、重复、可验证的操作时，每次都让模型重新读文档推理并不经济，更合适的是把它编译成工作流、工具或 Harness 代码。可改的对象不只是新工具：操作层（把浏览器轨迹编译成参数化工作流）、控制层（重试、熔断、压缩策略）、验证层（新增参数检查和回归测试）、架构层（加一个 Reviewer Agent）。

浏览器工作流像电子表格的宏录制：第一次发邮件，多模态 Agent 要从像素和 DOM 里找“撰写、收件人、主题、正文、发送”；第二次只是收件人和内容不同，没必要再找一遍。PreAct 的实验在重复任务上做到了 8.5–13 倍端到端加速，回放不需要逐步调用模型。但原书强调更重要的结论：流程记忆必须同时有动作前验证、动作后验证和独立回放验证，否则会得到危险的假象：每个按钮都点过了，某个字段其实为空，任务从没真正完成。

Agent 修改自己的代码，也不意味着运行中的进程直接覆盖自己：从稳定版本建隔离分支，生成最小补丁，依次过静态检查、单元测试、安全扫描、失败轨迹重放、旧任务回归，再灰度发布。每个修改还应是一份可证伪的变更契约：失败证据、推断根因、归属组件、修改提案、预期修好什么、可能弄坏什么，以及分别验证两者的用例。DeepSeek Harness 走得更远，“一切皆插件”，连主循环都是插件，靠可撤销效果和反应式依赖声明实现运行时安全装卸；原书的判断是，自我进化的上限取决于承载它的系统有多强的可组合性。

走一遍浏览器工作流的生命周期，看最终状态检查怎么拦住“假成功”。

    不只更新产物，还更新“更新方法”

    原书 9.2 节

    四种载体回答“写到哪里”，另一条正交的轴是“优化的是产物内容，还是产生和管理产物的方法”。原书引用 Lilian Weng 的划分，优化对象逐层扩大：单条规则或记忆 → 结构化上下文 → 工作流 → Harness 代码 → 产生更新提案的优化器代码。这是五种搜索尺度，不是五种新载体。

    最内层只改内容，作用面小、好归因、好回滚，应是默认选择。但反复让模型重写整份 Prompt 会退化：为了简洁，少数重要细节在多轮改写后逐渐消失。ACE 把上下文维护成带稳定标识符的条目集合，增量更新再确定性合并。往外一层，MCE 把“上下文里有什么”和“上下文怎么构造”拆成内外两个循环；AFlow 把多次 LLM 调用组成的工作流表示为代码图来搜索；Meta-Harness 让 Coding Agent 读候选 Harness 的源码、分数和轨迹去搜索更好的 Harness。

    最外层的代表是 Dream-RSI：把已完成的发现过程存成发现树，当作离线回放模拟器，让候选的探索策略在旧树上比较“先展开哪个分支、并行几个、何时停”，而不必重新调用 Agent 和评估器。它和前面两种复用历史的方式不同：轨迹总结改变 Agent 知道什么，工作流回放改变它怎样重复执行，发现树回放比较它怎样组织探索。它只能重组历史里实际走过的分支，旧树上更高分的策略不保证能迁移。

    五种搜索尺度

    双循环，以及“更新了”不等于“用上了”

    原书 9.3 节

    原书推荐的结构是双循环：在线执行循环只完成任务、记录证据，不直接改写正式 Agent；离线进化循环聚合轨迹、诊断根因、生成更新提案，过了验证门槛才发布新版本。Voyager 在 Minecraft 里展示了一个完整的例子：自动课程提出难度适中的下一个目标，技能库把验证成功的程序存成可组合的代码，迭代提示把环境观察、执行错误和自验证结果带回下一轮。缺一不可：没有课程不知道学什么，没有环境验证技能库会积累错误，没有持久化每次都从头开始。这背后就是数百年来的科学方法：假设、实验、评估、反馈。

    原书特别区分两种能力。Harness 更新能力是从轨迹中产生有价值的持久修改；Harness 受益能力是任务 Agent 后续能找到、激活并正确使用这些修改。一个 Skill 写得完全正确，较弱的任务模型却没在合适场景加载它，或加载了也没坚持遵循，最终成绩都会显得“没进化”。所以要分层评估：更新提案有效率、产物激活率、遵循成功率、保留任务集增益。长期还要看回退、泛化、token 效率、安全性和工程质量。

    开放任务的闭环最难。原书引用一项研究：四次从想法到论文的端到端自动科研尝试，三次在实现或评估阶段失败。问题包括实现漂移（方案一难就退回熟悉但偏离假设的实现）、认识论上的过度乐观（把噪声解释成发现）、隐性判断力不足（不知道哪个基线重要、何时放弃）。对策：结论与证据分离、保留负面结果、维护搜索多样性、让人在定义问题和评价标准的层面介入。

    拖动三个环节的比率，看端到端增益怎样被层层打折。

    安全边界与睡眠学习

    原书 9.3 节

    自我进化可能把一次错误变成长期风险：网页里的注入被总结成经验后跨会话反复生效；自动搜来的恶意软件包被封装成工具后扩散到所有后续任务；有缺陷的验证器持续批准看似进步、实际退化的版本。原书设了三道边界。证据与指令隔离：原始网页、工具输出及其 LLM 摘要都是不可信证据，总结不是净化；按固定 schema 提取主张、原文位置、采集时间，模型给的置信度不能当批准门槛。待验证能力与正式能力隔离：新东西先进不服务真实流量的待验证区，过安全检查和回归才转正。安全机制不可自我修改：业务 Agent 可以改 Prompt、Skill、知识库、工具，但不能改批准自身更新的验证器、测试用例、发布门槛、审计日志和稳定版本备份，否则降低阈值、删掉失败用例就能把退化伪装成进步。

    睡眠学习是对离线整合的类比：在线 Agent 只完成任务、追加证据；后台在空闲期或满足条件时整理一批新经历。分开采集和整理，可以防止一次偶发成功、网络故障或恶意输入立刻改写长期能力。持续进化也不是无限增长：上下文腐化会在更长的时间尺度上重现，经验相互冲突、Prompt 被边界规则淹没、Skill 重复、多次微调灾难性遗忘，所以要周期性合并、下沉、删除、重训。原书提到 Hermes 的做法：独立的 Curator 跟踪 Skill 的使用、陈旧和归档状态，在空闲期做确定性修剪，变更前存快照，可以回滚。
