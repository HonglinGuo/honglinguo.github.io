能力是分四步长出来的

原书 8.1 节

现代模型的能力开发通常分四个环节。预训练在海量文本上“预测下一个词”，学会语言、知识和基本推理，最贵，是地基。Mid-training（也叫继续预训练）从已有基模出发，在目标语言、领域文档、代码、长上下文上继续做语言建模，补通用预训练没覆盖好的“教材章节”。SFT（监督微调）用几千到几万条“输入—输出”示范，教模型用什么格式、风格、流程回答。RL（强化学习）不再模仿标准答案的 token，而是让模型自己试，按结果奖惩调整。原书的类比：通识教育、集中研修专业教材、老师示范答题规范、自己下场做题反复打磨。

关键认识：模型的输出本质上是一个概率分布，训练就是调整这个分布，四个环节的区别只在“想要什么”和“用什么信号定义想要”。SFT 在数学上和预训练是同一个任务，差别只有两点：数据换成了问答示范，损失只算在回答部分（loss masking）。所以 SFT 擅长固化格式、风格、流程这类协议性知识，不擅长灌入大量事实性知识，后者靠 Mid-training 或 RAG。LoRA 是贯穿所有方法的工程默认项：只训一个占原参数 1%–5% 的低秩补丁，学习率约为全参的 10 倍。

原书还讲了一段认知史：OpenAI 先相信算法（Atari），再相信环境（Gym、Universe、Dota），最后发现先验 > 环境 > 算法。同一个寻宝游戏，表格 Q-learning 要近 10000 局才稳定通关，Kimi K3 驱动的 LLM Agent 第一局 18 步就通关，靠的是预训练带来的先验，而不是更好的学习算法。

点四个阶段，对照它们的数据、目标和代价。

四个环节

缺底座、缺协议，还是缺策略

原书 8.4–8.6 节

原书反复提醒：不要把“模型做不好”统一归因成需要 RL。先排除不改权重的方案：提示词、工具、代码约束、上下文管理能解决就不训练；事实要频繁更新、引用或删除，优先 RAG。

然后在目标留出集上测能力支持：不只看 pass@1，还要看固定采样下的 pass@k。pass@1 低但 pass@k 随 k 明显上升，说明正确策略已在模型分布里、只是概率太小，RL、拒绝采样、蒸馏都有东西可放大。如果合理的 k 下 pass@k 仍接近 0，基模几乎生成不出成功轨迹：GRPO 的一组 rollout 全是 0，组内优势直接消失，继续加采样只能按约 1/p 的速度等偶然成功。RL 擅长把已有但概率低的成功行为推高，不擅长从全零奖励里凭空创造能力。

对症下药：缺领域语言、事实、代码模式、长上下文基础能力，先 Mid-training（数据从失败分布反推、按能力配比、每阶段“双重回放”防遗忘、多维门禁决定何时停）；会做但格式、工具 schema、流程不稳，先 SFT；已有非零成功率和可靠奖励、但好策略概率低或泛化不足，才上 RL。这不是必须依次跑完的仪式：强基模可以直接 RL（DeepSeek-R1-Zero），格式型任务可能只需 SFT。

SFT 记住地图，RL 拿着指南针探路

原书 8.1、8.7 节

两者的差别来自优化目标。SFT 最大化标注回答的概率，逐条复现示范；示范多样时也能泛化，示范单一时容易对表面模式过拟合。RL 最大化期望奖励，探索多条路径、提高高奖励路径的概率；奖励忠实、探索充分时，可能学到示范里没有的可迁移策略，奖励有偏时同样会钻捷径。从分布形状看，SFT 倾向覆盖式（mass-covering，尽量覆盖示范里出现过的多个写法），RL 配合反向 KL 倾向寻峰式（mode-seeking，把概率集中到少数高奖励的峰）。

原书用 GeneralPoints 实验量化这件事：类似 24 点，用四张牌加减乘除凑 24。训练时 J、Q、K 都按 10 算，测试时改成 11、12、13（规则 OOD）；或训练用黑色花色、测试用红色花色（视觉 OOD）。基于 Llama-3.2-Vision-11B，相同预算下对比 SFT 和 PPO。原书的解释是：有限的 SFT 数据强化了“遇到 J/Q/K 就当 10”的固定模式；RL 更可能强化“重新计算直到正确”的策略。另一个发现是，这个模型和严格结构化输出要求下，不经 SFT 直接 RL 完全失败，因为它连可解析的输出都给不出，奖励算不了。

在线反馈给了 RL 三个机会：能评估示范之外的候选（SimpleVLA-RL 学出了人类示范里没有的“推切”动作）；能利用“验证比生成容易”（代码可测、答案可对）；能在当前策略实际访问的状态上训练，避免离线模仿的协变量漂移。原书还提到，后训练也塑造模型“何时行动”：Coding 模型的行动阈值差异，很可能就写在参数里。

一个 step：16 次 rollout 到一次参数更新

原书 8.8 节

原书用一条 SWE-bench 任务讲 GRPO：parser.py 遇到空输入会抛 IndexError，要求修复且不能改测试。第一步，同一个问题复制到 16 个隔离沙箱，策略模型独立尝试 16 次，每次“读代码 → 改文件 → 跑测试 → 提交”就是一次 rollout；有的补上边界检查，有的只捕获异常掩盖问题，有的去改测试。第二步，验证器在干净环境里跑测试算奖励，通过且没改测试得 1，否则 0。第三步，算相对优势：比组内平均好的为正，差的为负。第四步，把优势变成损失，梯度下降更新参数，以后“先复现、查边界、改实现、跑测试”更容易出现。

关键在第三步：如果 16 条全部失败或全部成功，大家奖励一样，比不出谁更好，相对优势为零，这一组对训练毫无贡献。这也是后面 RLVP、过程奖励、部分进展奖励要解决的问题。PPO 则训练一个价值模型估计每一步“通常能做多好”，适合需要细粒度信用分配的长轨迹；两者都会限制单次更新幅度。DPO 不同，它直接学事先收集好的“好回答—差回答”偏好对，不在线 rollout。

原书还算了一笔时间账：复杂 Agent rollout 的墙钟时间由最慢那条决定，假设 2000 秒，加上 600 秒更新，一个 step 约 43 分钟，100 steps 就接近 72 小时。

名义上 on-policy，数值上已经 off-policy

原书 8.8 节

先分清两个词。Online 只表示数据在训练中不断交互产生；On-policy 要求生成 rollout 的行为策略 μ 和当前要优化的策略 π 相同或足够接近。异步集群哪怕一直在线生成，只要 rollout worker 落后几个 checkpoint，数据就已经陈旧，带上了 off-policy 成分。数据来自别的策略时要用重要性比率 ρ = π(a|s)/μ(a|s) 纠正。真正新鲜的 on-policy rollout 在更新前 ρ = 1。原书的立场是：“on-policy 更好”不是普遍定理，但在当前 LLM 策略梯度里通常意味着更低的分布偏差和更稳定的优化。

一个容易被当作“小噪声”的大问题：大规模 RL 通常用 vLLM/SGLang 生成 rollout，再用 FSDP/Megatron 重算 log probability。即使加载同一份权重，浮点精度、归约顺序、并行方式、批大小、fused kernel 的差异，都会让同一个 token 的 log probability 略有不同，更新前本应为 1 的 ρ 已经偏离 1。放大链条是：小误差 → 指数化的比率偏差 → 长前缀上的累积 → 裁剪和优势加权改变 → 梯度方向改变，最终可能表现为比率尖峰、大量 token 被裁、响应长度突变，奖励和熵一起坍塌。

工程对策：参数更新前，用同一批轨迹比较 sampler 和 trainer 的 log probability，监控 ρ 的分位数、最大值、近似 KL、被裁比例，这是最直接的 on-policy 单元测试；同步的不只是权重，还有 LoRA、tokenizer、chat template；rollout 要保存生成时的 behavior log probability；对不齐就显式当作 off-policy 修正，并限制 staleness。

用原书的例子算一算：每个 token 的 log 比率只偏 10⁻³，长轨迹上会放大成多少。

环境与奖励：奖励结果，惩罚路径

原书 8.9–8.11 节

RL 的瓶颈常常不在算法，而在环境是否真实、可重置、可并行。环境一旦失真，模型学到的就是只在仿真里管用的“应试策略”，构建高保真环境往往比训练本身更贵。造不出环境时可以让模型扮演环境：ZeroSearch 用 LLM 扮演搜索引擎，并按课程逐渐掺入噪声；DreamGym 把环境动态蒸馏进一个经验模型。但模拟器的偏差就是训练的天花板，RL 还会主动利用模拟器的漏洞，所以要用真实交互定期校准。训练和评估可以共享任务生成器与验证代码，但不能共享同一批任务。多轮任务里还有一个实现细节：工具返回的 token 不是策略生成的，计算梯度时要屏蔽。

奖励设计有三个维度。来自哪里：最可靠的是可验证奖励（RLVR，测试、断言、状态差异）；目标难以规则化时用生成式奖励模型给诊断。要区分 reward hacking（钻规则漏洞）和 reward seeking（模型先猜评判器看什么，再给自己设一个过于简单的检查、刚好通过就结束）。什么时候给：结果奖励探索空间最大，过程奖励缓解信用分配但可能把模型限制在预设路径上。表达多少信息：有确定答案用二元标量，多个独立目标用向量，开放任务用生成式诊断；每多一个维度就多一种被钻空子的可能。

RLVP（验证路径惩罚）解决“结果对了但路径违规”：改测试、跳过身份验证、执行破坏性命令也可能拿到表面成功。总奖励写成 R = O + βΦ，O 是结果，Φ 是确定性规则逐动作算出的路径信号。真实环境大多是非对称验证器：检测坏动作便宜可靠，证明“有意义的进展”很难。所以惩罚几乎总能恢复组内差异，进展奖励只在可达时才有效。原书实验：TerminalBench 上违规次数从 3.71 降到 0.66，成功率基本持平。

蒸馏：让一次 rollout 产生密集监督

原书 8.12 节

RL 样本效率低，根本原因是反馈太稀疏：一条 rollout 结束只得到一个成败标量。客服说“需要信用卡后四位”，人听一次就记住，模型却可能要几百次交互才偶然学会。蒸馏把一次 rollout 变成密集信号。

在轨蒸馏（On-Policy Distillation）的分工是：学生决定走到哪里，教师在学生已经走到的位置给出下一步的完整概率分布，最小化两者的 KL。离轨 SFT 的监督密集，但只覆盖教师会走到的状态，学生一旦犯了教师不会犯的错，就进了训练数据没见过的地方；on-policy RL 在学生自己的状态上训练，但信号稀疏。在轨蒸馏把两者结合，一条长度 T 的 rollout 产生约 T 组逐 token 监督。原书说在数学等任务上，达到同等性能的步数约为纯 RL 的 1/10。它同样不能从零创造能力：学生至少要能走进教师可纠正的状态。

没有更强的教师怎么办？在轨自蒸馏（OPSD）让同一个模型分饰两角：教师版能看到标准答案这类“特权信息”，学生版只看到问题，在自己的轨迹上向教师版对齐。对着答案解释刚走过的路，比独立探索容易。特权信息只能在训练侧构造，绝不能泄露给部署时的 Agent。

SFT 侧也有几种常见蒸馏：Prompt 蒸馏把“长提示 + 思考型教师”压到“短提示 + 非思考学生”；CoT 蒸馏把开源教师的完整思考轨迹交给学生，配合拒绝采样只保留答案正确的轨迹（RFT）。原书提到一个现场：写蒸馏实验代码时，GPT 驱动的 Codex 和 Claude 驱动的 Claude Code 都拒绝了，最后用 Kimi K3 完成；对多数团队，用开源 SOTA 做教师已经够用。

从问题案例到训练数据

原书 8.13–8.14 节

第 7 篇的评估资产可以直接变成训练输入：端到端回归任务（含验证器）→ RL 任务与可验证奖励、拒绝采样的采样池；轨迹前缀回归任务 → DPO 偏好对、决策边界示范、在轨蒸馏的教师状态；失败归因记录 → 过程监督负标签、RLVP 的惩罚规则；Rubric 多维评分 → 向量奖励、生成式奖励模型的训练数据。

原书给了三个案例。Coding Agent 过早结束：首错在“准备宣称完成”的决策边界。端到端侧用模型看不到的隐藏测试做奖励（通过 +1、不通过 −1）；前缀侧把过早宣称作为 rejected、“先跑测试逐条核对再下结论”作为 chosen，做 DPO。评估必须边界集和保留集都看，否则会把模型训练成永远不敢收尾。中文引号：用户说“直引号改弯引号”，但英文原文、代码、JSON、路径里的引号必须保留，先把作用域规则写成 Skill，再合成正反例做 SFT。编辑文件经常失败：沿字节到工具匹配的链路逐层找首个差异，只有模型输出是首个差异时才做复制训练；Qwen3-8B 的 byte-exact 准确率从 37.5% 提到 78.9%，而 tokenizer 无损往返本身只有 80.1%，说明这个数字已逼近 tokenizer 上限。

原书最后的核心原则：在投入大规模资源前，先用小规模实验验证关键假设，小批 Mid-training 看遗忘曲线，少量 SFT 看格式能否稳定，小批 rollout 看 pass@k、奖励差异和 sampler/trainer 一致性。快速失败比大规模失败更可接受。
