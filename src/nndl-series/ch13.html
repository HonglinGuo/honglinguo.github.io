语言模型回顾与解码策略

原书 13.1 节 · 第 362–365 页

语言模型对文本序列的概率建模。由链式法则 p(x₁, …, xT) = Π p(xt|x<t) 精确分解，从左到右逐个预测，叫自回归语言模型。评价指标困惑度 PPL = exp(−(1/T)Σ log p(xt|x<t))，可以理解为模型在每个位置上平均“在几个词之间犹豫”。参数化经历了 N 元模型 → 前馈网络 → RNN → Transformer 的演进；生成式大模型多用仅解码器 Transformer 加因果掩码。

训练最小化负对数似然。朴素做法要对每个位置各前向一次，但教师强制（用真实前缀做输入）配合因果掩码，一次前向就能并行算出所有位置的损失。代价是暴露偏差：训练时看到的前缀是真实数据，推断时是模型自己生成的，一旦出错后面就建立在错误前缀上。对大规模预训练模型这个问题相对温和，后续的指令微调、偏好对齐也有缓解作用。

推断时从 p(xt|x<t) 里怎么选，由解码策略决定。确定性解码适合翻译、代码：贪心每步取最大，只顾单步最优；束搜索每步保留累计对数概率最高的 k 个候选（k = 1 就是贪心），但在开放式生成上容易单调、重复。随机采样适合对话、创作：Top-k 只在前 k 个里采，但固定 k 适应不了分布形状；Top-p（核采样）取累积概率刚达到 p 的最小集合，分布尖时集合小、平时集合大，典型 p ∈ [0.9, 0.95]；温度 τ 调 softmax 的锐利程度。常见组合是温度 + Top-p。（温度和 Top-k 的交互演示见本系列第 8 篇和本站《Transformer 拆开看》。）

左边：一棵两步的小解码树（概率为示意），看贪心为什么会错过更好的序列；右边：同一个 p 在尖锐和平坦两种分布上保留的候选数。

预训练、分词与规模法则

原书 13.2 节 · 第 365–368 页

预训练在大规模无标注语料上做自监督学习。它的合理性可以从信息论理解：要准确预测下一个词，不仅要懂语法，还要懂事实和常识——预测即压缩，好的语言模型隐含地压缩、存储了大量世界知识。三种范式：自回归（仅解码器，GPT 系列；GPT-3 175B 发现了上下文学习）、掩码语言模型（仅编码器，BERT；双向上下文，适合理解任务，但训练—推断不一致，生成不如自回归）、编码器—解码器（T5，“文本到文本”，适合条件生成）。大规模生成模型多选自回归：架构简单、易扩展，所有任务都能统一成“给定前缀、预测后续”。

数据来自网页、书籍、论文、代码、百科，要去重、质量过滤、去隐私、去有害内容；混合比例是重要的设计决策。分词：词级会有未登录词，字符级序列太长，现代模型用子词折中。BPE 从字符出发，反复合并频次最高的相邻对，直到词表达到预设大小；字节级 BPE（GPT-2）在 UTF-8 字节上做，初始词表只有 256，任何输入都能无损表示；WordPiece 的合并准则是最大化语料似然；SentencePiece 把空格也当普通字符，可直接处理中文。典型词表 32K–128K。

规模法则：Kaplan 等发现交叉熵损失与参数量 N、数据量 D、计算量 C 分别呈幂律，L(N) ≈ (Nc/N)αN，αN ≈ 0.076、αD ≈ 0.095、αC ≈ 0.050，在对数—对数坐标下近似直线。Chinchilla 进一步回答固定算力怎么分：训练计算量 C ≈ 6ND，拟合 400 多个实验后发现 N* ∝ C0.5、D* ∝ C0.5，最优训练词元数约为参数量的 20 倍。但推理成本也要考虑，LLaMA 等模型选择“过度训练”：LLaMA-7B 用了 1T 词元，远超 Chinchilla 建议的约 140B。架构上已明显趋同：仅解码器、RoPE、RMSNorm（Pre-Norm）、SwiGLU、GQA、BPE；MoE 用路由实现高容量低计算，如 DeepSeek-V3 总参数 671B、每词元激活约 37B。

在原书的小语料“low low low lower lower newer”上一步步跑 BPE；再用 Chinchilla 比例算一笔账。

涌现能力、上下文学习与思维链

原书 13.3 节 · 第 369–371 页

涌现能力：某项能力在规模低于阈值时接近随机，超过阈值后快速提升。例子有少样本学习、多步推理、指令遵循、代码生成、跨语言迁移、工具使用。解释有两种：类似物理相变；或者复杂任务需要多种基础能力同时达标。也有研究指出，部分“涌现”可能是评估指标非线性造成的统计假象——用精确匹配时只有完全正确才得分，曲线就呈阶跃式。原书的稳妥说法是：复杂能力的评估结果同时受模型规模、任务构造和评价指标影响。

上下文学习（ICL）：在提示里给 K 个示例，不更新参数就能做新任务（K = 0、1、>1 对应零样本、单样本、少样本）。它对示例的选择、顺序、格式很敏感；即使把示例标签随机换成错的，性能下降也有限——示例还在传递输入分布、标签空间和格式。它和元学习的联系见第 11 篇：预训练语料里混着大量隐含“任务”，自回归预训练近似是在任务分布上优化。

思维链（CoT）在示例里加入中间步骤：p(y|x) = Σc p(c|x)p(y|x, c)。它把难题拆成小步，并给模型更多“计算空间”（输出越长，可用的计算步骤越多），效果有明显的规模依赖。“Let's think step by step”就能激发零样本 CoT。扩展有：自一致性（采样多条推理路径、多数投票——正确路径往往收敛到同一答案，错误路径各错各的）、思维树（树形搜索、可回溯）、测试时扩展（推断时投入更多计算）。

左边：如果每个词元的正确率随规模平滑上升，用“整个答案都对才算对”的精确匹配来看会是什么样（示意）；右边：自一致性的多数投票能把单条路径的正确率提高多少（模拟）。

指令微调与基于人类反馈的对齐

原书 13.4–13.5 节 · 第 371–379 页

预训练模型只是“文本续写器”：问“中国的首都是哪里？”，它可能续写成“这是一道常见的地理题……”。指令微调（SFT）在“指令—回答”数据上继续训练，损失只算回答部分（只训练补全）。和预训练相比：数据少（数千到数十万条）、质量要求高、轮数少（1–3 个 epoch）。参数太多时用 LoRA（h′ = Wx + BAx，A 高斯初始化、B 初始化为零，保证起点 ΔW = 0；算法见第 11 篇）。数据可以人工标注，也可以模型合成（Self-Instruct）；LIMA 用约 1000 条精选数据就达到相当效果——少而精。原书的判断：SFT 主要是激活和对齐已有能力、提供一个“接口”，而不是注入新知识。但 SFT 只会模仿，解决了“怎么做”，没解决“做到什么程度才算好”。

对齐需要偏好数据：同一指令下两个回答，标注哪个更好（yw ≻ yl）——比较比直接打分更容易一致。Bradley-Terry 模型假设 p(yw ≻ yl|x) = σ(r(x, yw) − r(x, yl))，奖励只确定到相差一个只依赖 x 的常数。用它训练奖励模型 rφ（取最后一个词元的隐状态接线性层），损失 −log σ(rφ(yw) − rφ(yl))。RLHF 把语言模型当策略，最大化 𝔼[rφ] − β KL(πθ ‖ πref)，KL 项防止奖励过度优化（Goodhart 定律：度量一旦成了目标就不再是好度量）。用 PPO 训练要同时维护策略、参考、奖励、价值四个模型。

DPO 分三步消掉强化学习：① 带 KL 约束的目标有解析解 π*(y|x) = πref(y|x) exp(r/β)/Z(x)；② 反解出 r = β log(π*/πref) + β log Z(x)；③ 代入 Bradley-Terry，两个回答相减时只依赖 x 的 β log Z(x) 正好消掉——这是最关键的一步，Z(x) 在指数级大的回答空间里根本算不出来。得到 ℒDPO = −log σ(β log(πθ(yw)/πref(yw)) − β log(πθ(yl)/πref(yl)))：一个二分类损失，隐式奖励就是 β 乘对数概率比。不需要奖励模型、不需要在线采样、不需要价值网络；局限是只用离线偏好数据，有分布漂移，对数据质量敏感。GRPO 走另一条路：保留在线 RL，但对每条指令采 G 个回答（通常 8–64），用组内标准化 Âi = (ri − mean)/std 代替价值网络，配合 PPO 裁剪和 KL 正则；特别适合数学、代码这类可验证奖励。此外还有宪法 AI、RLAIF、SimPO、KTO，以及防越狱、防提示注入、红队测试等安全对齐工作。幻觉的根源是下一个词元预测并不直接惩罚事实错误，缓解手段有 RAG、事实性奖励、在不确定时表达不确定。

先展开 DPO 推导；再看 DPO 梯度的自适应权重；最后点一点 GRPO 的组相对优势。

DPO 推导三步

  1. RLHF 目标：maxπ 𝔼y~π[r(x, y)] − β KL(π ‖ πref) = Σy π(y|x)[r(x, y) − β log(π(y|x)/πref(y|x))]。关于 π 严格凹，有唯一最大值。
  2. 在 Σπ = 1 约束下用拉格朗日乘子求导：r − β log(π/πref) − β = λ ⇒ π*(y|x) = πref(y|x) exp(r(x, y)/β) / Z(x)：奖励加权后的“玻尔兹曼分布”。
  3. 取对数反解奖励：r(x, y) = β log(π*(y|x)/πref(y|x)) + β log Z(x)。奖励完全由策略的对数概率比表示，Z(x) 只依赖 x。
  4. 代入 Bradley-Terry：r(yw) − r(yl) 中 β log Z(x) − β log Z(x) = 0，算不出来的配分函数被消去。
  5. 把 π* 换成 πθ，最大化偏好数据的对数似然：ℒDPO = −𝔼 log σ(r̂θ(yw) − r̂θ(yl))，r̂θ = β log(πθ/πref)。形式和奖励模型损失一样，只是奖励由策略本身参数化。

易混辨析

SFT vs 偏好对齐：模仿参考回答（解决“怎么做”）vs 学“哪个更好”（解决“做到什么程度”）。

RLHF-PPO vs DPO vs GRPO：在线 RL + 奖励模型 + 价值网络（四个模型）vs 离线二分类、不要奖励模型和采样 vs 在线 RL、用组内相对奖励代替价值网络（三个模型，规则奖励时两个）。三者常在不同阶段组合使用。

β 的作用：在 RLHF 和 DPO 里都控制偏离参考策略的程度；DPO 实践中常取 0.1–0.5。

奖励模型的绝对值：Bradley-Terry 只能确定相对值，加一个只依赖 x 的常数不改变偏好概率——这正是 DPO 能消掉 Z(x) 的原因。

推理增强：过程奖励、测试时扩展与 RL

原书 13.6 节 · 第 379–381 页

结果奖励模型（ORM）给整个回答一个分数，标注简单，但分不清“过程错了答案碰巧对”和“只错一步”。过程奖励模型（PRM）给每个推理步骤打分，提供稠密信号、精确定位错误，整条路径常取各步的最小值；标注成本高，可以用蒙特卡罗估计自动化。实践中 ORM 粗筛、PRM 精评。

测试时扩展：在推断时投入更多计算。一种是长程推理——回答前生成更长的中间过程，提出假设、验证、回溯、修正；另一种是搜索与验证——生成 N 条路径，用多数投票、奖励模型打分（Best-of-N）或 PRM 引导的树搜索选出最好的。研究表明同等预算下“多路径 + 验证”往往优于单条更长的路径，一个充分搜索验证的小模型有时能超过只生成一次的大模型。但原书提醒：更长推理不自动等于更可靠，验证器不可靠时，额外计算也可能放大错误。

RL 提升推理：以 DeepSeek-R1 为例，在 SFT 模型上做大规模 GRPO，数学答案匹配就给 1、否则 0，代码跑测试用例，另加格式奖励。训练中出现了推理长度自然增长、自我反思、换思路、阶段性跃迁等现象。纯 RL 也有初期拿不到正奖励、推理链可读性差、开放任务难定义奖励等问题，所以实际是多阶段：SFT 冷启动 → 大规模 RL → 拒绝采样与蒸馏。SFT 给“格式”和“起点”，RL 给“质量”和“深度”。

易混辨析：ORM vs PRM

ORM：对整个回答一个标量。便宜，但信用分配粗——过程有错而答案对、或只差一步而答案错，它都分不清。

PRM：每步一个分数，路径分常取最小值 mink r(x, s₁, …, sk)。贵，但能定位错误，还能在推理时引导束搜索 / 树搜索。

智能体：框架、工具、协作与治理

原书 13.7–13.9 节 · 第 382–387 页

基于大语言模型的智能体以 LLM 为“大脑”，通过感知环境、调用工具、执行操作、根据反馈修正计划来完成复杂任务。四个核心组件：感知（用户指令、工具返回、检索结果、网页、多模态信号，还要筛选压缩以适应上下文窗口）、规划（分解子任务、定顺序、考虑工具能力边界和失败预案）、行动（按 JSON 等格式生成动作，由外部执行器执行并返回结果）、记忆（短期 = 上下文窗口；长期 = 向量库等外部存储）。合起来是“感知—思考—行动”的闭环。

ReAct 让“思考 → 行动 → 观察”交替进行：比纯思维链多了外部信息，能减少幻觉；比直接调工具多了显式思考，更透明；只靠提示模板就能实现。任务分解有自顶向下（Least-to-Most）、逐步展开、规划—执行—再规划。反思：Reflexion 失败后写一段自然语言“经验总结”存进记忆，下次作为上下文——不更新参数的学习；Self-Refine 是单次生成里的“生成—批评—修改”。还可以用思维树做搜索，用编译器、单元测试、符号计算等外部验证器给出比自我评估更可靠的反馈。

工具调用：函数调用、API、代码执行（Toolformer 是早期代表）；工具多时要做工具检索；工程上用 JSON Schema 等结构化输出约束格式，把多步工作流表示成状态机或图，便于错误回放、权限审计、失败恢复。RAG：索引（切片、编码成向量）→ 检索（Top-k 相似度）→ 生成（拼进上下文），能用上可更新的外部知识而无需重训；检索本身就是一种工具。多模态智能体可以直接看截图操作界面；架构分模块拼接式（如 LLaVA）和原生多模态。多智能体有分工、讨论、辩论三种模式，通信拓扑有链式、星形、全连接，还可共享记忆；挑战是协调开销和“群体思维”。

当模型能调工具、读写外部状态时，评估对象就成了整个流程：不只看答案对不对，还看证据覆盖、参数合规、是否越权、能否回滚、记忆是否引入错误或隐私风险。RAG 要分开评检索质量和生成忠实性；高风险步骤前要人工确认、留可重放日志。原书的结论：智能体工程更像把语言模型嵌入一个受约束的软件系统，而不是简单地给模型加几个工具。（本站《Agent》系列有更细的展开。）
