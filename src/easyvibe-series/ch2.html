有问题，先问 AI

原教程 初级二 · 如何搭配 AI 主动学习、1.1 节

原教程把这一条放在整章最前面：把 AI 当成第一求助对象。概念没听懂、工具不会装、命令不会写、程序报错、不知道下一步做什么，凡是原本会问老师同学的，先问 AI，再自己动手。传统学法是搜教程、照步骤、报错再搜；在 AI IDE 里，很多操作可以直接让它做，比如“检查有没有装 Python，没有就帮我装”“下载失败了，帮我换国内镜像源”“帮我建一个叫 demo 的虚拟环境”。

它不是“把任务丢给 AI 自己等结果”，而是一个AI 原生学习闭环：遇到问题说清目标和现象 → 带着上下文问 AI → 自己照着建议试 → 不符合预期就把结果或完整报错继续交给 AI → 符合了就用自己的话复述为什么有效。最后一步最容易被跳过，但正是它把“这次解决了”变成“下次能迁移”。

原教程给了一个通用提问模板：我的目标是……；我目前做到……；我尝试了……；实际结果或完整报错是……；请先解释原因，再告诉我下一步最小的操作。注意结尾的“最小的操作”：让 AI 一次只给一步，你才跟得上、也才能验证。

IDE 与 AI IDE

原教程 初级二 第 2–3 节；附录 七款 AI 编程工具对比

用记事本也能写代码，但很快会遇到四个问题：全是黑字看不出结构、没有提示拼错就要反复查、文件多了找不到要改的那一行、出错只能靠打印日志猜。IDE（集成开发环境）把源代码编辑器（高亮、补全）、构建运行工具、调试器（断点、看变量）和 Git 等集成在一起。最流行的是 VS Code，核心理念是“一切皆插件”：装 Python 插件就是 Python IDE。

普通 IDE 是工具箱，前提是你知道要做什么、怎么做。AI IDE 在里面放了一个能听懂自然语言、能动手的助手：说“做一个登录页”先给骨架；把报错和代码丢给它先分析原因；确认后让它新建文件、批量跨文件修改；用 @文件名 或 @整个项目 指定参考范围。原教程归纳了五项核心能力：代码生成与补全、代码理解与问答、重构与优化、自动生成测试、Agent 式任务执行（自动生成、安装、运行、修改）。

市面上大多数 AI IDE 都基于开源的 VS Code 二次开发，所以熟悉 VS Code 之后迁移成本很低。它们的差别集中在四个维度：价格、可用模型（部分模型有地区限制）、Agent 能力、速度与性能。原教程的建议是实际测试，适合自己的就是最好的；遇到某个模型解决不了的问题，换一个模型再试往往有效，不推荐用 Auto 自动选模型。

除了本地 IDE，还有一类网页平台（Lovable、Bolt.new、v0、Replit、z.ai 等）：打开浏览器就能用，生成后直接预览甚至部署，但文件管理和复杂项目受限。原教程用同一份贪吃蛇需求实测了七款工具，结论是看人选：零基础先用顺手的网页平台，有开发经验、要长期做项目的用本地 IDE。

先翻开普通 IDE 与 AI IDE 的对照；再回答几个问题，看哪类工具适合你现在的情况。

我现在该用哪类工具？（据原教程七款工具实测结论整理）

原教程介绍的工具（截至原文写作时）本地 AI IDE：Google Antigravity（Agent-First，可直接操作编辑器、终端、浏览器）、字节 Trae（有国际版和中国版，零基础推荐中国版免费起步）、Cursor（大仓库与多文件场景体验好，专业版约每月 20 美元）、阿里 Qoder（Action Flow 拆步骤、透明跟踪执行）、腾讯 CodeBuddy（中文指令与企业合规）、VS Code + Cline（插件形式，可切换 API 端点，每步需确认）、AWS Kiro（深度集成 AWS）。网页平台：Lovable（对新手最友好，自动连 Supabase）、Replit（在线开发加部署一体）、v0（专注 React UI）、Bolt.new、Google AI Studio、z.ai、Minimax Agent（能看到自动查错修复全过程，但慢、耗 Token）。模型来源：IDE 自带额度、接第三方 API Key，或购买云厂商的 Coding Plan（包月式高频调用）。产品功能和价格变化很快，以官网为准。

易混辨析：网页平台 vs AI IDE vs 编码 Agent

网页平台是一整套托管环境，代码跑在对方的云上，优点是零配置、即时预览，缺点是文件和环境不在你手里。AI IDE 是装在本机的编辑器，代码、依赖、服务都在你电脑上，能处理复杂项目。编码 Agent 是两者里面那个“会自己规划、执行命令、修改文件”的能力，Trae 的 Builder、Cursor 的 Agent 模式、网页平台的“全栈开发”按钮都是它；第 11 篇讲的 Claude Code、Codex 则是不带图形界面、直接在终端里跑的编码 Agent。

本地实战：让 Agent 在空文件夹里干活

原教程 初级二 第 4–5 节

原教程的本地流程只有四步：新建空文件夹 → 用 AI IDE 打开 → 在侧边栏描述需求 → 让 Agent 生成项目并启动。示例需求是“用 React 实现贪吃蛇……实现后帮我启动这个项目，遇到没安装的环境就自动安装”。这里要意识到 Agent 不只是聊天：它会创建文件、安装依赖、执行启动命令，你描述目标，它决定执行哪些命令。在网页平台做过的项目，也可以下载下来用本地 IDE 打开继续迭代。

新手最常卡的是 Agent 执行到一半停住了。原教程列了几种原因：它在等你确认执行某条命令（点 Run）；命令行在问你问题（输入 y 或回车）；或者它启动了一个本地服务，比如贪吃蛇的开发服务器，服务需要一直运行，所以对话看起来卡住了，这时终端里会出现一个 localhost 网址，点 Skip 让 Agent 继续，再用浏览器打开那个网址。不确定该干什么时，截图问 AI。

Agent 改完代码后，IDE 会列出“几个文件需要审阅”：可以展开看改动、整体接受，也可以取消。所有主流 IDE 的 Agent 都支持回退（Revert），对结果不满意就回到修改前，改一下需求重来。跑通以后，可以让 AI 当导游讲代码，目标是理清三件事：有哪些核心数据（蛇、食物、分数、游戏状态）、这些数据在什么时机变化（移动、吃到、结束）、每种变化对应哪段代码。原教程还有个巧招：网页平台生成的项目 README 里常写了一份不错的架构说明，把它整段贴给本地 Agent，让它按这个架构改本地代码，就是“直接参考最佳实践”。

Agent 停住或结果不对时，该怎么处理？

请从上到下讲一遍，这个贪吃蛇游戏每一步是怎么动起来的？尽量少用专业术语。
蛇在屏幕上的每一节身体，是用什么数据结构来记的？能打个比方吗？
你是怎么控制“隔一段时间动一下”的？这在代码里是哪一段？
请把 SnakeGame.tsx 按功能分几块讲一下：每一块大概负责什么？
你刚才说的“状态”具体指什么？如果把定时器去掉，会发生什么？

易混辨析：Chat 模式 vs Agent（Builder）模式

以 Trae 为例：Chat 主要用来和当前文件夹里的代码对话、问问题，它给建议和代码片段，但不主动执行；Builder（Agent 模式）会在打开的文件夹内创建和修改文件、运行命令，相当于“本地版的全栈开发按钮”；Builder with MCP 再给 Agent 接上更多外部工具（第 12 篇细讲 MCP）。想弄懂代码用 Chat，想让它动手用 Builder。

说清需求，控制节奏

原教程 初级二 第 6 节；七款工具对比 · 关于提示词编写

同一个 AI，有人几句话就要到能跑的项目，有人聊半天还不对，差别往往在说话方式够不够具体、有没有步骤。“帮我做个网页”只能让 AI 脑补，给你一个看上去很完整但用不上的东西。原教程给了四个要补的信息：用途（拿来干嘛：发给招聘方看的一页个人简介）、内容块（页面上要出现哪几部分，不用专业词）、水平和限制（我不会写代码，请用最简单的写法）、交付形式（给我一份可以存成 index.html 直接打开的完整代码）。

第二件事是节奏。一上来就要“像淘宝那样的网站”，AI 会给你一大团代码，打不开、到处报错、你也看不懂错在哪。更好的顺序是三步：先要一个最小例子，只确认浏览器里能看到东西；确认后在此基础上补内容，并要求给完整代码而不是片段；结构差不多了再考虑好不好看。每加一步都先运行一次，这样哪一步出问题都能退回上一版正常的状态。工具对比那篇说得更直接：别说 “build me a Snake game”，拆成“先做前端、再做记分后端、最后连起来”三条待办。

“把画面变好看”是另一个典型的模糊需求，对人类设计师都太模糊。要拆成具体可执行的要求：游戏区居中、浅色背景让蛇和食物更醒目、分数放大放在显眼处、以蓝色为主色。之后再小步微调。

排错三步：先描述，再补 F12，迭代到解决

原教程 附录 常见问题与排错；初级二 6.3–6.4 节

原教程对排错的态度很明确：看到报错就慌、瞎改代码、花半小时搜、一个人调到深夜，都是浪费时间。流程是看到报错 → 截图 → 问 AI → 按建议做 → 测试。提问只要讲清三件事：刚才做了什么、现在看到了什么、想要什么效果，用大白话、按时间顺序。

第一步直接描述现象加截图，很多问题 AI 看一眼就能解决。第二步只有当 AI 说“需要更多信息”时，才按 F12 打开浏览器开发者工具补充：页面白屏、报错看 Console（截红色报错）；数据没存上、接口出错看 Network（重新操作一遍，找到那条请求，看 URL 和状态码、Payload 传了什么、Response 返回了什么）；样式不对看 Elements（右键元素“检查”，截 Styles 面板）。第三步改完测试，问题还在就带着新现象继续问。

如果是“AI 给的代码我粘进去不工作”，原教程另有五步：说清你做了什么、现在什么样（别只说“打不开”）；把当前完整代码发过去，很多时候是少复制了一行或新旧内容混在一起；附上错误文字或截图；要求“小白模式”一步一步讲改哪行、怎么保存、怎么刷新；最后让它说清改好后应该看到什么，你好对照。

先自己答，再点开
1. AI IDE 比普通 IDE 多了哪些能力？选 AI IDE 比较哪几个维度？

普通 IDE 提供编辑器、构建运行、调试器等工具，但要你自己知道做什么、怎么做。AI IDE 多了五项能力：代码生成与补全、代码理解与问答、重构与优化、自动生成测试、Agent 式任务执行（自己建文件、装依赖、跑命令、改代码），还能用 @ 指定参考范围。它们大多基于 VS Code，差别主要在价格、可用模型、Agent 能力、速度与性能四个维度，以实测为准。

2. 把模糊需求说具体要补哪四类信息？为什么先跑起来再变复杂？

用途（拿来干嘛）、内容块（页面上有哪几部分）、自己的水平和限制、希望的交付形式（例如可直接打开的完整 index.html）。先要最小例子、再补内容、最后美化，每步运行验证：出错时范围小、容易定位，还能随时退回上一版正常状态；一次性要一个大系统，得到的是一大团打不开也看不懂的代码。

3. 白屏、数据没存上、按钮错位分别看哪个面板？

先直接描述现象加截图问 AI；AI 要更多信息时再补：白屏和报错看 Console 的红色错误；数据没存上、接口报错看 Network，重新操作后找到那条请求，看 URL 与状态码、Payload、Response；样式和位置不对看 Elements，右键元素“检查”后截 Styles 面板。
