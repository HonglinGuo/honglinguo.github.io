它解决什么

原文 06-hooks「Overview」「Configuration」「Hook Types」

原文的定义：Hook 是在 Claude Code 会话中特定事件发生时自动执行的动作，可以是 shell 命令、HTTP webhook、LLM 提示词、MCP 工具调用或子代理评估；它们通过 stdin 收 JSON，通过退出码和 stdout 上的 JSON 回传结果。用途：自动化、校验、权限管理、自定义工作流。

配置可以放在六个地方：~/.claude/settings.json（所有项目）、.claude/settings.json（项目，可提交）、.claude/settings.local.json（本地，不提交）、组织托管策略、插件的 hooks/hooks.json、以及 Skill 或子代理的 frontmatter（组件生命周期内有效）。五种类型：command（默认，跑 shell 命令；也可以用 args 数组直接 exec，免去 shell 转义）、http（POST 同样的 JSON 到一个 URL）、prompt（让模型按一段提示词做判断，多用于 Stop）、mcp_tool（直接调用一个 MCP 工具）、agent（起一个能用工具的子代理去检查，实验性）。

事件地图

原文「Hook Events」

原文列了 33 个事件。按会话的阶段看最好记：会话（SessionStart、SessionEnd、Setup、InstructionsLoaded）；提示词（UserPromptSubmit、UserPromptExpansion）；工具（PreToolUse、PermissionRequest、PermissionDenied、PostToolUse、PostToolUseFailure、PostToolBatch）；回合结束（Stop、StopFailure、SubagentStart、SubagentStop）；任务与团队（TaskCreated、TaskCompleted、TeammateIdle）；环境变化（ConfigChange、CwdChanged、DirectoryAdded、FileChanged、PreCompact、PostCompact、PreModelSwitch、PostModelSwitch、WorktreeCreate、WorktreeRemove）；其他（Notification、MessageDisplay、Elicitation、ElicitationResult）。

对每个事件要知道两件事：matcher 匹配的是什么（工具事件匹配工具名，SessionStart 匹配 startup / resume / clear / compact / fork，PreModelSwitch 匹配目标模型名……），以及能不能拦。能拦的主要是“之前”类事件（PreToolUse、UserPromptSubmit、PermissionRequest、PreCompact、PreModelSwitch）和回合结束类（Stop、SubagentStop）；“之后”类（PostToolUse、PostCompact、PostModelSwitch、SessionEnd）事情已经发生，只能观察、补充上下文或给反馈。

matcher 与 if：选哪个工具，选哪一次调用

原文「Matcher Patterns」「Narrowing with if conditions」

配置结构是三层：事件名 → 一组 { matcher, hooks: [...] } → 每个 hook 的 type、command、timeout 等。matcher 按工具名选：精确字符串 "Write"、正则 "Edit|Write"、逗号分隔 "Write,Edit"（v2.1.191 起）、通配 "*" 或空串、MCP 工具 "mcp__memory__.*"；大小写敏感，v2.1.195 起精确匹配，带连字符的名字不会误匹配。

要按参数再缩小范围，就在单个 hook 上加 if，用权限规则的语法：Edit(src/**)、Read(.env)、Read(~/.ssh/**)、Bash(git push *)。if 写在 hook 处理器那一层，和 type、command 平级，不是写在 matcher 上。路径锚点和权限规则一致：裸名字 .env 匹配任意深度，src/** 相对当前目录，/src/** 相对项目根，// 是绝对路径；v2.1.214 起单段 dir/** 只匹配 当前目录/dir，要任意深度写 **/dir/**。

输入、退出码与决策

原文「Hook Input and Output」「PreToolUse」「Exit Codes」

每个 hook 从 stdin 收到一段 JSON：公共字段有 session_id、transcript_path、cwd、permission_mode、hook_event_name，工具事件还有 tool_name、tool_input，子代理里还有 agent_id、agent_type。脚本必须从 stdin 读，不是从命令行参数读——原文排障一节专门强调。

回传有两条通道。退出码：0 成功，继续，并解析 stdout 上的 JSON；2 是阻断，操作被拦下，stderr 作为错误显示；其他非零是非阻断错误，继续执行，只在记录里提示一行。JSON 输出（退出码 0 时）：PreToolUse 用 hookSpecificOutput.permissionDecision 返回 allow（跳过确认）、deny（拒绝，理由给 Claude 看）、ask（弹确认，理由给你看）、defer（优雅退出，稍后再恢复）；还可以用 updatedInput 整体替换工具输入。多个 PreToolUse hook 意见不一时，优先级是 deny > defer > ask > allow；而且无论 hook 返回什么，权限里的 deny 和 ask 规则照样生效。

易混辨析：hook 的 allow 与权限规则

hook 返回 allow 只是跳过确认框（需要用户交互的工具、组织设为 ask 的连接器工具除外），不能推翻权限里的 deny 或 ask 规则。

退出码 2 和 JSON deny 都能拦：前者 stderr 当错误显示，后者的 permissionDecisionReason 会交给 Claude，让它知道为什么被拒、换个做法。顶层的 decision/reason 写法在 PreToolUse 上已弃用。

prompt 型 hook：让模型判断“做完了没有”

原文「Prompt Hooks」「Stop and SubagentStop」「Prompt-Based Hooks」

prompt 型 hook 不跑脚本，而是把一段提示词交给模型评估，返回 {"ok": false, "reason": "..."} 这样的结构化判断（ok: false 时必须给理由）。最典型的用法是挂在 Stop 上：Claude 每次回答完准备停下时，检查“所有要求的文件都改了吗、还有没解决的报错吗”，没做完就把它拦回去继续干。Stop 和 SubagentStop 的输入里有 last_assistant_message，方便判断。

原文提醒了几个边界：同一回合 Stop hook 连续拦截 8 次后，Claude Code 会强行结束这一回合，防止写坏的 hook 无限循环（CLAUDE_CODE_STOP_HOOK_BLOCK_CAP 可调，0 关闭）；v2.1.163 起 Stop hook 也可以只返回 additionalContext 给 Claude 反馈并继续，不带错误标签；在 PostToolUse 上，prompt hook 返回 ok: false 默认结束回合，加 continueOnBlock: true 则把理由交给 Claude 让它重试。另外要分清 Stop（每次 Claude 回答结束都触发）和 SessionEnd（整个会话结束时触发一次，默认只有 1.5 秒预算，给自己设 timeout 可以放宽到最多 60 秒）。

示例对号入座

原文「Examples」及 06-hooks 目录下的脚本

原文目录里放了一批可以直接拷的脚本：format-code.sh、validate-bash.py、security-scan.py、validate-prompt.py、context-tracker.py、session-end.sh 等，安装方式是拷到 ~/.claude/hooks/、chmod +x，再在 settings.json 里登记。每个脚本的价值在于它挂在哪个事件、用什么方式回传：格式化只需要事后执行，不回传；危险命令要在之前用退出码 2 拦；安全扫描在之后用 additionalContext 把警告告诉 Claude；上下文统计用 UserPromptSubmit 和 Stop 一前一后两个事件配对计算。

调试与安全

原文「Debugging」「Security Considerations」「Hook Execution Details」

调试三板斧：claude --debug 看详细的 hook 执行日志；会话里 Ctrl+O 打开详细模式看 hook 进度；最有用的是脱离 Claude 单独测：echo '{"tool_name":"Bash","tool_input":{"command":"ls -la"}}' | python3 .claude/hooks/validate-bash.py; echo $?，看退出码对不对。不执行的话依次检查 JSON 语法、matcher 是否匹配工具名、脚本是否可执行、是不是从 stdin 读。

执行细节：command、http、mcp_tool 默认超时 600 秒（prompt 30、agent 60，部分事件会调低）；所有匹配的 hook 并行执行，完全相同的命令会去重。安全上原文的建议清单：校验所有输入、变量加引号 "$VAR"、拦截 .. 路径穿越、用 $CLAUDE_PROJECT_DIR 写绝对路径、跳过 .env 和 .git/ 等敏感文件；HTTP hook 要在请求头里用环境变量，必须显式列出 allowedEnvVars，防止把环境变量泄露给远端；组织可以在托管设置里用 disableAllHooks 统一关掉 hooks。

回扣开头的三个问题

先自己答，再点开
1. Hook 与 CLAUDE.md、Skill 规则的根本区别？配在哪、有哪五种？

Hook 由 Claude Code 程序在事件点执行，不经过模型判断，是确定性的，能用退出码 2 拦下操作；CLAUDE.md 和 Skill 只是给模型的指令。配置位置：~/.claude/settings.json、.claude/settings.json、.claude/settings.local.json、托管策略、插件 hooks/hooks.json、Skill 或子代理的 frontmatter。五种类型：command、http、prompt、mcp_tool、agent。

2. 退出码 0、2、1 的含义？hook 返回 allow，deny 规则还生效吗？

0：成功，继续，并解析 stdout 的 JSON；2：阻断，操作被拦，stderr 作为错误显示；其他非零：非阻断错误，继续执行，记录里提示一行。PreToolUse 的 JSON 决策优先级 deny > defer > ask > allow；无论 hook 返回什么，权限里的 deny 和 ask 规则都照样生效，hook 的 allow 只是跳过确认框。

3. matcher 和 if 各筛选什么？Stop 与 SessionEnd 的区别？

matcher 按工具名（或事件特有的值）选，支持精确、正则、逗号分隔、通配；if 写在单个 hook 上，用权限规则语法按工具参数筛，如 Edit(src/**)、Bash(git push *)。Stop 在 Claude 每次回答结束时触发，能拦（连续 8 次后强制结束）；SessionEnd 在会话结束时触发一次，不能拦，默认只有 1.5 秒预算。
