它解决什么

原文 05-mcp「Overview」「MCP vs Memory」

原文一句话：MCP 是 Claude 访问外部工具、API 和实时数据源的标准方式；和 Memory 不同，它提供的是对变化中数据的实时访问。Memory 存偏好、规范、历史这类不怎么变的东西；MCP 去取当前的 GitHub issue、实时的数据库查询、在线服务的状态。

接好以后，服务器暴露的东西以三种形态出现：工具（名字形如 mcp__github__get_pr，Claude 在任务里调用）、prompt（变成斜杠命令 /mcp__github__review，见第 2 篇）、资源（在提示词里用 @服务器:协议://路径 引用，比如 @database:postgres://mydb/users）。服务器还可以在运行中动态增删工具（list_changed 通知，不用重连），可以中途弹对话框向你要输入（Elicitation），也可以返回交互式界面（MCP Apps）。

一张功能卡。

添加服务器：四种传输

原文「MCP Installation Methods」「MCP Configuration Management」

HTTP 是原文推荐的方式，连远程服务器，支持 OAuth：claude mcp add --transport http 名字 URL，需要固定令牌就加 --header "Authorization: Bearer …"。stdio 在本机起一个进程：claude mcp add --transport stdio 名字 -- npx 包名，注意 -- 之后是要执行的命令，环境变量用 --env KEY=value；原生 Windows 上 npx 要套一层 cmd /c。SSE 已弃用但还能用。WebSocket（ws）适合服务器主动推事件，但 --transport 不接受它，只能写进 .mcp.json 或用 claude mcp add-json，而且只支持请求头认证、没有 OAuth。

管理命令是一组 claude mcp 子命令：list、get 名字、remove 名字、add-json 名字 '{…}'、add-from-claude-desktop、reset-project-choices、login/logout（v2.1.186+，加 --no-browser 可在 SSH 里完成 OAuth）。会话里用 /mcp 看连接状态、每个服务器的工具数（0 个工具会被标出来）、触发 OAuth。stdio 服务器启动时环境里已经有 CLAUDE_PROJECT_DIR；在项目、本地、用户配置里引用它要写成 ${CLAUDE_PROJECT_DIR:-.} 带默认值。

拼一条 claude mcp add 命令，看它写到哪里。

作用域与 .mcp.json

原文「MCP Scopes」「Environment Variable Expansion」「Server Deduplication」

三种作用域：local（默认）写在 ~/.claude.json 里、挂在当前项目路径下，只有你、只在这个项目；project 写进项目根的 .mcp.json，提交进 git 给团队共享，队友第一次用时要确认；user 也写在 ~/.claude.json，你的所有项目都能用。老版本里 local 叫 project、user 叫 global，看老文章时注意。同一个服务器在多层都有定义时，local 优先，方便你在本机覆盖团队配置。

.mcp.json 可以提交，但密钥不能：配置里的 command、args、env、url、headers 都支持 ${VAR} 和 ${VAR:-默认值} 展开，令牌放在你 shell 的环境变量里。变量没设又没默认值时，服务器照样加载但带着字面量 ${VAR}，claude mcp list 和 /mcp 会提示。安全上还有一条：在不受信任的目录里，仓库自带配置“自己批准”的服务器不会被自动启动，要先接受信任对话框（v2.1.196）。

上下文开销：工具定义、输出与“写代码调用”

原文「MCP Tool Search」「MCP Output Limits」「Solving Context Bloat with Code Execution」

MCP 接多了，上下文会被两样东西吃掉：工具定义和中间结果。对前者，Claude Code 默认开着 Tool Search：所有 MCP 工具延后加载、按需发现，定义不先塞进上下文（ENABLE_TOOL_SEARCH 可设 auto / auto:N 按阈值切换、false 关闭；用非官方的 ANTHROPIC_BASE_URL 时会自动关掉）。某个服务器每轮都要用，可以设 "alwaysLoad": true，但原文提醒要省着用。工具描述和服务器说明也有截断上限（以原文为准），重要信息写在描述开头。

对后者，Claude Code 给输出设了阈值：超过 10,000 tokens 警告，默认上限 25,000 tokens，更大的结果存成文件、对话里只放路径（MAX_MCP_OUTPUT_TOKENS 可调）；跑超过 2 分钟的 MCP 调用自动转后台。原文还专门介绍了 Anthropic 工程博客的思路：让代理写代码去调用 MCP，把工具当成带类型的函数，数据在执行环境里流转、过滤，只把最终结果交给模型。博客里的例子是把一份会议纪要从 Google Drive 搬到 Salesforce，直接调工具时纪要要经过上下文两次。

先估一下这个例子能省多少，再看原文的取舍。

易混辨析：Tool Search 与“写代码调用 MCP”

Tool Search 是 Claude Code 内置的，解决“工具定义太多”：定义按需发现，默认开启。

写代码调用 MCP 是原文引用的 Anthropic 工程博客里的架构思路，解决“中间结果来回经过模型”：数据在沙箱执行环境里流转，只交回结果。它需要安全的沙箱、监控和额外基础设施；原文的判断是服务器少时直接调用更简单，几十个服务器、几百个工具时才明显划算。

认证与排障：先看状态码

原文「OAuth 2.0 Authentication」「Troubleshooting」

支持 OAuth 的服务器，加的时候不用带令牌，Claude Code 会走完整个流程：会话里 /mcp 触发浏览器授权，令牌存进系统钥匙串；需要无人值守的场景可以预先给 --client-id、--client-secret、--callback-port。用自定义 headersHelper 动态生成请求头时，服务器返回 401 或 403 会自动重新调用它刷新凭据（v2.1.193）；项目 .mcp.json 里的 headersHelper 需要先接受目录信任，并且运行时不继承你的凭据环境变量（v2.1.238）。在 claude.ai 账号里配好的 MCP 连接器会自动出现在 Claude Code 里，不想要就设 ENABLE_CLAUDEAI_MCP_SERVERS=false。

排障原文的第一条建议是：改任何东西之前先跑 claude mcp list（或会话里 /mcp），v2.1.219 起它会在失败的服务器旁边打印 HTTP 状态码和服务器给的错误文本。401/403 是凭据坏了或过期，用 claude mcp login 重新认证；404 是 URL 错了，最常见是漏了 /mcp 或 /sse 路径后缀；5xx 或超时是远端挂了。另一个隐蔽的坑是从浏览器或聊天里复制的令牌带了首尾空白，Claude Code 会提示，用 printf '[%s]\n' "$TOKEN" 就能看出来。headless 跑时 --mcp-config 里校验失败的服务器会被跳过而不是报错，要看 stream-json 的 init 事件里的 mcp_server_errors。

看报错，选第一步该做什么。

更多接入点与安全

原文「Database MCP Setup」「Managed MCP」「Plugin-Provided」「Subagent-Scoped MCP」「claude mcp serve」

数据库要只读。原文的 DBHub 例子特意加了警告：它的 execute_sql 会执行收到的任何 SQL，包括 UPDATE、DELETE、DROP。原文给的做法有两层：建一个只有 SELECT 权限的数据库用户（这才是真正的保护），再在 DBHub 的配置里打开只读模式（只读模式靠过滤 SQL 文本，历史上被绕过过）。永远别连生产库。

MCP 还可以从几个别的地方进来：插件（插件根目录的 .mcp.json 或 plugin.json 内联，用 ${CLAUDE_PLUGIN_ROOT} 引用插件内的路径）；子代理（定义的 mcpServers: 字段，只在该子代理里可用，不与父代理和兄弟共享）；组织托管（managed-mcp.json 下发一组固定服务器；allowedMcpServers / deniedMcpServers 是 settings 的键，按 URL、启动命令或名字过滤，deny 优先）。反过来，claude mcp serve 能让 Claude Code 本身作为 MCP 服务器被别的应用调用。

回扣开头的三个问题

先自己答，再点开
1. MCP 和 Memory 的边界？推荐哪种传输、怎么加？

Memory 存不怎么变的偏好、规范、历史；MCP 访问实时变化的外部数据和服务。推荐 HTTP：claude mcp add --transport http 名字 URL [--header ...]，支持 OAuth；本地进程用 stdio：claude mcp add --transport stdio 名字 -- 命令；SSE 已弃用；ws 只能写进 .mcp.json 或 add-json，只支持请求头认证。

2. 不带 --scope 写到哪？团队共享用什么？密钥怎么办？

默认 local：写进 ~/.claude.json 的当前项目下，只有你、只在本项目。团队共享用 --scope project，写进项目根 .mcp.json 提交到 git，队友首次使用要确认；user 也在 ~/.claude.json，所有项目可用。密钥不进文件：用 ${VAR} 或 ${VAR:-默认值} 引用环境变量，或用 OAuth、headersHelper。多层同名时 local 优先。

3. MCP 多了上下文被什么占掉？有什么办法？

工具定义和中间结果。Claude Code 默认 Tool Search，工具定义按需发现，alwaysLoad 慎用；输出超过 1 万 tokens 警告、默认 2.5 万上限，更大的存文件只给路径；超过 2 分钟的调用自动转后台。原文还介绍了让代理写代码调用 MCP 的思路：数据在执行环境里流转，博客例子从约 15 万 tokens 降到约 2 千，但需要沙箱和额外基础设施，服务器很多时才划算。
